## 多仓库边界

至少分别检查以下 Git 根：

| 仓库 | 工作区路径 | 主要提交内容 |
| :--- | :--- | :--- |
| 根仓 | `.` | docs、scripts、bringup、顶层 README/规范 |
| 导航仓 | `src/ats_sentry_nav` | 导航算法/接口/launch 与 README |
| 行为仓 | `src/ats_sentry_behavior` | 行为树与 README |
| MuJoCo 仓 | `src/sim/ats_mujoco_sim` | 仿真与 README |
| loopback 仓 | `src/sim/loopback_sim` | 轻量仿真与 README |
| 串口仓 | `src/standard_robot_pp_ros2` | 实机出口与 README |

未知修改与未跟踪文件默认属于用户。禁止 `git add .`、`git add -A`，只显式
stage 当前任务列出的文件。

## 参数与接口边界

- `.msg/.srv/.action`：字段、常量、feedback/result schema 的唯一权威。
- YAML：参数、topic、frame、QoS、timeout、owner 和 profile 值。
- launch：选择 profile、文件路径、节点是否存在和唯一 owner；不承载算法调参。
- XML/CSV：行为树拓扑和点位结构化资产，不强行塞入总 YAML。

正式实机总 YAML 的目标位置是
`src/ats_sentry_bringup/params/node_params.yaml`。当前 MINCO、Goal Manager、MPC
仍有各自 `*_reality.yaml`，属于待迁移范围。

## 新增代码放置规则

1. 先定位行为 owner，不按“方便引用”随意跨仓放置。
2. 新增跨进程数值数据时定义明确 ROS interface，禁止复用调试点云。
3. 地图融合和 generation 逻辑放在 adapter/规划 snapshot owner，不放入 RViz。
4. 目标 cancel/preempt/timeout 放在 Goal Manager/行为 action client，不放入 MPC。
5. 四舵轮限值和控制求解放在 `ats_swerve_mpc`，串口只做出口授权与协议。
6. 仿真 fault injector/evaluator 放在 MuJoCo/根脚本，不污染实机节点。

## 构建边界

```bash
colcon build --base-paths src ...
colcon test --base-paths src ...
```

禁止无目标递归读全仓。定位顺序是 symbol/topic/参数 `rg` -> 完整函数/类 ->
直接 producer/consumer -> launch/test。生成目录、缓存和参考项目默认跳过。
