# 代码范围与目录结构

本文档只根据 `src` 中的当前代码整理，用于说明每个目录应该维护什么、不应该承担什么。

## 顶层目录职责

### `src/ats_sentry_bringup`

根仓保留的总入口包。它承担部署编排，不承担算法实现。该目录不再对应独立远端分包，也不应加入 `dependencies.repos`。

代码范围：

- `launch/`：组合实机、loopback、MuJoCo/外部仿真接入、视觉测试、RViz、rosbag。
- `params/node_params.yaml`：实机统一参数入口。
- `map/`：提交到仓库的地图 YAML / PGM。
- `pcd/`：本机 PCD 放置目录，`*.pcd` 不进入 Git。
- `rviz/`：统一 RViz 视图。
- `scripts/`：仿真输入和路径调试脚本。

不应放入：

- Nav2 插件实现。
- 行为树插件实现。
- 视觉算法代码。
- 串口协议解析代码。
- 第三方依赖源码。

### `src/ats_sentry_behavior`

行为树决策域。它把裁判系统、视觉目标、导航反馈和地图代价转成决策输出。

代码范围：

- `behavior_trees/*.xml`：比赛/测试行为树。
- `params/*.yaml`：行为树服务端参数。
- `plugins/action`：行为树动作节点，例如发布导航目标、选择巡逻点、视觉跟随点、云台命令和姿态模式。
- `plugins/condition`：行为树条件节点，例如比赛状态、血量、RFID、视觉目标有效性、资源模式。
- `plugins/control`：行为树控制节点。
- `plugins/decorator`：节流与超时装饰节点。
- `src/ats_sentry_behavior/src/ats_sentry_behavior_server.cpp`：行为树执行服务端，负责订阅裁判/视觉/导航状态并写入黑板。
- `src/ats_sentry_behavior/src/ats_sentry_behavior_client.cpp`：行为树 action client，按参数发送目标树。

### `src/ats_sentry_nav`

导航域。它包含定位、点云处理、地形栅格、Nav2 配置、Nav2 插件、轨迹优化和速度坐标转换。

主要子包：

- `ats_nav_bringup`：导航 launch 与 Nav2 参数。
- `ats_nav2_plugins`：Nav2 行为插件 `BackUpFreeSpace` 和 costmap 插件 `IntensityVoxelLayer`。
- `ats_sentry_nav`：导航聚合包，依赖内部多个功能包。
- `ats_teleop_twist_joy`：手柄控制入口。
- `fake_vel_transform`：将 Nav2 输出从 fake yaw / 大 yaw 相关坐标系转换到中间速度话题。
- `sentry_chassis_vel_transform`：根据云台大 yaw joint 把速度转换到下位机底盘 `/cmd_vel`。
- `livox_ros_driver2`：Livox 雷达驱动和自定义 Livox 消息。
- `point_lio`：LIO 定位与建图。
- `loam_interface`：将 Point-LIO 输出整理成导航链需要的话题。
- `sensor_scan_generation`：根据注册点云生成传感器扫描。
- `terrain_analysis`：从 registered_scan / lidar_odometry 生成 `terrain_map`。
- `terrain_analysis_ext`：从地形点云生成 `terrain_map_ext` 与 traversability 语义栅格。
- `trajectory_optimizer`：B-spline 平滑、ESDF 查询、轨迹 profile、速度限速。
- `minco_planner`：A* / MINCO / yaw / footprint 检查的规划骨架。
- `small_gicp_relocalization`：PCD 地图重定位。
- `pointcloud_to_laserscan`：点云格式转换工具。

### `src/interfaces`

接口与消息域。所有自研消息、裁判系统消息、视觉交互消息和仿真控制消息都归入这里。

子包：

- `ats_rm_interfaces`：实车串口桥和行为树使用的裁判系统、云台、机器人状态消息。
- `sp_msgs`：视觉与导航/行为树之间的消息，包含 `VisionTargetMsg`、`TrajectoryProfileMsg` 等。
- `carstatemsgs`：MuJoCo / DDR-opt 相关车体状态与轨迹消息。
- `manda_can_control`：MuJoCo 舵轮控制和反馈消息 / 服务。

命名约定：

- 面向比赛裁判系统和实车状态的消息放 `ats_rm_interfaces`。
- 面向视觉融合和导航互操作的消息放 `sp_msgs`。
- 面向仿真车体状态和轨迹结构的消息放 `carstatemsgs`。
- 面向仿真 CAN / 舵轮控制的消息放 `manda_can_control`。

### `src/sim`

仿真域。所有不属于实机主链但用于验证导航、感知或控制的仿真包放在这里。

子包：

- `ats_mujoco_sim`：MuJoCo 舵轮底盘仿真，作为后续完整仿真主线。
- `loopback_sim`：ROS 包名 `nav2_loopback_sim`，用于快速闭环验证 Nav2 与行为树，后续保留为决策快速测试入口。

### `src/sp_vision25`

视觉域。代码范围包括相机、云台、YOLO、自瞄、Buff、全向感知和 ROS2 融合输出。

与导航/行为树相关的关键范围：

- `io/ros2/publish2nav.cpp`：发布 `vision/target` 和 `vision/target_point_map`。
- `io/ros2/subscribe2nav.cpp`：订阅 `enemy_status`、`autoaim_target`。
- `io/ros2/vision_target.hpp`：视觉对导航的内部融合状态结构。
- `src/sp_vision25/src/sentry.cpp`：哨兵视觉主程序，跟踪目标后通过 ROS2 发布视觉目标状态。

### `src/standard_robot_pp_ros2`

串口桥与下位机接口域。代码范围包括：

- `standard_robot_pp_ros2_node`：串口收发、裁判系统解析、底盘速度和云台命令下发。
- `gimbal_manager_node`：订阅 `cmd_gimbal`，生成 `cmd_gimbal_joint`。
- `packet_typedef.hpp`：串口协议结构。
- `config/standard_robot_pp_ros2.yaml`：串口参数和云台/速度保护参数。

### `src/tools`

工具域。当前包括：

- `pcd2pgm`：PCD 到 PGM 栅格地图转换。
- `rosbag2_composable_recorder`：组合式 rosbag 录制。
- `teleop_gimbal_keyboard`：键盘云台控制工具。

### `src/dependencies`

第三方或上游依赖域。包括 BehaviorTree.ROS2、RMOSS core、sdformat 工具等。一般不在本项目文档中作为自研代码展开，只说明它们提供的能力：

- BehaviorTree.ROS2：行为树执行服务。
- rmoss core / interfaces：RoboMaster 相关基础设施和消息接口。
- sdformat_tools：SDF / xacro 生成辅助。
