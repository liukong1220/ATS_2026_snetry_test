## 1. 本轮测试目标

本轮上车不追求一次把所有导航问题都测完，优先确认下面四件事：

1. 恢复是否还会“走一下停一下”
2. 动态障碍靠近时，是否比以前更早重规划
3. 分段放行后，是否能先脱离膨胀层边缘
4. 是否出现新的副作用，比如恢复动作过早保守

### 2.3.1 这些 RViz 可视化分别是什么意思

建议先记住一句最实用的话：

- `plan` 看 planner 想怎么走
- `smoothed_path_visual` 看 smoother / optimizer 实际把线改成什么样
- `trajectory_profile_markers` 看这条线上的速度和曲率压力大不大
- `trajectory_esdf_debug` 看 fake ESDF 觉得哪里离障碍近、应该往哪边推开

具体解释：

1. `plan`
   - 这是 SmacPlannerHybrid 的原始全局路径。
   - 主要用来判断原始规划是否已经贴墙、切角、终端被拉直。

2. `smoothed_path_visual`
   - 这是 B 样条平滑和 obstacle refinement 之后的可视化路径。
   - 如果它比 `plan` 更早从墙边回拉，说明平滑/避障在起作用。
   - 如果它反而内切进障碍边缘，说明 refinement 太激进或 corridor 太松。

3. `trajectory_profile_visual`
   - 这是轨迹 profile 的路径表达，主要对应带时间参数化后的轨迹。
   - 一般配合 `trajectory_profile_markers` 一起看。

4. `trajectory_profile_markers`
   - 青色折线和点表示 profile 路径。
   - 点的颜色大致表示该点速度相对速度上限的比例。
   - 尾部文字 `kappa_max=... cost=...` 是这一条轨迹的摘要。

5. `trajectory_esdf_debug`
   - 红绿点表示路径采样点到障碍物的距离状态。
   - 越偏红，表示越靠近障碍；越偏绿，表示越安全。
   - 黄色小箭头表示 `grad d(x)`，也就是“当前这个点往哪边移动会更远离障碍”。
   - 尾部文字 `d_min / d_avg / |g|avg / risk_count` 是整条轨迹的 ESDF 摘要。

6. `local_costmap/costmap` 和 `global_costmap/costmap`
   - 这是 Nav2 看到的障碍和膨胀层。
   - 用它确认 ESDF 红点是不是真的对应墙角、膨胀层、还是传感器噪声。

7. `Obstacle Scan`
   - 看实时障碍输入是否正常。
   - 如果 costmap 很怪，先怀疑 scan / 点云链路，不要先怪 optimizer。

8. `TF`
   - 看 `map / odom / base_footprint / gimbal_yaw / gimbal_yaw_fake` 是否稳定。
   - 如果 TF 抖，轨迹看起来“像是优化有问题”，其实可能是状态估计或坐标链问题。

### 2.3.2 这些文字分别代表什么

#### A. `trajectory_esdf_debug` 里的文字

当前会显示：

- `d_min`
- `d_avg`
- `|g|avg`
- `risk_count`

它们的意思是：

1. `d_min`
   - 全轨迹采样点里，离最近障碍物的最小距离，单位是米。
   - 这是最危险的那个点。
   - 越小越危险；如果明显小于 `obstacle_safe_distance`，说明这条线某一段已经很贴边。

2. `d_avg`
   - 全轨迹采样点的平均障碍距离，单位是米。
   - 它不是“安全下限”，更像“整条路径整体离障碍远不远”。
   - `d_min` 小但 `d_avg` 大，通常表示只有局部一小段危险。

3. `|g|avg`
   - 全轨迹采样点的平均梯度模长，`g` 指 `grad d(x)`。
   - 可以粗略理解成“距离场在这条路径附近变化得强不强”。
   - 值偏大通常说明路径附近有更明显的障碍边界可供推离。
   - 值偏小不一定是好事，也可能是处在平坦区域、对称峡谷中线，或者局部梯度不明显。

4. `risk_count`
   - 当前写法是 `risk=a/b`。
   - `b` 是参与统计的总采样点数量。
   - `a` 是其中距离小于 `obstacle_safe_distance` 的危险点数量。
   - 它回答的问题是：这条路径里“危险采样点多不多”，不是只看最危险的一个点。

#### B. `trajectory_profile_markers` 里的文字

当前会显示：

- `kappa_max`
- `cost`

它们的意思是：

1. `kappa_max`
   - 这条轨迹上的最大绝对曲率。
   - 可以粗略理解为“最急的弯有多急”。
   - 越大通常表示某一段弯得越猛，对控制器越难跟。

2. `cost`
   - 这是当前轨迹 profile 的总 cost。
   - 代码里它等于：
     - `curvature_penalty`
     - `velocity_smoothness_cost`
     - `obstacle_cost`
     三项相加。
   - 所以它不是单独表示“碰撞代价”，而是整个轨迹当前综合代价。
   - `cost` 变大，可能是弯太急，也可能是速度剖面不平滑，也可能是更贴障，不要只按一个方向解释。

### 2.3.3 两组文字为什么会重叠

原因很简单：

1. `trajectory_profile_markers` 的 `kappa_max / cost` 文字默认挂在轨迹尾部上方。
2. `trajectory_esdf_debug` 的 `d_min / d_avg / |g|avg / risk_count` 之前也挂在差不多的位置。
3. 两者都属于“尾部摘要文字”，RViz 就容易叠在一起。

当前已经做的修正：

1. `kappa_max / cost` 仍然挂在轨迹尾部正上方。
2. `d_min / d_avg / |g|avg / risk_count` 改成沿轨迹末段的局部法向偏移后再抬高显示。
3. 这样正常情况下两组文字会稳定错开，不再挤在同一块区域。

## 3. 分轮测试顺序

建议按下面顺序逐轮进行。

不要一开始就混合所有场景，否则很难判断是哪一层逻辑起作用。

### 第一轮：静态障碍 + 膨胀层边缘

目标：

1. 验证分层采样是否让恢复更平滑
2. 验证分段放行是否能避免“完全不动”

场景建议：

1. 让机器人靠近墙边或障碍边缘
2. 让局部 costmap 膨胀层明显覆盖到机器人附近
3. 给一个需要脱离当前位置的导航目标

重点看：

1. 是否还会“走一下停一下”
2. 是否会完全卡死不动
3. 是否能先释放一段短安全轨迹脱离边缘
4. 恢复方向是否比以前更连续

### 第二轮：人为动态遮挡

目标：

1. 验证动态障碍简单速度预测是否生效
2. 验证是否能比以前更早重规划

场景建议：

1. 先让机器人进入恢复动作
2. 然后让人或另一台机器人短时从恢复走廊前方经过
3. 不要直接完全贴死，优先做“逐渐逼近恢复走廊”的遮挡

重点看：

1. 是否比以前更早重规划
2. 是否少了“碰到边界才急停”的现象
3. 是否出现过早保守，明明还能走却不走

### 第三轮：普通导航阶段动态干扰

目标：

1. 判断当前动态障碍预测是否只够恢复层使用
2. 判断下一步是否该扩展到局部参考轨迹层

场景建议：

1. 不刻意制造恢复
2. 只让机器人做普通导航
3. 在其局部前进方向附近让动态障碍经过

重点看：

1. 普通导航是否也会被动态障碍反复打断
2. 打断主要发生在恢复阶段，还是正常 `FollowPath` 阶段
3. 若普通导航阶段也频繁犹豫，说明下一步应扩展到局部参考轨迹层

## 4. 现场该怎么看

### 4.1 恢复是否还会“走一下停一下”

看：

1. 机器人实际动作
2. `/cmd_vel`
3. `back_up_free_space_markers`

理想现象：

1. 恢复动作连续
2. `cmd_vel` 不再明显一下大一下小
3. 恢复轨迹方向不会每拍来回跳

异常现象：

1. 机器人仍然明显一顿一顿
2. 刚动一下就立刻停
3. 恢复 marker 每拍变化很大

### 4.2 动态障碍靠近时是否比以前更早重规划

看：

1. 恢复轨迹 marker 是否提前变化
2. 机器人是否在真正碰到边界前就切新方向
3. 是否比以前更少“先顶一下再停”

理想现象：

1. 动态障碍刚逼近恢复走廊时，就提前切换
2. 不再等到几乎碰边才急停

异常现象：

1. 仍然要等碰到边界才停
2. 反而过早保守，障碍还没真正挡住就放弃

### 4.3 分段放行后是否能先脱离膨胀层边缘

看：

1. 原本完全卡死的位置，现在是否能至少先退一小段
2. 即使最终没完全恢复，也是否先改变了危险局部位置关系

理想现象：

1. 不再“完全原地不动”
2. 能先释放一个短安全段，再继续重规划

异常现象：

1. 还是完全不动
2. 或释放的安全段太短，导致重新变成碎步试探

### 4.4 是否出现新的副作用

重点观察：

1. 恢复动作过早保守
2. 恢复方向不自然
3. 普通导航也开始明显犹豫
4. 动态障碍只是擦边经过，恢复动作却已经完全放弃

如果出现：

1. 过早保守
   - 优先怀疑 `prediction_horizon_s`
   - `predictive_block_margin`
   - `monitor_lookahead_distance`
2. 方向不自然
   - 优先怀疑恢复几何仍太“直线化”
   - 下一步考虑圆弧 / 样条恢复轨迹
3. 普通导航也被反复打断
   - 说明动态障碍预测应该扩展到局部参考轨迹层

### 4.5 上车时怎么把这些可视化串起来理解

建议按这个顺序看，不容易乱：

1. 先看 `plan`
   - 判断原始 planner 有没有先天贴墙、切角、终端拉直。

2. 再看 `smoothed_path_visual`
   - 判断 optimizer/smoother 是在把坏路径修好，还是反而修坏。

3. 再看 `trajectory_esdf_debug`
   - 看红点是不是正好落在贴墙段。
   - 看黄箭头方向是不是符合直觉。
   - 看 `d_min / risk_count` 是不是和你肉眼看到的危险段一致。

4. 再看 `trajectory_profile_markers`
   - 如果 `kappa_max` 很大，说明轨迹某段很急。
   - 如果 `cost` 很大，但 `d_min` 其实不小，那问题更可能在曲率或速度剖面，不一定是贴障。

5. 最后再对照机器人实际运动
   - 路径看着对但车走得抖，优先怀疑 odom / TF / 下位机响应。
   - 路径本身就贴墙或拧巴，再回头看 planner/smoother/ESDF。
