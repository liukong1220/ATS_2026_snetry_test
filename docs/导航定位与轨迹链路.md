# 导航定位与轨迹链路

更新时间：2026-07-31。本文把当前自研链、Nav2 对照链和 P2/P3/P4 边界分开说明。

## 定位链路

```text
MID-360 LiDAR + IMU
  -> livox_ros_driver2
  -> point_lio
  -> /localization
  -> /registered_scan
  -> localization_fusion / small_gicp relocalization
```

契约：

- Point-LIO 是 `/localization` 与 `/registered_scan` 的 owner；ROGMap 不是定位器。
- `map -> odom` 只能有一个权威；SLAM 与 prior-PCD relocalization profile 互斥。
- 观测时间、ROS/sim/steady clock、timeout 与 stale 行为必须分别核对。
- `LocalizationStatus.localization_epoch` 发生变化后，旧规划/授权不得继续执行。

实机雷达兼容边界：

- 普通总入口默认 `launch_fake_vel_transform:=True`。
- 普通总入口默认 `launch_chassis_vel_transform:=True`。
- fake-yaw 关闭时保留 `gimbal_yaw_odom -> gimbal_yaw_fake` 零旋转 TF。
- 不新增重复 `base_footprint -> base_link` publisher。

专用 Nav2-free 入口当前把两级速度 transform 固定关闭，因为 MPC 已直接输出车体系
速度。这是 profile 选择，不代表可以删除兼容层源码或破坏固定/云台雷达切换契约。

## ROGMap 与 2.5D 地面适配

```text
/registered_scan + /localization
  -> ats_rog_map
  -> probabilistic occupancy / inflation / 3D ESDF
  -> /rog_map/get_ground_projection
  -> ats_rog_map_adapter
       + /map
       + /traversability_grid
       + /traversability_slope_grid
  -> /rc_esdf/planning_grid
  -> /rc_esdf/signed_distance_grid
  -> /rc_esdf/footprint_clearance_grid
```

`GetRogMapProjection` 单个 response 原子携带：

- `OccupancyGrid`：`0` free、`100` raw occupied、`-1` unknown；
- `generation`、`ready`、`stale`；
- row-major signed distance：free 正、occupied 负、unknown NaN；
- frame 内 `gradient_x/gradient_y`，unknown 为 NaN。

规划节点禁止订阅或反解析 `/rog_map/esdf` 可视化点云获取距离。

## 地图融合规则

- 任一有效来源 occupied，最终保持 occupied。
- 任一新鲜来源明确 free，可消解其它来源的 unknown。
- 只有所有来源都没有 free/occupied 证据时才输出 unknown。
- unknown 默认按障碍处理。
- static map 更细、分辨率不整除或 origin 平移/yaw 旋转时，对输出 cell footprint
  覆盖的全部源 cell 做保守聚合，不能只采样中心。
- ROGMap projection 范围外与 terrain/slope 的 `-1` 表示该来源无证据，不能覆盖
  另一来源的明确 free。
- `robot_unknown_clear_radius` 当前保持 `0.0`；没有带 yaw 的定向矩形栅格化前，
  不能用外接圆清 unknown，且任何清理都不能覆盖 occupied。

物理 occupancy、概率证据、ROG inflation、JPS clearance 和 footprint margin 必须
分层，禁止重复膨胀。

## planning grid 唯一 owner

`planning_grid_owner` 只允许：

| 值 | 启动 | 抑制 |
| :--- | :--- | :--- |
| `rog_map` | `ats_rog_map_adapter` | `rc_esdf_map` 的 planning-grid 输出 |
| `rc_esdf` | `rc_esdf_map` | adapter 的 planning-grid 输出 |

`bringup.launch.py` 普通默认仍是 `rc_esdf`；专用 Nav2-free 实机入口默认
`rog_map`。显式 arbiter 尚未实现，禁止运行中热切换。

## 自研目标与轨迹链

```text
/ats_navigate_to_pose
  -> ats_goal_manager
  -> PlannerGoal(goal_id + localization_epoch + map_publication_sequence)
  -> minco_planner
  -> immutable PlanningMapSnapshot
  -> JPS (A* fallback)
  -> MINCO S3
  -> clearance-aware independent yaw
  -> footprint gate / Local Collision Repair
  -> candidate Path + PlannerStatus
  -> Goal Manager commit recheck and retime
  -> atomic ExecutionCommand
  -> ats_swerve_mpc
```

### Goal Manager

拥有：

- `/ats_navigate_to_pose` action server；
- goal accept、feedback、result、cancel、preempt、timeout；
- map/localization/gimbal lease 校验；
- 最终 reference 的统一重定时与提交；
- `/planner/execution_command` 和急停 heartbeat 的唯一权威。

### MINCO planner

拥有：

- 单次规划 immutable snapshot；
- start/goal/frame/map 校验；
- JPS 搜索与 A* fallback；
- MINCO S3 时间参数化；
- 独立 yaw、footprint safety 和 repair；
- 候选 reference 与结构化失败原因。

MINCO 不得在正式链越权解除急停；`planner_manages_emergency_stop=false`。

### MPC

`ats_swerve_mpc` 状态为世界系 `[x,y,yaw]`，输入为车体系 `[vx,vy,wz]`。
正式实机默认：

- `control_rate_hz=20`、`dt=0.05`、`horizon=30`；
- reference/execution lease `0.5 s`；
- `max_vx=max_vy=1.5 m/s`、`max_wz=2.0 rad/s`；
- `/planner/execution_command` 是唯一执行授权；
- `/cmd_vel` 直接到串口层，MPC 后无旋转/增益级。

这些是配置值，不是本轮实测性能。轮加速度、转向速率和真实执行器约束仍需台架
与实车标定。

## reference 提交时序

候选 reference 和正式 reference 不能使用不同的“当前时间”随意发布。最终提交点
必须：

1. 复核同一 snapshot/publication heartbeat 仍新鲜；
2. 复核 localization epoch、gimbal request/feedback 与 goal id；
3. 在同一互斥区按各 pose 相对时间统一重定时；
4. 原子发布含 reference 的 `ExecutionCommand EXECUTE`；
5. MPC/串口拒绝旧 sequence、旧时间戳和 STOP 前 reference。

`/planner/emergency_stop` 与 `/minco/reference_path` 是不同 DDS topic，不具备跨 topic
原子顺序。结构化 `ExecutionCommand` 用于收敛这个风险，但仍需运行注入证明恢复后
旧轨迹不复活。

## generation 账本

| 编号 | Owner | 语义 |
| :--- | :--- | :--- |
| ROG source generation | `ats_rog_map` | 3D occupancy/ESDF update |
| adapter publication sequence | `ats_rog_map_adapter` | 一次融合产品发布 |
| MINCO snapshot generation | `minco_planner` | 单次规划本地不可变 snapshot |

三者不能等同。当前 `OccupancyGrid` 没有 source generation，只能证明单次 MINCO
规划内部的一致性。要宣称端到端一致，需用同一不可变消息携带 source generation、
grid 和数值 ESDF，并由 consumer 校验。

## 安全 fallback

以下任一条件都必须产生确定性零速度：

- map unready/stale 或 adapter lease 过期；
- Point-LIO/localization status stale 或 epoch 改变；
- 全 unknown、start/goal occupied、目标不可达；
- projection service timeout 或迟到 response；
- MINCO/footprint/repair 失败；
- runtime safety recheck 失败；
- MPC infeasible、reference/command 过期；
- 串口断连或 cmd_vel watchdog 超时。

恢复后若没有新目标，旧 response、旧 generation、旧 reference 和旧 execution
command 都不能自行恢复运动。

## Nav2 对照链边界

`ats_nav_bringup`、`ats_nav2_plugins`、`trajectory_optimizer` 的 Nav2 smoother 部分、
`fake_vel_transform` 和部分 MuJoCo launch 仍保留 Nav2 接口。它们用于基线和迁移，
不属于目标 V1 运行链。

P3 只有同时满足以下运行证据才成立：

- `launch_nav2=false`；
- 无 Nav2 navigator/planner/controller/behavior server；
- MINCO 不订阅 `/plan`；
- 目标入口不调用 `nav2_msgs/action/NavigateToPose`；
- ATS action 的 feedback/result/cancel/preempt/timeout 通过；
- 扩大矩形与红框都在自研入口通过。

当前实机专用入口满足前四项的静态结构，但本轮没有运行最后两项，因此仍标记
“已实现未运行”，而不是 P3 已验收。

## ROGMap/RViz 边界

RViz 可直接显示 `/rog_map/occ`、`/rog_map/inf_occ`、`/rog_map/unk`、
`/rog_map/esdf` 和 bounds Marker。建议颜色与 display 结构复用原 ROGMap 项目风格，
但规划永远走数值服务。P2 配置当前默认 `visualization.enable=false`，新 RViz 文件、
开关和 headless/GUI 截图验收仍待实施。

## 当前证据结论

- **已验证**：本文接口、配置值、owner 和 launch 默认值已静态交叉核对。
- **已实现未运行**：Nav2-free ATS action -> Goal Manager -> MINCO -> MPC 源码链。
- **未验证**：本轮没有构建、MuJoCo、红框、fault injection 或实车结果。
- **未完成**：单一总 YAML、全仓 Nav2 依赖移除、新 ROGMap RViz、P3 两场景和 P4 实车门禁。
