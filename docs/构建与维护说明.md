## 依赖拉取方式

根仓直接保留 `src/ats_sentry_bringup`，该目录不再通过独立远端仓库拉取。部署机器只需要先克隆根仓：

```bash
git clone --depth=1 -b develop https://github.com/liukong1220/ATS_2026_snetry_test.git
cd ATS_2026_snetry_test
```

然后用根目录清单拉取其余功能域：

```bash
./import_workspace_repos.sh --shallow
```

维护规则：

- `dependencies.repos` 中所有项目依赖统一使用 `https://github.com/liukong1220/<repo>.git`。
- 自研分包仓库和 fork 后的工具/依赖仓库用于开源项目，应保持 public。
- GitHub topic 使用 `ats-nav` 表示 `ATS_NAV` 研发归类。
- `src/ats_sentry_bringup` 不加入 `dependencies.repos`，也不再由拆仓脚本导出。
- `src/ats_sentry_bringup/pcd/*.pcd` 不上传 Git，实机需要时从本地或离线介质放入。
- 仓库迁移、fork 和 topic 归类已经完成，一次性迁移脚本不再保留；根目录只保留 `import_workspace_repos.sh` 作为部署拉取脚本。

部署脚本位于根目录，部署机器克隆根仓后可直接执行：

```bash
./import_workspace_repos.sh --shallow
```

脚本会在当前命令进程中临时设置 `init.defaultBranch=main` 和 `advice.detachedHead=false`，用于屏蔽 `git init` 默认分支提示；如果后续清单再次锁定到 commit hash，也会减少 detached HEAD 提示噪声。该设置不写入用户全局 `git config`。

## 推荐低负载构建方式

低性能机器建议始终限制：

- colcon 同时只构建 1 个包。
- 单包内部最多使用 2 个编译任务。

命令：

```bash
source /opt/ros/humble/setup.bash
export CMAKE_BUILD_PARALLEL_LEVEL=2
export MAKEFLAGS=-j2
colcon build --symlink-install --parallel-workers 1 \
  --base-paths src \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

如果目录迁移后遇到 CMake cache 指向旧源码路径，清理缓存：

```bash
source /opt/ros/humble/setup.bash
export CMAKE_BUILD_PARALLEL_LEVEL=2
export MAKEFLAGS=-j2
colcon build --symlink-install --cmake-clean-cache --parallel-workers 1 \
  --base-paths src \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

如果个别包因旧 `build/<pkg>` 中 symlink 目录残留失败，可删除对应包的 build 目录后重试：

```bash
rm -rf build/<pkg>
```

该操作只清理构建产物，不删除 `src` 源码。

低性能机器可先单独构建消息包和基础包，再构建重包：

```bash
source /opt/ros/humble/setup.bash
export CMAKE_BUILD_PARALLEL_LEVEL=2
export MAKEFLAGS=-j2

  --packages-select sp_msgs ats_rm_interfaces carstatemsgs manda_can_control \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

  --packages-select livox_ros_driver2 point_lio small_gicp_relocalization terrain_analysis terrain_analysis_ext \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

然后再构建剩余包。

## 路径维护规则

### 新增仿真代码

放入：

```text
src/sim/<name>
```

适用：

- 物理仿真。
- 软件闭环仿真。
- MuJoCo 仿真桥。
- loopback 快速测试入口。
- 只在仿真中使用的地图生成、传感器模拟和控制桥。

当前不再新增 Gazebo 仿真代码或 ROS-GZ 桥接入口。完整仿真统一使用 MuJoCo；需要快速验证决策、Nav2 参数和话题链路时使用 loopback。

### 新增消息接口

放入：

```text
src/interfaces/<interface_package>
```

命名建议：

- 与实车裁判/机器人状态相关：放 `ats_rm_interfaces`。
- 与视觉和导航交互相关：放 `sp_msgs`。
- 与仿真车体状态相关：放 `carstatemsgs`。
- 与仿真控制反馈相关：放 `manda_can_control`。

### 新增导航相关代码

放入：

```text
src/ats_sentry_nav/<package>
```

适用：

- ROGMap/RC-ESDF 适配、JPS/MINCO、Goal Manager、MPC。
- 过渡期 Nav2 对照插件。
- costmap 插件。
- 点云到地图/栅格处理。
- 定位、重定位、地形分析。
- 轨迹优化、速度治理。
- 与导航输出坐标系强相关的速度转换。

`sentry_chassis_vel_transform` 已归入导航域，原因是它依赖云台大 yaw，并直接连接 `fake_vel_transform` 与下位机 `/cmd_vel`。

## 文档维护规则

本次重写后的文档以当前 `src` 为依据。后续更新文档时，应先检查对应源码：

- 启动入口变化：读 `src/ats_sentry_bringup/launch`、`src/ats_sentry_nav/ats_nav_bringup/launch`。
- 参数变化：读根仓总 YAML、行为参数和导航仓 `*_reality.yaml`/ROGMap 配置，并核对 launch 实际加载关系。
- 行为树变化：读 `src/ats_sentry_behavior/behavior_trees` 和 `plugins`。
- 消息变化：读 `src/interfaces`、`ats_navigation_interfaces` 和 `ats_rog_map_interfaces`。
- 仿真变化：读 `src/sim`。
- 视觉变化：读 `src/sp_vision25/io/ros2` 和主程序。
- 串口变化：读 `src/standard_robot_pp_ros2`。

未从 `src` 直接确认的信息，不应写成确定结论。

## 最窄验证顺序

```bash
python3 -m py_compile <changed_launch_files>
MAKEFLAGS=-j1 colcon build --base-paths src \
  --packages-select <targets> --parallel-workers 1
colcon test --base-paths src --packages-select <targets>
colcon test-result --test-result-base build/<package> --verbose
ros2 launch <package> <launch> --show-args
git diff --check
```

地图、规划、安全或控制源码最后一次修改后，必须重跑相应 MuJoCo 闭环。topic
存在、单次运动或编译通过不能替代终点、owner、fault injection 和接触评估。

## 多仓提交

每次修改前后分别检查：

```bash
git -C /home/ats/ATS_2026_snetry_test status --short --branch
git -C /home/ats/ATS_2026_snetry_test/src/ats_sentry_nav status --short --branch
git -C /home/ats/ATS_2026_snetry_test/src/ats_sentry_behavior status --short --branch
git -C /home/ats/ATS_2026_snetry_test/src/sim/ats_mujoco_sim status --short --branch
git -C /home/ats/ATS_2026_snetry_test/src/sim/loopback_sim status --short --branch
git -C /home/ats/ATS_2026_snetry_test/src/standard_robot_pp_ros2 status --short --branch
```

- 未知修改与未跟踪文件默认属于用户。
- 禁止 `git add .` 和 `git add -A`；按精确文件清单 stage。
- 缓存、模型生成物、PCD、本地地图和嵌套仓库不提交。
- 接口、算法、安全、仿真和文档按内容拆分中文提交。
- 推送前确认分支为 `develop`，推送后核对本地 HEAD 与 `origin/develop`。

## 参数维护目标

`src/ats_sentry_bringup/params/node_params.yaml`。当前 MINCO、Goal Manager 和 MPC
仍分别加载 `*_reality.yaml`，因此尚未完成统一。迁移必须先加入总 YAML 并让 launch
加载、验证 effective params，再删除或降级旧文件。

ROS interface schema、行为树 XML 和点位 CSV 不迁入 YAML。详细方案见
[导航参数与接口统一配置方案](./项目优化文档/nav2free/导航参数与接口统一配置方案.md)。
