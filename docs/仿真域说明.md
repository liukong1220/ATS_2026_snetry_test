# 仿真域说明

本文档根据 `src/sim` 和 `src/ats_sentry_bringup/launch` 中的仿真入口整理。当前仿真主线已切换为 MuJoCo；Gazebo 入口和依赖已清理，不再作为后续导航测试方案。`loopback_sim` 保留，用于以后快速测试决策、Nav2 参数和话题链路。

## 仿真域结构

```text
src/sim/
├── loopback_sim/             # ROS 包名 nav2_loopback_sim
└── ats_mujoco_sim/           # ROS 包名 ats_mujoco_sim
```

## loopback 仿真

包路径：

- `src/sim/loopback_sim`

ROS 包名：

- `nav2_loopback_sim`

核心节点：

- `loopback_simulator`

源码：

- `src/sim/loopback_sim/nav2_loopback_sim/loopback_simulator.py`

入口：

- `src/sim/loopback_sim/launch/loopback_simulation.launch.py`
- `src/sim/loopback_sim/launch/bringup_launch.py`
- `src/sim/loopback_sim/launch/tb3_loopback_simulation_launch.py`
- `src/ats_sentry_bringup/launch/loopback_decision_sim.launch.py`
- `src/ats_sentry_bringup/launch/loopback_nav_only.launch.py`
- `src/ats_sentry_bringup/launch/loopback_vision_test.launch.py`

节点行为：

- 订阅 `initialpose`。
- 订阅 `cmd_vel`，可支持 `Twist` 或 `TwistStamped`。
- 发布 `odom`。
- 发布 `scan`。
- 可发布 `/clock`。
- 发布 `map -> odom`、`odom -> base_footprint`、`base_footprint -> base_link`、`base_link -> base_scan` 等 TF。
- 可补 `base_footprint -> gimbal_yaw_fake`，使实机导航链中依赖 fake yaw frame 的节点在 loopback 下也能运行。

适用场景：

- 快速验证 Nav2 参数。
- 验证行为树是否能发送 Nav2 action。
- 验证视觉接管逻辑，不需要物理引擎。
- 验证恢复行为和速度链路。

loopback 参数：

- `src/sim/loopback_sim/params/nav2_params.yaml`

该参数包含 Nav2、loopback simulator、B-spline smoother、trajectory speed governor 和恢复行为配置。

## MuJoCo 仿真

包路径：

- `src/sim/ats_mujoco_sim`

ROS 包名：

- `ats_mujoco_sim`

核心源码：

- `ats_mujoco_sim/sim_node.py`
- `ats_mujoco_sim/twist_to_motion_ctrl.py`
- `ats_mujoco_sim/kinematics.py`
- `ats_mujoco_sim/dynamic_obstacles.py`
- `mujoco_lidar/*`
- `models/swerve.xml`
- `models/swerve_chassis.xml`

入口：

- `launch/ats_mujoco_sim.launch.py`
- `launch/mujoco_navigation.launch.py`
- `launch/planner_mujoco.launch.py`

`sim_node.py` 能力：

- 加载 MuJoCo 舵轮底盘模型。
- 接收 `manda_can_control` 控制消息。
- 发布运动反馈、四轮速度反馈、四轮转角反馈、电池和系统状态。
- 发布里程计和 TF。
- 可启用 MID360 扫描模式的 LiDAR 点云。
- 可启用 ToF 点云。
- 可处理动态障碍配置。

主要控制输入：

- `/motion_control`：`manda_can_control/msg/MotionCtrl`
- `/speed_ctrl`：`manda_can_control/msg/SpeedCtrl`
- `/steer_ctrl`：`manda_can_control/msg/SteerCtrl`
- `/simulation/PoseSub`：仿真位姿输入

主要反馈输出：

- `/motion_fb`
- `/speed_fb`
- `/steer_fb`
- `/battery_fb`
- `/system_state_fb`
- `/localization`
- `/lidar_odometry`
- `/local_pointcloud`，仿真 MID360 原始点云，默认 frame 为 `front_mid360`
- `/registered_scan`
- `/left_tof/points`
- `/right_tof/points`

`twist_to_motion_ctrl.py`：

- 订阅 `cmd_vel_nav2_result`。
- 发布 `/motion_control`。
- 对 x、y、yaw 三个方向做比例和限幅。

MuJoCo 导航入口 `mujoco_navigation.launch.py` 组合：

- MuJoCo 仿真节点。
- `nav2_map_server`。
- 可选 `ats_nav_bringup` 导航链。
- 可选 `twist_to_motion_ctrl`。
- 可选 RViz。

当前 MuJoCo LiDAR 测试链路固定使用 Livox MID360：

- `lidar_model` 默认且仅支持 `mid360`。
- `lidar_downsample` 控制 MID360 每帧 24000 条 ray 的降采样，默认 `1`。
- `lidar_frame_id` 默认 `front_mid360`，用于复用实车 terrain / costmap 传感器配置。
- `/local_pointcloud` 与 `/registered_scan` 均按 `x / y / z / intensity`
  字段发布，保证 `terrain_analysis(_ext)` 和 `IntensityVoxelLayer` 可按
  `PointXYZI` 链路解析。
- 其他 LiDAR 扫描模式不会被 `ats_mujoco_sim` 接受。

## 仿真与实机共享的部分

共享：

- 行为树包 `ats_sentry_behavior`。
- 导航域 `ats_sentry_nav`。
- 消息域 `interfaces`。
- 速度链 `fake_vel_transform` / `sentry_chassis_vel_transform`。
- 轨迹链 `trajectory_optimizer`。

不共享：

- loopback 不模拟真实动力学。
- MuJoCo 使用 `manda_can_control` 仿真控制接口。

## 仿真选型

- 只调行为树、Nav2 和话题链：优先 loopback。
- 调底盘动力学、LiDAR、ToF、控制接口：使用 MuJoCo。
- Gazebo 已从当前主线清理，不再新增 Gazebo 调试入口。
