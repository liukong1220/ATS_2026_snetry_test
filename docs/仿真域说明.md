# 仿真域说明

本文档根据 `src/sim` 和 `src/ats_sentry_bringup/launch` 中的仿真入口整理，并补充 2026-07-07 MuJoCo/MID360/ESDF/RViz 导航闭环修正结果。当前仿真主线已切换为 MuJoCo；Gazebo 入口和依赖已清理，不再作为后续导航测试方案。`loopback_sim` 保留，用于以后快速测试决策、Nav2 参数和话题链路。

## 仿真域结构

```text
src/sim/
├── loopback_sim/             # ROS 包名 nav2_loopback_sim
└── ats_mujoco_sim/           # ROS 包名 ats_mujoco_sim
```

## loopback 仿真

包路径：

- `src/sim/loopback_sim`

ROS 包名：

- `nav2_loopback_sim`

核心节点：

- `loopback_simulator`

源码：

- `src/sim/loopback_sim/nav2_loopback_sim/loopback_simulator.py`

入口：

- `src/sim/loopback_sim/launch/loopback_simulation.launch.py`
- `src/sim/loopback_sim/launch/bringup_launch.py`
- `src/sim/loopback_sim/launch/tb3_loopback_simulation_launch.py`
- `src/ats_sentry_bringup/launch/loopback_decision_sim.launch.py`
- `src/ats_sentry_bringup/launch/loopback_nav_only.launch.py`
- `src/ats_sentry_bringup/launch/loopback_vision_test.launch.py`

节点行为：

- 订阅 `initialpose`。
- 订阅 `cmd_vel`，可支持 `Twist` 或 `TwistStamped`。
- 发布 `odom`。
- 发布 `scan`。
- 可发布 `/clock`。
- 发布 `map -> odom`、`odom -> base_footprint`、`base_footprint -> base_link`、`base_link -> base_scan` 等 TF。
- 可补 `base_footprint -> gimbal_yaw_fake`，使实机导航链中依赖 fake yaw frame 的节点在 loopback 下也能运行。

适用场景：

- 快速验证 Nav2 参数。
- 验证行为树是否能发送 Nav2 action。
- 验证视觉接管逻辑，不需要物理引擎。
- 验证恢复行为和速度链路。

loopback 参数：

- `src/sim/loopback_sim/params/nav2_params.yaml`

该参数包含 Nav2、loopback simulator、B-spline smoother、trajectory speed governor 和恢复行为配置。

## MuJoCo 仿真

包路径：

- `src/sim/ats_mujoco_sim`

ROS 包名：

- `ats_mujoco_sim`

核心源码：

- `ats_mujoco_sim/sim_node.py`
- `ats_mujoco_sim/twist_to_motion_ctrl.py`
- `ats_mujoco_sim/kinematics.py`
- `ats_mujoco_sim/dynamic_obstacles.py`
- `mujoco_lidar/*`
- `models/swerve.xml`
- `models/swerve_chassis.xml`

入口：

- `launch/ats_mujoco_sim.launch.py`
- `launch/mujoco_navigation.launch.py`
- `launch/planner_mujoco.launch.py`

推荐完整导航入口：

```bash
ros2 launch ats_mujoco_sim mujoco_navigation.launch.py
```

低性能电脑推荐显式使用 CPU LiDAR 后端：

```bash
ros2 launch ats_mujoco_sim mujoco_navigation.launch.py \
  use_rviz:=true \
  use_viewer:=false \
  show_viewer:=false \
  enable_lidar:=true \
  lidar_backend:=cpu \
  lidar_downsample:=24 \
  enable_tof:=true \
  launch_nav2:=true \
  launch_twist_bridge:=true
```

`sim_node.py` 能力：

- 加载 MuJoCo 舵轮底盘模型。
- 接收 `manda_can_control` 控制消息。
- 发布运动反馈、四轮速度反馈、四轮转角反馈、电池和系统状态。
- 发布里程计和 TF。
- 可启用 MID360 扫描模式的 LiDAR 点云。
- 可启用 ToF 点云。
- 可处理动态障碍配置。

主要控制输入：

- `/motion_control`：`manda_can_control/msg/MotionCtrl`
- `/speed_ctrl`：`manda_can_control/msg/SpeedCtrl`
- `/steer_ctrl`：`manda_can_control/msg/SteerCtrl`
- `/simulation/PoseSub`：仿真位姿输入

主要反馈输出：

- `/motion_fb`
- `/speed_fb`
- `/steer_fb`
- `/battery_fb`
- `/system_state_fb`
- `/localization`
- `/lidar_odometry`
- `/local_pointcloud`，仿真 MID360 原始点云，默认 frame 为 `front_mid360`
- `/registered_scan`，已转换到 `odom` 语义的注册点云
- `/left_tof/points`
- `/right_tof/points`

`twist_to_motion_ctrl.py`：

- 在 `mujoco_navigation.launch.py` 中默认订阅 `cmd_vel_gimbal_yaw_odom`。
- `cmd_vel_gimbal_yaw_odom` 由 `fake_vel_transform` 从 `cmd_vel_nav2_result` 转换得到。
- 发布 `/motion_control`。
- 对 x、y、yaw 三个方向做比例和限幅。

MuJoCo 导航入口 `mujoco_navigation.launch.py` 组合：

- MuJoCo 仿真节点。
- `nav2_map_server`。
- 可选 `ats_nav_bringup` 导航链。
- 可选 `twist_to_motion_ctrl`。
- 可选 RViz。

当前 MuJoCo 完整导航链路：

```text
ats_mujoco_sim
  -> /localization
  -> /lidar_odometry
  -> /local_pointcloud
  -> /registered_scan
  -> terrain_analysis / terrain_analysis_ext
  -> /terrain_map / /terrain_map_ext
  -> /traversability_grid / /traversability_slope_grid
  -> Nav2 planner/smoother/controller
  -> /cmd_vel_nav2_result
  -> fake_vel_transform
  -> /cmd_vel_gimbal_yaw_odom
  -> twist_to_motion_ctrl
  -> /motion_control
  -> MuJoCo chassis
```

当前 MuJoCo LiDAR 测试链路固定使用 Livox MID360：

- `lidar_model` 默认且仅支持 `mid360`。
- `lidar_downsample` 控制 MID360 每帧 24000 条 ray 的降采样，默认 `1`。
- `lidar_frame_id` 默认 `front_mid360`，用于复用实车 terrain / costmap 传感器配置。
- `/local_pointcloud` 与 `/registered_scan` 均按 `x / y / z / intensity`
  字段发布，保证 `terrain_analysis(_ext)` 和 `IntensityVoxelLayer` 可按
  `PointXYZI` 链路解析。
- 其他 LiDAR 扫描模式不会被 `ats_mujoco_sim` 接受。

当前 MID360 / frame 约定：

- `/local_pointcloud`
  - frame: `front_mid360`
  - 含义：仿真 MID360 局部坐标系下的原始点云。
- `/registered_scan`
  - frame: `odom`
  - 含义：MuJoCo raycast 命中点转换到 `odom` 后的注册点云，供地形分析直接消费。
- `/lidar_odometry`
  - header frame: `odom`
  - child frame: `front_mid360`
  - 含义：当前仿真 MID360 位姿。
- `/localization`
  - header frame: `odom`
  - child frame: `gimbal_yaw_odom`
  - 含义：Nav2 使用的主机器人里程计。
- TF `gimbal_yaw_odom -> front_mid360`
  - 应与 `ats_robot_description` 中 MID360 模型外参一致。

注意：MuJoCo 模式下 `/registered_scan` 已经是 `odom` 下的注册点云，不应再当作 Point-LIO 的旧 `cloud_registered` / `lidar_odom` 语义重复变换。

## MuJoCo 地形、ESDF 与 traversability

当前地形链路：

- `terrain_analysis`
  - 订阅：`registered_scan`、`lidar_odometry`
  - 发布：`terrain_map`
  - frame：`odom`
- `terrain_analysis_ext`
  - 订阅：`registered_scan`、`lidar_odometry`、`terrain_map`
  - 发布：`terrain_map_ext`
  - 发布：`traversability_grid`
  - 发布：`traversability_slope_grid`
  - 发布：`traversability_height_diff_grid`
  - 发布：`traversability_occupancy_ratio_grid`
  - 发布：`traversability_ground_confidence_grid`
  - frame：`odom`

当前 RC-ESDF-lite / smoother 主输入：

- `trajectory_optimizer/Nav2BSplineSmoother`
  - `esdf_source: traversability_grid`
  - `terrain_pointcloud_topic: terrain_map_ext`
  - `traversability_grid_topic: traversability_grid`
  - `traversability_slope_topic: traversability_slope_grid`

关键实现约束：

- `terrain_analysis_ext` 内部 planar voxel 索引为 `planarVoxelWidth * indX + indY`。
- ROS `OccupancyGrid` 标准索引为 `x + y * width`。
- 发布 `traversability_grid`、`traversability_slope_grid` 和各 debug grid 时，必须把内部索引转换为 ROS 标准索引。
- 如果省略该转换，RViz 中点云方向可以正确，但 ESDF / traversability 会表现为 X/Y 转置或方向错误。

## MuJoCo RMUC2026 Mesh 场景

当前已接入用户导出的 RMUC2026 场地 mesh：

- 原始 OBJ：`src/ats_sentry_bringup/map/rmuc2026_v1_2_0.obj`
- 原始 STL：`src/ats_sentry_bringup/map/rmuc_2026.stl`
- MuJoCo 资产副本：`src/sim/ats_mujoco_sim/models/meshes/rmuc2026_v1_2_0.obj`
- MJCF 场景：`src/sim/ats_mujoco_sim/models/rmuc_2026_swerve.xml`
- 专用启动入口：`src/sim/ats_mujoco_sim/launch/rmuc_2026_mujoco.launch.py`

OBJ 导出坐标是毫米级，bounds 为：

- `x`: `[-14574.999728, 14574.999728]`
- `y`: `[-6400.656324, 9649.343676]`
- `z`: `[-1004.889128, -996.012790]`

因此 MJCF 中使用 `scale="0.001 0.001 0.001"` 转为米，并在 geom 上使用 `pos="0 -1.624343676 1.004889128"` 将场地中心对齐到 MuJoCo 世界原点附近，同时把最低顶点抬到 `z=0`。

只启动 RMUC2026 MuJoCo mesh 场景：

```bash
ros2 launch ats_mujoco_sim rmuc_2026_mujoco.launch.py \
  use_viewer:=true \
  launch_mujoco_rviz:=true \
  start_x:=-12.0 \
  start_y:=-6.0 \
  start_z:=0.20 \
  start_yaw:=0.0 \
  lidar_backend:=cpu \
  lidar_downsample:=24
```

低性能或只验证加载时可关闭 GUI：

```bash
ros2 launch ats_mujoco_sim rmuc_2026_mujoco.launch.py \
  use_viewer:=false \
  show_viewer:=false \
  launch_mujoco_rviz:=false \
  enable_lidar:=false \
  enable_tof:=false
```

注意：该入口只负责 MuJoCo 真实 mesh 场景和传感器仿真；完整 Nav2 仍需要与 RMUC2026 mesh 对齐的 2D/2.5D 导航地图。当前仓库中 `rmuc_2025.pgm` 可作参考，但不应长期直接当作 2026 场地的导航地图。

## MuJoCo RViz2

当前完整导航 RViz 配置：

- `src/sim/ats_mujoco_sim/rviz/mujoco_navigation.rviz`

该配置应包含：

- `Navigation 2` panel。
- `nav2_rviz_plugins/GoalTool` 目标工具。
- `/map`
- TF
- `/local_pointcloud`
- `/registered_scan`
- `/terrain_map_ext`
- `/traversability_grid`
- `/global_costmap/costmap`
- `/local_costmap/costmap`
- `/plan`

手动发目标时必须使用 Nav2 的 `GoalTool`。旧的 RViz 默认 `SetGoal` 只发布 `/goal_pose`，不会进入当前 Nav2 `/navigate_to_pose` action 主链。

如果 RViz 点目标后机器人不导航，优先检查：

```bash
ros2 action list | rg navigate_to_pose
ros2 action info /navigate_to_pose
ros2 topic echo --once /goal_pose
```

若 `/goal_pose` 有消息但 `/navigate_to_pose` 没有 goal，说明 RViz 仍在使用旧 `SetGoal` 工具，需要重新加载 `mujoco_navigation.rviz` 或确认 `nav2_rviz_plugins` 可用。

## 仿真与实机共享的部分

共享：

- 行为树包 `ats_sentry_behavior`。
- 导航域 `ats_sentry_nav`。
- 消息域 `interfaces`。
- 速度链 `fake_vel_transform` / `sentry_chassis_vel_transform`。
- 轨迹链 `trajectory_optimizer`。

不共享：

- loopback 不模拟真实动力学。
- MuJoCo 使用 `manda_can_control` 仿真控制接口。

## 仿真选型

- 只调行为树、Nav2 和话题链：优先 loopback。
- 调底盘动力学、LiDAR、ToF、控制接口：使用 MuJoCo。
- Gazebo 已从当前主线清理，不再新增 Gazebo 调试入口。
