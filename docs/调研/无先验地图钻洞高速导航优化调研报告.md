## 1. 现行架构与核心接口契约

### 1.1 活动导航链

```text
LiDAR (10 Hz) + IMU (200 Hz)
  -> Point-LIO（批量更新 + IMU 饱和降级 + SO(3) 高频前向传播）-> /odometry_identified, /registered_scan
  -> small_gicp_relocalization（Schur SE(2) 方向信息 + LOST-only Scan Context）-> localization_fusion -> map->odom
  -> ats_rog_map（odom 全局层 + 地面相对列 + TUNNEL_FREE + 进程内 adapter）-> /rog_map_adapter/planning_snapshot
  -> ATS Goal Manager (/ats_navigate_to_pose) -> 统一混合图搜索 -> MINCO S3 (bicubic) + 独立 yaw + 自适应连续扫掠足迹门 + Local Collision Repair
  -> /planner/execution_command（含带导数参考与提交屏障）
  -> ats_swerve_mpc（唯一 OSQP v1.0.0 SQP-RTI + 延迟增广 + 沿迹/横迹权重 + rollout 安全门）-> /cmd_vel/autonomy_raw
  -> [实机可选 sentry_chassis_vel_transform] -> cmd_vel_arbiter -> /cmd_vel/selected -> 串口 / MuJoCo (/motion_control)
```

- 正式链彻底移除 `ilqr`、`qp_shadow`、`astar_fallback`、独立 `ats_rog_map_adapter` 包、`/rc_esdf/*`、`/cmd_vel_mpc` 与任何 Nav2 节点/话题（无 `bt_navigator`/`planner_server`/`controller_server`/`/plan`）。
- Point-LIO 提供局部里程计与身份链（`odom_instance_id`/`odom_epoch`），无回环检测或位姿图后端；不引入 GPL-2.0 ZLIO 代码。

### 1.2 运行模式与雷达/速度链契约

| 维度 | 有图定位模式（默认 `slam:=false`） | 无先验建图模式（显式 `slam:=true` / `--mapless`） |
| --- | --- | --- |
| 先验输入 | 必需加载同源 PGM/YAML/PCD，缺图 fail-closed | 先验留空，在线累积 `40 × 30 m`（`0.1 m`）`odom` 全局层 |
| 静态墙与 unknown | `use_static_map_obstacles=true`，`allow_missing_static_map=false`，全来源 unknown 按障碍阻断 | `use_static_map_obstacles=false`，`allow_missing_static_map=true`，支持 A3 远目标局部前沿推进；已提交段保持 known-free |
| 漂移修正 | 先验 PCD 匹配 + `localization_fusion` | 增长点云地图匹配 + `localization_fusion` |
| 坐标系 | 内部地图/规划/控制在 `odom`；目标权威在 `map`，规划时按 `map->odom` 变换 | 同左；显式 `/rog_map/save_map` 时一次三维变换输出 `map` 系 PGM/YAML/PCD |

- **双模式雷达安装（`lidar_mount_mode`）与方案 A 速度链**（由 `scripts/validate_navigation_config.py` 锁定）：
  - `real_robot_navigation.launch.py` 默认 `lidar_mount_mode:="gimbal"`、`gimbal_use_base_footprint_odom:="True"`、`launch_fake_vel_transform:="False"`、`launch_chassis_vel_transform` 自动联动（`gimbal` 为 `True`、`chassis` 为 `False`）；`base_footprint` 解耦模式消除双父 TF 冲突并保留 `gimbal_yaw_odom -> gimbal_yaw_fake` 零旋转兼容 TF；显式设 `gimbal_use_base_footprint_odom:=False` 回退至大 yaw 前馈延迟补偿。
  - `bringup.launch.py` 默认 `lidar_mount_mode:="chassis"`，`launch_fake_vel_transform:="False"`，`launch_chassis_vel_transform:="False"`。
  - 小陀螺平移启用 `allow_body_yaw_follow:=true`、`enforce_gimbal_lock:=false`，MPC 与速度变换统一施加旋转系速度搬运 $R(-\omega_z \Delta t)$。

### 1.3 唯一所有权与失效安全底线

- `/rog_map_adapter/planning_snapshot` 唯一发布者为 `ats_rog_map` 进程内 adapter；单消息承载 occupancy、signed distance、梯度、`source_generation`、`publication_sequence`、`localization_epoch`。单次规划内图搜索、MINCO、足迹门与局部修复绑定同一不可变本地快照。
- `/cmd_vel/autonomy_raw` 唯一发布者为 `ats_swerve_mpc`；`/cmd_vel/selected` 唯一发布者为 `cmd_vel_arbiter`；`/motion_control`（MuJoCo）或串口桥唯一消费 `/cmd_vel/selected`。
- `/rog_map_adapter/ready` 是持续续租的 steady-clock 心跳；租约超时、Point-LIO 断流/重启、全 unknown、无路、unsafe 轨迹、MPC 求解失败或硬碰撞门禁均触发 `/planner/emergency_stop=true` 与三路确定性零速；恢复后不复活急停前旧参考。
- Goal Manager 在急停上升沿强制执行 `stop_to_reference_guard_sec`（默认 `0.01 s`）提交屏障，MPC 旧参考/旧 epoch 拒绝门不放宽。

## 4. 统一验收门禁

| 门禁 | 现行要求 |
| --- | --- |
| 到达精度 | 中间路线点 `map` 独立真值误差 $\le 0.15\ \mathrm{m}$；终点与重载首目标 $\le 0.08\ \mathrm{m}$ |

| 障碍延迟 | S3 实体障碍注入 20 次，可见延迟 `p95 < 250 ms`（O1 原设计目标 `150 ms`），同时报告最大值与射线清除恢复 |
| 失效安全 | `adapter_lease`（`SIGSTOP`/`SIGCONT`）、`point_lio_restart`、`unknown`、`no_path`、`unsafe` 均触发急停与三路持续零速；恢复后旧执行授权不复活 |

#### P0-2：为什么速度仍慢且轨迹不够平滑 + O2 真局部滚动地平线裁剪与拼接
- **实测根因（7 重叠加限速、平滑破坏与长线重算）**：
  1. **极端保守净空限速（最大元凶）**：仿真叠层 `rmuc_2025_navigation.yaml:137-139` 设置 `clearance_speed_min: 0.15`、`clearance_speed_low: 0.45`、`clearance_speed_high: 0.90`，中心净空 `<= 0.45 m` 的直行走廊/隧道被直接压死在 **`0.15 m/s`**，`0.45–0.90 m` 之间按 `0.15/(1-u)` 缓慢爬升；
  2. **窄道转向限速与小陀螺自旋误冲突**：`rmuc_2025_navigation.yaml:125-132` 设置 `narrow_turn_speed_limit: 0.8`、`narrow_turn_yaw_rate_threshold: 0.2`、`narrow_turn_clearance: 0.90`，与小陀螺（`spin_enabled: true`, `spin_rate: 3.0 > 0.2`）叠加时，所有净空 `<= 0.90 m` 的过道一旦起旋即被一刀砍到 `0.8 m/s`；
  3. **事后时间重缩放破坏 MINCO $C^2$ 光滑性**：MINCO 先完成 jerk 最小化，随后 `applyWheelSpeedTimeScaling` 按 `wheel_speed_time_scaling_change_rate: 0.6`（L121）在后处理阶段逐点拉伸 `dt`，直接打断加速度/加加速度连续性并拉出长斜坡顿挫；
  4. **引导折角与过度排斥导致走廊微摆**：`rmuc_2025_navigation.yaml:56-59` 的 `search_clearance_cost_weight: 4.0` + `path_shortcut_min_clearance: 0.8` 禁止净空 `< 0.8 m` 区域拉直捷径，喂给 MINCO 带折角引导；`max_lateral_acceleration: 1.5 m/s²`（`node_params.yaml:1066`）、`joint_time_weight: 20.0`（L1097）偏弱，且 `joint_center_clearance: 0.55` + `joint_footprint_clearance: 0.15`（`rmuc_2025_navigation.yaml:281-282`）在中等走廊受两侧墙排斥容易微摆；
  5. **高密度足迹采样 + 长线全量求解拖垮实时性**：仿真把 `joint_footprint_edge_samples` 抬到 **`4`**（每采样点 20 个足迹点 × 16 采样/段 × 27 段 = **8,640 次** ESDF 查询/次迭代）、`joint_time_budget_ms: 50.0`、`footprint_yaw_refinement_rounds: 2`（L286–293），叠加上 `spliced=0` 全线重解，导致 B1（28 m）单次 MINCO **`p95=184.43 ms`（`max=217.34 ms`）**，同时图搜索在全图重搜时先对 `0.436 m` 展开 `23,611` 节点（`10.4 ms`）失败后再降档 `0.341 m`；
  6. **滚动拼接分支失效（`spliced=0`）**：`minco_planner_node.cpp:2514-2618` 中分支 (A) 要求 `goal_match_dist <= 0.05` 且 `|seed_scale - 1.0| <= 1e-6`，分支 (B) 用全长 28 m 未优化代数续接段过全路径足迹门禁，远端任意一格擦边即整条丢弃并回退整条全图 L-BFGS 重解；
  7. **MPC 侧三重叠加减速**：`node_params.yaml:1386-1400` 中 `max_ax/ay: 2.0`、`max_wheel_acceleration: 2.0` 低于 MINCO `max_acceleration: 2.5`，加速段被削顶并触发滞后；`rollout_min_slowdown_scale: 0.45`（`rollout_slowdown_horizon_sec: 1.20`）靠墙再打折；`cross_track_slowdown_start/end: 0.15/0.60`（`min_reference_progress_scale: 0.10`）在轻微横偏时把参考进度大幅放慢。
- **优化方案**：
  1. **统一实车与仿真速度/平滑配置（消除 `rmuc_2025_navigation.yaml` 367 行双份漂移）**：(a) 重标定净空限速（如隧道直行安全段 `clearance_speed_min` 提升至 `0.6–0.8 m/s`，仅极窄急弯收紧）并改造 `narrow_turn_speed_limit` 只对路径几何转弯/主动转向限速，不因小陀螺自旋误杀平动速度；(b) 提高 `max_lateral_acceleration`（如 `2.2–2.5 m/s²`）与 `joint_time_weight`（平衡 `joint_energy_weight` 保证 jerk 光滑），收敛 `joint_center_clearance`（`~0.44–0.46 m`）与 `path_shortcut_min_clearance` 消除折角与走廊微摆；(c) 对齐 MPC 与 MINCO 的加减速上限（`max_ax/ay`、`max_wheel_acceleration`），将速度限制前置融入时间分配与 MINCO 联合优化，减少/取消破坏 $C^2$ 连续性的事后时间重缩放；
  2. **修复 O2 真局部滚动地平线（`8–10 m`）与稳定拼接（`spliced=1`）**：只对近端 `8–10 m` 窗口做完整 MINCO + ESDF 优化（固定 `6–10` 段、合理缩减冗余足迹边采样密度），放宽分支 (A) 的 `goal_match_dist` 与 `seed_scale` 判据，不再让未优化远端代数段一票否决近端拼接；缓存混合搜索净空档与节点缓冲；目标 B1 28 m 路线 **`MINCO p95 <= 20 ms`、全规划 `p95 < 30 ms`**。
