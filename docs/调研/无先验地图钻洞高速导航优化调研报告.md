## 1. 当前架构与接口契约

### 1.1 活动链

```text
LiDAR/IMU -> Point-LIO -> odom位姿、身份和去畸变扫描
                              |
                   ROGMap + odom全局层 + terrain
                              |
                   进程内adapter融合/数值ESDF
                              |
                /rog_map_adapter/planning_snapshot
                              |
map目标 -> ATS Goal Manager -> JPS/A* -> MINCO S3 + 独立yaw
                              |
                       footprint / local repair
                              |
                    ExecutionCommand授权及参考
                              |
                      全向SE2 iLQR MPC
                              |
                     速度仲裁 -> 四舵轮底盘
```

建图时，扫描与增长地图配准，经`localization_fusion`接受后修正`map->odom`；比赛定位时使用先验PCD。Point-LIO提供局部状态估计，ROGMap不是定位器。当前没有回环检测、位姿图或关键帧后端。

正式目标入口为`/ats_navigate_to_pose`，类型`ats_navigation_interfaces/action/NavigateToPose`。自研action及无Nav2 graph检查已有实现；P3整体验收仍须满足路线、取消/抢占/超时等门禁。历史Nav2兼容属于独立基线，不进入正式ATS链。

### 1.2 模式与坐标系

| 项 | 显式建图模式 | 比赛定位模式 |
| --- | --- | --- |
| 输入地图 | 不加载先验PGM/PCD | 先验文件必需，缺失fail closed |
| 静态PGM障碍 | `use_static_map_obstacles=false` | 当前仍为true，尚未完成原“仅作引导”目标 |
| unknown | 远目标可在未观测区域，局部目标接续待实现。已提交段须 known-free | unknown 按现行阻塞规则处理 |
| 漂移修正 | 增长地图匹配 + fusion | 先验PCD匹配 + fusion |
| 内部地图/规划/控制 | odom | odom |
| 目标权威/保存地图 | map；每次规划转换目标，保存时一次转换静态层 | map目标按当前`map->odom`转换 |

普通`map->odom`修正不搬移内部odom地图。前端实例或epoch变化属于独立失效事件，必须按身份/重置契约处理，不能沿用旧轨迹。

### 1.3 唯一所有权、时间与数值场

- 规划地图由`ats_rog_map`进程内adapter唯一发布；投影使用进程内调用。正式链没有独立投影service/client和owner二选一入口。`PLANNING_GRID_OWNER=rog_map`只保留为runner兼容取值。
- `PlanningMapSnapshot`携带occupancy、signed distance、梯度、`source_generation`、`publication_sequence`和`localization_epoch`。MINCO单次规划绑定不可变本地快照，JPS/MINCO/footprint/repair使用同一版本。
- 来源generation、发布序号、MINCO本地generation和执行参考stamp含义不同，不要求数值相等；必须验证生产、消费、提交和拒绝的传递关系。
- 融合遵守occupied优先；任一新鲜来源的明确free可消解其他来源unknown；所有来源都无free/occupied证据才为最终unknown。来源范围外或terrain/slope的-1仅表示缺少该来源证据，不能覆盖另一来源的明确free。
- unknown、地图外、距离场符号/梯度、origin/yaw、分辨率、QoS和steady-clock租约均为接口契约。物理占据、ROG inflation、JPS clearance和footprint margin分层，避免重复膨胀；细静态图向粗栅格转换采用面积重叠保守聚合。
- ego unknown清理默认0.0；只有对应profile的定向矩形和边界测试通过后才评估启用，occupied始终保留，不按外接圆清理足迹外unknown。
- 当前正式执行授权为`ExecutionCommand`，其中参考仍为`nav_msgs/Path`，尚未完成解析导数轨迹接口。调试点云不是数值ESDF接口。
- ready是续租心跳。输入健康、地图新鲜度和规划安全必须同时满足；ready恢复不复活急停前reference。map stale/unready、全unknown、无路、unsafe及MPC失败均保持确定性零速。

### 1.4 闭环验收需要追踪的话题

| 链路 | 必查契约 |
| --- | --- |
| Point-LIO输入 | `/localization`、`/registered_scan`的frame、观测时间、身份与stale行为 |
| ROG可视化 | `/rog_map/occ`、`inf_occ`、`unk`、`esdf`非空只作辅助；不反解析ESDF点云 |
| 规划快照 | `/rog_map_adapter/planning_snapshot`只有1个发布者；正式graph无`/rc_esdf/*` |
| 规划/控制 | `/minco/raw_path`、`/minco/reference_path`、MPC reference/predicted及正式执行授权可追溯 |
| 安全/底盘 | `/planner/emergency_stop`、`/cmd_vel/autonomy_raw`、`/cmd_vel/selected`、`/motion_control`；分别核验 MPC、arbiter、bridge 的唯一发布权与底盘消费者，故障后三层输出均零；`/cmd_vel_mpc` 仅保留在历史证据中 |

P3最终要求正式入口不启动Nav2：当前入口已不声明`launch_nav2`，不传不存在的开关；兼容入口若仍声明该参数则显式设为`false`。同时核对无四类Nav2服务进程、MINCO不订阅`/plan`、目标入口不调用Nav2 action，以及自研feedback/result/cancel/preempt/timeout和当前2027隧道/对称点速度套件均通过。正式入口已有实现与这些最终门分开记；旧矩形/红框只作历史记录。

## 2. 当前有效配置与物理边界

### 2.1 profile口径

数值以实际launch加载及覆盖后的参数为准；下表是当前受版本控制的配置，不代表实车测量结果。

| 项 | 实车 | 2025仿真 | 2027仿真 |
| --- | --- | --- | --- |
| footprint长×宽 | 0.581×0.571m | 0.581×0.571m | 0.581×0.571m |
| footprint margin | 0.02m | 0.02m | 0.02m |
| ROG车高门 | 候选0.242+0.007=0.249m | 同左 | 同左 |
| terrain头顶门 | 0.249m | 0.249m | 0.249m |
| `jps_safe_distance`配置值 | 0.36m | 0.36m | 0.36m；运行时足迹准入仍有效 |
| `yaw_tunnel_enabled` / `spin_enabled` | true / true | true / true | true / true |

用户11月16日明确要求三类profile使用2027取值，已据此同步实车配置。这是新的直接配置授权，不代表H2净空、M路线或H3实车适用性验收通过；0.249m仍是未获证候选门。本轮不操作实车。

`jps_safe_distance`的YAML值为0.36m；现有节点仍会把首选搜索净空提升至矩形全航向半径约0.436m，无路时再走放宽阶梯，最终由定向足迹门裁决。本轮没有移除该保护，不能把配置值等同于所有搜索阶段的实际净空。

#### 2.1.8 雷达与速度兼容层

雷达固定在底盘上；`gimbal_yaw_odom`保留名称，语义为底盘系。通用`bringup.launch.py`的两个速度兼容层默认False，`real_robot_navigation.launch.py`默认均为True，保留用户指定的fake-yaw链。外参、重力、位姿年龄和底盘响应仍待实车测量。

### 2.2 地图范围

odom全局存储为40×30m、0.1m；12×12m是跟随机器人计算ESDF/JPS/MINCO的窗口，不是全部地图存储。ROGMap三维滑窗的数值配置保持独立。窗口移出不删除全局层，范围外观测计数并记录。RViz默认关闭体素/unknown/ESDF、地图和路径调试组，只显示当前传感器点云、车模与MID360坐标轴；不删除规划所需数值场。

栅格静动态晋升、视野内射线清除、视野外保持后退回unknown及静态保存过滤已有实现；点簇关联、速度跟踪和沿速度前向膨胀未发现生产实现。保存PGM/YAML/PCD的接口存在，完整保存质量与动态排除仍待验收。

### 2.3 速度与控制限制

用户报告实车可达8–10m/s，具体值待其测量；本阶段统一暂定5m/s：MINCO的`reference_speed/max_velocity`、MPC的`max_vx/max_vy`、实车速度变换出口、MuJoCo速度桥及单轮线速度上限均为5.0。MINCO起点保护跟随当前`max_velocity`，不再固定截为2m/s；MuJoCo同时按5/0.0425≈117.647rad/s配置轮端控制范围，避免XML旧范围再次截断。

已确认yaw速率上限3rad/s、角加速度2rad/s²；保留平移/逐轮加速度、转向、曲率、近障和终点停车约束。MPC预测窗口60×0.05=3s，覆盖5m/s、2m/s²的2.5s制动时间。5m/s是允许上限，不要求在窄洞或不安全路径强行达到。

旧450rpm推定不再作为当前能力证据。当前`motor_max_rpm=1348.1359885`是按0.0425m轮半径、减速比1和1.2冗余反推的暂定等效值，使保守轮速与显式5m/s一致，并非电机实测铭牌。平移与自旋的组合仍受逐轮向量限速，不能同时任意取满两项上限；单轮时间缩放仍不启用。

### 2.4 MID360与MuJoCo资源/显示

MID360官方典型帧率10Hz、首回波20万点/秒、水平360°；本轮点云按该口径仿真，项目IMU配置保持200Hz，不再沿用LIO入口的20Hz/24万射线口径。[官方规格](https://www.livoxtech.com/cn/mid-360/specs)

- 每帧0.1s最多2万条射线，实际回波数取决于命中。按<=5ms分段使用当时底盘状态，保留逐点offset_time；模板均匀重采样，降采样覆盖整帧，不放慢扫描相位。
- 启动时根据进程CPU affinity分配约1/3逻辑核、最多8个追踪线程，独立LiDAR子进程限制到这组CPU；BLAS/OMP单线程防止嵌套抢占。自动预算1/2–3/4+线程对应约5000/10000/20000射线/帧，显式正值可覆盖。
- 当前源码进一步在继承的可用CPU集合中优先选择独立高频物理核，再补兄弟线程；拓扑不可读时保留回退分配，不修改宿主调度策略或全局配置。另一主机的同输入射线微基准不能代替本机在线实时率与健康验收。
- 频率以仿真时间计。机器不足时物理背压降低实时率，不能用丢帧或重写stamp伪造10Hz；墙钟频率与实时率单列。
- 雷达固定在底盘，分段射线姿态与IMU随底盘转动。RViz固定odom，配准后的环境保持稳定；原始扫描/传感器轴随姿态变化，不人为旋转已配准地图。当前点云用Points且Decay Time=0；体素和距离场调试组可手动打开。

## 附录 A：自包含算法要点

本附录保留候选规则与公式，均为后续模块的实施建议，不代表当前源码已经实现或验收通过。数值标“参考值”的只作初值；采用前仍须核验原始实现、许可证和适用条件，并在本项目实测标定。第2节是当前参数权威，第5节决定实施顺序。

### A.1 ROGMap 列语义（取自 navi_minco_bit `projection_layer.cpp`，加入本项目顶板判据）

对每个 XY 列统计：观测次数 `observed_count`、占据体素数 `occupied_count`、最低/最高占据体素 z 索引。分辨率记 $r$。

```text
if observed_count < min_observed:            -> UNKNOWN（观测不足，不是 free）
if occupied_count == 0:                      -> FREE
span = (z_idx_max - z_idx_min) * r
ratio = clamp((occupied_count - 1) * r / span, 0, 1)   # 竖向占据率
if span <= surface_max:                      -> 薄面，可通行（地面/薄板）
if span >= wall_span_min and ratio >= wall_ratio_min:  -> 墙，占据
if tunnel_span_min <= span <= tunnel_span_max and ratio <= tunnel_ratio_max:
                                             -> 空心列（候选隧道），交给顶板判据
else                                         -> 不确定，按占据
```

参考值：`surface_max=0.10`、`wall_span_min=0.20`、`wall_ratio_min=0.80`、`tunnel_span=[0.24,0.40]`、`tunnel_ratio_max=0.55`。

参考实现缺的顶板判据，本项目必须加：取列内（或 3×3 邻域）最低连续占据面为局部地面 $z_g$，列内最低的“悬空”占据为顶板 $z_c$，

$$
\text{TUNNEL\_FREE} \iff z_c - z_g \ge h_{\mathrm{robot}} + m_{\mathrm{top}}
\ \wedge\ \nexists\, z_{\mathrm{obs}} \in (z_g + h_{\mathrm{step}},\ z_g + h_{\mathrm{robot}} + m_{\mathrm{top}}).
$$

所有高度都相对 $z_g$，不用绝对 odom z。这样坡道、台阶和机器人自身的俯仰都不会把顶板误判成障碍或把低洞误判成可通行。只有空隙存在而不比较车高的规则（ZT_2027 `dog_map` 的“列内空隙 >0.15 m 即通行”）会产生假 free，不要用。

### A.2 动静态双层（O1 候选规则；当前实现边界见5.3）

每格状态：`first_hit`、`last_hit`、`hit_time_accum`、`cleared_once`、`layer∈{DYN, STATIC}`。

```text
on hit(cell, t):
    if cell 空: first_hit = t, layer = DYN
    hit_time_accum += min(t - last_hit, frame_dt_max); last_hit = t
    if layer == DYN and hit_time_accum >= T_s(3 s) and not cleared_since(first_hit):
        layer = STATIC
on ray_pass_through(cell, t):          # 视野内本应命中却被穿透
    清除该格（DYN 与 STATIC 同样处理），cleared_once = true
on tick(t):
    DYN 且不在视野内: if t - last_hit > T_hold(约 3 s): 置 UNKNOWN（不是 FREE）
    DYN 且在视野内: 不按时间清除，只靠射线穿透清除
save_map(): 只写 STATIC 且 cleared_once == false 且观测占比高于阈值的格
```

对照：navi_minco_bit 用纯时间衰减（最后一次命中后 `keep_time=0.5 s` 仍占据，`clear_time=1.2 s` 强制变 free），开销低，但被遮挡的墙会被清成 free，不满足本项目高速需求。

移动障碍：同一帧 DYN 格做欧氏聚类，簇质心用最近邻或匈牙利匹配关联上一帧，常速度 Kalman 估计速度；速度超过阈值的簇沿速度方向前向膨胀 $v\cdot t_{\mathrm{pred}}$（$t_{\mathrm{pred}}$ 取规划周期加 MPC 预测一半）。

### A.3 滚动重规划起点与局部目标（取自 sentry_nav_26，按 SUPER 时间语义收紧）

```text
t_now = 当前时间；t_ref = min(t_now - traj.start + plan_lead, traj.duration)
if 正在执行 and |traj.p(t_ref) - p_measured| < deviation_max:
    start = (traj.p, traj.v, traj.a, traj.yaw)(t_ref)；新轨迹 t0 = traj.start + t_ref
else:
```

### A.7 连续 footprint 检查采样步长（Implicit-SVSDF 的简化替代）

定向矩形半对角线 $\rho=\tfrac12\sqrt{L^2+W^2}$。相邻采样间任一车体点的最大位移满足

$$
\delta \le |v|_{\max}\,\Delta t + |\omega|_{\max}\,\rho\,\Delta t .
$$

若把相邻检查间的最大位移预算限制为余量的一半，可取 $\delta \le m/2$（$m$ 为 footprint 余量），得到采样时间上限

$$
\Delta t \le \frac{m}{2\,(|v|_{\max} + |\omega|_{\max}\rho)} .
$$

按当前暂定上限，$L=0.581$、$W=0.571$、$\rho\approx0.407$、$v=5$、$\omega=3$、$m=0.02$，得 $\Delta t \le 1.6\,\mathrm{ms}$。这只是位移采样预算；完整不漏碰证明还依赖足迹栅格化、占据保守性及连续间隙下界，不能由该式单独推导。当前半格采样尚未满足此预算。

### A.8 隧道轴线估计

取预瞄窗口内左右两侧墙点（ESDF 等值线或 A.1 中隧道两侧的墙列），分别对左右两组点做主方向估计（PCA 第一主轴）。轴向 $\psi_{\mathrm{axis}}$ 取两主轴的平均，用 $\mathrm{atan2}$ 在 $[-\pi,\pi)$ 内求平均，并处理 $\pm\pi$ 等价；宽度取两组点到轴线距离之和的中位数。用滑动窗口，不从段起点累积。中线上左右墙的 ESDF 梯度相互抵消，所以不能用梯度方向估计轴线。

### A.9 全向 MPC：舵轮轮速线性约束与延迟补偿

车体系命令 $u=[v_x, v_y, \omega]$。第 $i$ 个舵轮安装位置 $(x_i, y_i)$，轮速矢量为

$$
\mathbf v_i = \begin{bmatrix} v_x - \omega y_i \\ v_y + \omega x_i \end{bmatrix},\qquad \|\mathbf v_i\| \le v_{w,\max}=5.0\ \mathrm{m/s}.
$$

圆约束用内接正 $K$ 边形线性化（$K=8$ 时保守度 $\cos\tfrac{\pi}{8}\approx0.924$）：

$$
\cos\theta_j\,(v_x - \omega y_i) + \sin\theta_j\,(v_y + \omega x_i) \le v_{w,\max}\cos\tfrac{\pi}{K},\quad \theta_j = \tfrac{2\pi j}{K},\ j=0..K-1 .
$$

每个轮 $K$ 行、4 轮共 $4K$ 行，对 $u$ 线性，可作为后续QP候选约束。只对软约束行加精确罚 slack；本项目MPC失败继续输出确定性零速。分级制动需要先完成独立安全契约，不能直接迁入参考项目的失败缓降行为（holonomic_mpc_ekf 为 GPL-3.0，只借鉴思路）。

延迟补偿（参考 navi_minco_bit）：

- 求解前把测量状态按控制延迟 $t_d$ 用上一拍已发布命令前推：$\hat x(t+t_d)$；
- 世界系到车体系旋转时，用 $\psi + \omega\,t_d/2$ 代替 $\psi$，补偿执行期间的转动。

更完整的做法是把执行器建模为一阶滞后 $\dot v = (u(t-t_d) - v)/\tau$，作为增广状态加入预测模型，命令历史用环形缓冲保存。

沿迹/横迹权重：位置误差投影到参考切向 $t$、法向 $n$，代价写为 $q_t (e\cdot t)^2 + q_n (e\cdot n)^2$。参考值 $q_t=3$、$q_n=12$，用于抑制高速抄弯。

### A.10 重定位接受门（取自 HWSentryNav26 `odom_localizer`）

以下1 Hz、单线程及接受阈值来自上游候选设计，不是当前ATS已部署或实测的配置；当前参数以根YAML和第2节为准。候选接受条件为：

- 归一化误差 ≤ 0.3；
- 重叠率 ≥ 0.8；
- 信息矩阵（Hessian）最小特征值 ≥ 1e3；
- 条件数 ≤ 1e6。

后两条用于拒绝长走廊、隧道内沿轴向不可观测的退化匹配。接受后，与当前估计的跳变超过 0.2 m 或 0.1 rad 不直接采用，先连续确认；采用时用 EMA（系数 0.6）平滑。初始锁定参考 navi_minco_bit：粗配准（0.5 m 下采样）后做精配准（0.2 m），连续 3 个窗口结果的中位数一致才锁定。

### A.11 定位降载（Batch-LIO 思路）

Point-LIO 对每个点做一次 EKF 更新。Batch-LIO 把 1 ms 时间窗内的点合并为一次 EKF 更新（`batch_dt=0` 时退化为原逐点更新，结果逐位一致）；批量化后残差计算可以多线程并行。其 README 自述单帧计算最多降低 4.7×（未复现）。移植时只改更新调度，不改状态定义和观测模型，并以 `batch_dt=0` 与现有 `point_lio` 输出逐位比对作为第一道回归。

### A.12 弧长速度剖面（取自 HWSentryNav26）

几何定型后，以 $w(s)=v(s)^2$ 为决策变量，约束为

$$
0 \le w(s) \le v_{\max}(s)^2,\qquad
\left|\frac{w_{k+1}-w_k}{2\Delta s}\right| \le a_{\max},\qquad
\kappa(s)\,w(s) \le a_{\mathrm{lat,max}} .
$$

这些约束都是线性的，可用 LP/QP 求解。$v_{\max}(s)$ 在隧道段取 COMMITTED 恒速，在窄道和大曲率处取更低值。求出 $w(s)$ 后由 $\Delta t_k = 2\Delta s/(\sqrt{w_k}+\sqrt{w_{k+1}})$ 反推时间分配，作为 MINCO 的初始时间。
