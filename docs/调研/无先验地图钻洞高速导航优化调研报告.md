## 0. 结论

当前架构本质上是“先验地图驱动 + 低频全场栅格 + 停走式规划”，与目标三条（无先验障碍、钻洞、高速跟随）在结构上相反，调参无法达到目标，需要改三处骨架：

1. 障碍/规划栅格改为 odom 系（场地尺寸累积静态层 + 高频局部动态窗口），静态 PGM 退出障碍源，只做全局引导与重定位，地图就绪与重定位状态解耦（见第 0.1 节决策）；
2. 规划改为连续滚动时域重规划（从已提交轨迹前推状态起规划、换轨不急停、失败走制动轨迹而不是急停）；
3. 钻洞改为“列语义（顶板/地面分离）+ 定向矩形 footprint + 隧道执行契约”三件套。

定位链不需要推倒：Point-LIO 已不加载先验图，GICP + fusion 已是独立后端，与 z-localization 的“前端只做里程计、先验配准作为后端观测”结构一致。要改的是第四处：

4. 后端从“整帧接受/整帧拒绝 + 整体替换 map->odom”改为“按方向接受观测”（Schur 可观测性分析 + 信息加权更新 + NIS 门 + 分级状态机），跟踪期降到 1 Hz 单线程局部子图，恢复期才开高预算；前端在 Point-LIO 降载与 ZLIO 之间用 bag A/B 决定（第 2.1 节）。

### 0.2 场地边界与动静态障碍判定

场地边界不需要靠先验 PGM 判定，分两类处理：

1. 物理边界墙：雷达能看到，与其他墙一样由实时点云进入累积静态层。
2. 规则边界（场地外不可去）：用规则已知的场地矩形/多边形做 map 系 geofence。它只在 `/localization/status` 为 CONFIRMED/TRACKING 时启用，带定位误差余量，只约束全局引导与目标准入，不写入局部障碍层。定位丢失时 geofence 失效，局部避障不受影响。

点云积累可以区分动静态障碍。建议两层结构，全部在 odom 系：

| 层 | 判据 | 用途 |
| --- | --- | --- |
| 静态层（场地尺寸 2D，持久） | 同一格累计被命中时长 $\ge T_s$（默认 3 s，参数化；按累计而非连续计时，跨多次进出视野叠加），且期间没有被射线穿透清除；ROGMap 已有 hit/miss 射线概率更新，只需给每格加 `first_hit`、`last_hit`、`hit_count` | 全局引导 + 局部规划；赛后按保存过滤条件写入 PGM |
| 动态层（局部窗口，视野内清除） | 存活时间 $<T_s$ 的占据，或被射线穿透过的格；点簇做聚类 + 最近邻/匈牙利关联 + 常速 Kalman（参照 `webfound/HWSentryNav26/map_server/src/object_tracker.cpp`），速度超过阈值即标记移动 | 只进局部避障，移动簇按速度方向前向膨胀；清除规则见下方；不保存 |

判据说明：

- 射线穿透（free-space contradiction）是区分静态和动态的主证据：静止车辆离开后，其所在格会被后续射线清掉，自然退出静态层。
- 有先验时，可把先验当分类证据而不是障碍源：实时点落在先验墙上 -> 提高静态置信度；实时点不在先验中 -> 先进入动态层，按存活时间与射线清除规则处理。障碍是否存在永远只由实时点云决定。
- $T_s$ 取 3 s 的原因：高速行驶时一个静态障碍可能只在视野内停留数秒，取太长会导致它始终晋升不了；同时比赛中机器人卡柱、阵亡停在原地是常态，太短会把它们大量写入静态层。3 s 是两者的折中，需用比赛 bag 回放复核。新看到的墙、柱在晋升前留在动态层，因此动态层不能按纯时间衰减，否则被遮挡的墙会“消失”。局部避障安全只依赖动态层的保持规则，不依赖是否晋升。
- 动态层清除规则：只有当格子处在当前视野内、且被射线穿透（应命中却没命中）时才快速清除；处在视野外或被遮挡时保持，直到保持上限 $T_{\mathrm{hold}}$（建议与 $T_s$ 同量级，约 3 s）后才降级为 unknown，而不是降为 free。这样卡柱或阵亡的机器人只要还在视野里就一直是障碍，移开后被射线清掉。
- 静止超过 $T_s$ 的机器人（卡柱、阵亡后停留）会晋升为静态层，这是安全方向的误判；它离开后同样被射线清除。
- 赛后保存过滤：只写入“累计存活时间占观测时间比例高、且整场末段仍存在”的静态格；对晋升过静态但后来被射线清除过的格（典型是停过的机器人）不写入地图。具体比例阈值需用比赛 bag 回放标定。

### 0.3 建图模式下的规划坐标系

规划栅格放 odom 更好，并且不影响全图规划。

- 建图模式（无先验首跑）下没有重定位，`map->odom` 是恒等或开机固定值，map 与 odom 重合。“在 map 下全图规划”和“在 odom 下全图规划”是同一件事。
- 有先验的后续比赛中，GICP 会修正 `map->odom`。如果障碍存在 map 系，每次修正都会让所有障碍相对机器人跳变；存在 odom 系，障碍与机器人位姿始终出自同一里程计，局部一致性不受重定位影响。
- 全图不等于小窗口：RMUC 场地约 28×15 m，0.1 m 分辨率的 2D 静态层约 4.2 万格，放在 odom 系完全可承受。3D ROGMap 仍保持局部滑窗，只负责把新观测写进 2D 层。

推荐分工：

```text
map 系：目标点、全局引导路径（静态层 + geofence 上的粗 A*/JPS，1 Hz）、赛后保存的地图
odom 系：场地尺寸 2D 静态层、局部动态层、ESDF、MINCO、MPC
每次重规划：引导路径用当前 map->odom 转到 odom，取 4–6 m 处为局部子目标
```

赛后保存：保存 odom 系静态层（转换到保存时的 map 系）为 PGM，同时保存 Point-LIO PCD。下一场它只用于重定位和全局引导，不进入障碍层。当前 `mapping.sh` 的保存链需要先核对（见第 0 节表）。

## 1. 现状链路与瓶颈定位

```text
Mid360 20Hz -> Point-LIO(500Hz 轮询；逐点组发布 aft_mapped_to_init，见 2.1.7)
 -> loam_interface / sensor_scan_generation (按点云频率 10-20Hz 发布 /odometry，TF 查询阻塞上限 0.5s)
 -> small_gicp(0.35s, 先验 PCD) -> localization_fusion(map->odom 10Hz)
 -> ROGMap(odom, 10x10x1m@0.1, 每帧全 3D ESDF)
 -> adapter(0.5Hz 调投影服务 + terrain_ext + slope + 静态 PGM -> map 系全场栅格 + EDT)
 -> minco_planner(每张栅格全拷贝 + SHA + 全场 RC-ESDF 重建；仅 goal 触发规划)
 -> goal_manager(10Hz，提交点 sequence 严格相等 + 云台 ack)
 -> ats_swerve_mpc(20Hz, N=30, dt=0.05, 运动学 iLQR, 约束靠投影)
 -> fake_vel_transform -> chassis_vel_transform(缺源码) -> arbiter(20Hz 定时器锁存) -> 串口
```

新障碍物到规划器可见的时延（`推断`）：

$$
t_{\mathrm{obs}} \approx t_{\mathrm{scan}} + t_{\mathrm{LIO}} + t_{\mathrm{wait}}^{[0,2\,\mathrm{s}]} + t_{\mathrm{proj}}^{[0.9,3.2\,\mathrm{s}]} + t_{\mathrm{EDT}} \approx 1.0\ \text{至}\ 5.5\ \mathrm{s}
$$

1.5 m/s 下相当于在 1.5–8 m 的陈旧地图上行驶；而所需制动距离仅为

$$
d_{\mathrm{brake}} = v\,t_d + \frac{v^2}{2a} = 1.5\times0.2 + \frac{1.5^2}{2\times2.0} \approx 0.86\ \mathrm{m},
$$

所以瓶颈是地图链时延而不是感知距离（ROGMap 射线 10 m 已足够）。

#### 2.1.2 现状问题

- 下游 `/odometry` 跟随点云频率（10–20 Hz）。`publish_odometry_without_downsample: True` 不是 IMU 频率输出：它在每个点组 EKF 更新后都发布一次 `aft_mapped_to_init`（`laserMapping.cpp:686-689`），Mid360 点时间戳几乎各不相同，频率接近“每帧点数 × 20 Hz”，只被 `loam_interface` 拿来做最近时间匹配（2.1.7 第 1 项）。`sensor_scan_generation` 每帧阻塞 TF 查询上限 0.5 s。
- 地图 ready 与 `/localization/status` 绑定（`bringup.launch.py:163`，adapter:230-264）：没有先验 PCD 时 GICP 不确认，fusion 停在 BOOTSTRAP，局部避障也随之失效。避障本不需要全局定位（O1 解耦）。
- 默认 `world=rmuc_2026` 没有 `pcd/rmuc_2026.pcd`，过不了 preflight（`real_robot_navigation.launch.py:32-35, 63-64`）。
- 观测粒度太粗：退化门实车关闭（第 0 节），fusion 只有“接受 -> 整体替换”与“拒绝”两档，协方差只查有限性（`localization_fusion_node.cpp:58-66`）。隧道和长走廊里沿轴方向不可观，但横向与 yaw 仍然可观；整帧门要么把错误的轴向修正写进 map->odom，要么把有用的横向/yaw 约束一起丢掉。
- 跟踪期算力偏高：0.35 s 定时 + 3 线程 + 全局 KD 树，正常跟踪也在全图上找对应。
- 恢复范围太窄：multi_guess 只在当前估计 ±2 m、8 个 yaw 上搜；开局放错、被撞飞或长时间 LOST 后超出窗口就找不回，没有地点描述子。
- Point-LIO 计算量随点数线性增长：`point_filter_num 8` + 0.05 m 体素基本只靠固定抽点，开阔区点多 CPU 高，洞内点少约束弱，两头都不理想 [推断]。
- 前端没有 epoch：Point-LIO 发散只能整栈重启，重启后 odom 原点变化，而第 0.3 节把障碍与规划栅格放进了 odom 系，下游没有“odom 换代”的信号可用。
- 初始化依赖静止：`imu_en: True` 时用前 `MAX_INI_COUNT` 个 IMU 样本的加速度均值定重力方向（`laserMapping.cpp:490-507`，`IMU_Processing.cpp:87-110`），`gravity_init` 只在 `imu_en: False` 时使用。雷达已改装到底盘（2.1.8），比赛中重启时底盘可能正在小陀螺，初始姿态会偏 [推断，未实测]。

#### 2.1.3 z-localization 对照（`参考/webfound/z-localization` `76e1263`，GPL-2.0-only）

结构上它与本项目同构：ZLIO 前端只维护 odom 系里程计与自己的局部地图，后端用 GTSAM 固定滞后因子图维护 map->odom，先验图配准、回环、UWB 都是后端观测。区别在后端的观测处理和前端的自适应。

#### 2.1.4 HWSentryNav26 定位层对照（`f5f9412`，MIT）

| 模块 | 做法 | 结论 |
| --- | --- | --- |
| `small_glim` | 从 GLIM 精简：iSAM2 固定滞后 3 s 平滑器，每帧一个 iVox GICP 因子 + IMU 预积分因子，联合估计位姿、速度、零偏；预处理、估计、建图分线程异步；预处理与估计各 6 线程；初始化用开机 IMU 均值（`naive_initialization: true`，要求静止） | 不采纳为前端，理由见下表 |
| `small_glim` 撞击暂停 | IMU 任一轴饱和的帧直接丢弃不入图，之后 0.5 s 暂停插图；新帧延迟 0.5 s 才插入局部地图（用优化后的位姿） | 采纳饱和暂停（附录 A.19）；延迟插图依赖平滑器回头修正位姿，Point-LIO 是滤波器，不采纳 |
| `odom_localizer` | 915 行单节点。GICP 1 Hz 单线程，对整张先验图建 KD 树；启动 10 s 内用 `registered_cloud` 6 帧滑窗做源，之后改用前端 iVox 局部地图快照；按裁判系统颜色给红/蓝方初始 map->odom；整帧门 0.3/0.8/1e3/1e6，跳变 0.2 m/0.1 rad，EMA 0.6；没有描述子恢复，没有分级状态机 | 采纳调度、颜色初值、局部地图快照作源的思路；整帧门换成 Schur 方向门 |

为什么 HWSentryNav26 定位层借鉴得少：

- `small_glim` 的强项是平滑器的鲁棒性，代价是算力。它依赖 GTSAM 4.3 + `gtsam_points` 1.2（需源码编译，且要和 `-march=native` 编译选项一致），作者在 DEPLOY.md 里自述“这套方案确实比较吃 CPU”，平台是 Ultra 9 285H。本项目这一轮的目标是降 CPU，换成它方向相反。
- `odom_localizer` 的功能，本项目 `small_gicp_relocalization` + `localization_fusion` 基本都有，还多了确认计数、multi_guess、运动一致性检查和状态机。它真正值得拿的是“低频单线程”的调度纪律，这一条已写进 O5a。
- 它的地图层强依赖先验，第 3 版就已经排除。

HWSentryNav26 与 z-localization 对比（均为源码阅读 + 作者自述，未运行）：

| 维度 | HWSentryNav26 | z-localization | 更强的一方 |
| --- | --- | --- | --- |
| 前端算法 | 固定滞后因子图平滑（GICP + IMU 预积分），退化或颠簸时能用 3 s 窗口回头修正 | 迭代滤波 + 等变误差状态，平面分组相关残差，时空自适应 | 鲁棒性 HW 略占优（平滑器天然优势）；算力 z-loc 明显占优 |
| 前端算力 | 6+6 线程，作者自述吃 CPU | 关联线程 ≤2，作者自述前后端合计约 15% 单核 | z-loc |
| 前端初始化 | 要求静止 | 不要求静止，多帧联合估计重力和零偏 | z-loc（底盘小陀螺中重启更需要） |
| 后端观测 | 整帧门 + EMA | Schur 方向门 + NIS + 因子图 | z-loc，差距最大 |
| 状态与恢复 | 接受/拒绝两档；只有开局颜色初值 | 四级状态机；Scan Context 全场恢复；前端协调重置 | z-loc |
| 无先验图 | 不支持（地图为空只发初始位姿） | 建图模式 + 回环 + 地图包保存 + 离线动态残影清理 | z-loc |
| 依赖 | GTSAM 4.3 + gtsam_points（源码编译） | 前端无 GTSAM；后端 GTSAM 4.2 | z-loc 前端更轻 |
| 许可 | MIT，可直接拷代码 | GPL-2.0-only，只借鉴思路（已决策） | HW 更方便 |

结论：整体是 z-localization 更强，主要差在后端（方向门、状态机、恢复、无图建图）；只比前端鲁棒性，HW 的平滑器不差，但算力代价和本项目“降 CPU”的目标冲突。所以本报告的做法是：后端按 z-localization 的思路重写判据，前端保留 Point-LIO 并降载，从 HW 只拿调度纪律、颜色初值和撞击暂停。

结论：

1. 对“无先验、钻洞、高速、轮速 1.669 m/s”，规划内核保留 minco_planner，不换成 omni_minco。定向矩形与独立 yaw、栅格 ESDF、轮速限制、ROS 链和安全契约，omni_minco 一项都没有，补齐它们比把 omni 的数值层移植过来代价大得多。
2. 数值层和验收层 omni_minco 更扎实，而且与场景模型无关（不依赖圆盘），可以按下表逐项移植到 minco_planner。
3. omni_minco 的 500/500 通过是静止起终点的统计，不覆盖滚动重规划。它的 README 自述“起点速度较大且正对近处障碍时，物理上可能刹不住，此时规划器报失败”。高速滚动重规划会遇到这种情形，失败时必须保留已提交轨迹并走 A.5 的安全阶梯，不能放行候选。
4. 要给出“哪个更好”的实测排名，需要同一批栅格快照上的 A/B，协议见 A.22.7。在此之前，本节只给维度判断。

## 3. 正向设计：目标架构

设计原则：

1. 避障只依赖实时感知，在 odom 系闭环；全局先验（PGM/PCD/拓扑）只用于“去哪里”（全局引导、重定位），不进入障碍层。
2. 规划是连续滚动时域，不是一次性任务；“地图变化”是常态输入，不是失效事件。
3. 失效分级：轨迹在制动距离外受威胁 -> 重规划；制动距离内受威胁 -> 制动轨迹；输入不健康 -> 零速。急停只留给第三类。
4. 规划与控制共享同一时间参数化轨迹（多项式及其导数），MPC 跨换轨连续热启动。

```text
              ┌──────── map 系（仅引导）────────┐
 先验 PGM/拓扑 ─> 全局引导 A*/JPS(粗,1Hz) ─> 引导路径 ─┐

            │ Trajectory（多项式系数 + 时间基准 + generation）
            v

            v
```

与 `AGENTS.md` 稳定边界的关系：JPS、MINCO S3、独立 yaw、footprint gate、Local Collision Repair、`ats_swerve_mpc` 全部保留，只改输入语义与触发方式。三条契约变更（2026-10-22 用户已确认方向，见第 0.1 节）：

## 4. 钻洞专项设计

已知约束：2027 规则要求 0.571 m 面正对隧道（`docs/代码框架设计/导航定位与轨迹链路.md`）；MuJoCo footprint 为 `0.571×0.581`，实车配置为方形 `0.58×0.58`。设隧道宽 $W$、净高 $H$，车宽 $w=0.571$，车高 $h$。

0. 雷达覆盖：雷达在车头边缘中点内 0.05 m、前倾 30°（2.1.8），过洞时两侧墙对称可见，前方墙面低处和行进方向地面看得清楚；后方低处是盲区，倒出隧道时只能依赖 odom 累积层。
1. 感知：按 2.2 节公式做地面相对列分类，新增 `TUNNEL_FREE` 语义（顶板高于 $h+m_{\mathrm{top}}$，侧墙为 occupied），顶板不写入 2D 障碍层。terrain_ext 的 `max(maxZ-minZ)` 判据在隧道区内必须让位于列语义，否则顶板会被当成台阶。
2. 检测：两路证据取合取，滞回进出：
   - 列语义连续出现 `TUNNEL_FREE`；
   - sentry_nav_26 式双侧 ESDF 探测（预瞄 1.2 s，阈值按 $\tfrac{W-w}{2}+$ 余量设置）。
   轴线估计改为滑动窗口内两侧墙点的主方向（PCA/直线拟合），不用中线处相互抵消的 ESDF 梯度（`tunnel_yaw_alignment.cpp:37-154` 当前是从段起点的累积圆均值）。
3. 规划：隧道段固定 $\psi = \psi_{\mathrm{axis}}$ 或 $\psi_{\mathrm{axis}} + \pi$（用户 10-23 更正：$+x$ 车头正对隧道，车头为 0.571 m 短边，选离当前 yaw 近的一支；现有 `yaw_tunnel_yaw_offset: π/2` 与 footprint x/y 尺寸要按 2.1.8 改），横向约束
   $$|e_{\mathrm{lat}}| \le \frac{W - w}{2} - m_{\mathrm{side}},$$
   用定向矩形 footprint，不再用内切圆 clearance ladder（地板 0.41 m 会直接把 <0.82 m 的隧道判无路）。`joint_center_clearance` 在隧道段关闭或改为指向中线的软项。
4. 预对齐距离由 yaw 动力学决定，而不是固定 `pre_align 0.53 m`：
   $$d_{\mathrm{pre}} \ge v\left(\frac{\Delta\psi}{\omega_{\max}} + \frac{\omega_{\max}}{\alpha_{\max}}\right).$$
   取 $\Delta\psi=\tfrac{\pi}{2}$、$\omega_{\max}=\alpha_{\max}=2$，结果约 $1.79\,v$，1.5 m/s 时约 2.7 m。入洞前要么提前 2.7 m 开始转，要么在 prepare 段降速。
5. 执行契约（HW `DESIGN.md §3.3` + rose 历史保持）：
   - prepare：降速并对齐；
   - armed：误差门 $|e_\psi|<\epsilon_\psi$、$|e_{\mathrm{lat}}|<\epsilon_y$ 通过才放行；
   - committed：禁止自旋，恒速，footprint gate 只在“前方确定碰撞”时制动，不因单帧噪声中止；
   - exit：整车离开后才解除。
6. 连续碰撞：隧道段用 Implicit-SVSDF 思路的连续扫掠检查，或至少在隧道段把采样加密到“相邻采样位移 ≤ 余量/2”。

### 5.1 执行顺序（第 6 版：当前无法实车测试，全部先在仿真验证）

前提：现在只能做仿真，所以 MuJoCo 要能跑真实算法链，包括 Point-LIO 和建图。现状不满足：MuJoCo 直接发布真值 `/registered_scan`（odom/world 系）、真值 `/odometry` 和 `odom->gimbal_yaw_odom` TF，不跑 Point-LIO；模型里有 `imu_gyro`/`imu_accel` 传感器但没有发布；雷达是整帧单一状态快照，没有逐点时间（`sim_node.py:406-570`，`models/rmuc_2027_swerve.xml:183, 227-228`）。因此第一步是给 MuJoCo 加“LIO 模式”（附录 A.21），之后所有 SLAM、建图、钻洞的验证都在这个模式下做，并且能直接拿真值算轨迹误差，这是实车 bag 做不到的。

顺序原则（第 5 版的判断仍成立）：

1. 三个目标的阻断项在地图层和规划层，SLAM 优化主要换来 CPU。
2. SLAM 里输出逐位不变的改动先做；改变点云或轨迹的数值优化放到 odom 地图和滚动规划稳定之后，只需重新验收一次。
3. O1 的 odom 系静态层依赖 odom epoch。
4. 无先验模式下 GICP 与 fusion 不参与；方向门与全局恢复放到最后的“有先验”阶段。

MuJoCo 两种模式的分工：`truth` 模式（现状）用来隔离规划、MPC 问题，排除定位误差干扰；`lio` 模式跑真实 Point-LIO 链，每个阶段的最终验收都在 `lio` 模式下做。Gazebo 已有 LIO 链（`gz_livox_bridge`），但曾测到间歇性约 2 s 的 `ros_gz_bridge` 内部滞后，只作交叉复核。

## 附录 A：自包含算法要点

本附录把正文借鉴的参考实现提炼为可直接实施的规则与公式，实施时不需要再打开 `参考/` 目录。数值标“参考值”的取自对应开源项目的默认配置，只作初值，需在本项目实测标定。

### A.1 ROGMap 列语义（取自 navi_minco_bit `projection_layer.cpp`，加入本项目顶板判据）

对每个 XY 列统计：观测次数 `observed_count`、占据体素数 `occupied_count`、最低/最高占据体素 z 索引。分辨率记 $r$。

```text
if observed_count < min_observed:            -> UNKNOWN（观测不足，不是 free）
if occupied_count == 0:                      -> FREE
span = (z_idx_max - z_idx_min) * r
ratio = clamp((occupied_count - 1) * r / span, 0, 1)   # 竖向占据率
if span <= surface_max:                      -> 薄面，可通行（地面/薄板）
if span >= wall_span_min and ratio >= wall_ratio_min:  -> 墙，占据
if tunnel_span_min <= span <= tunnel_span_max and ratio <= tunnel_ratio_max:
                                             -> 空心列（候选隧道），交给顶板判据
else                                         -> 不确定，按占据
```

参考值：`surface_max=0.10`、`wall_span_min=0.20`、`wall_ratio_min=0.80`、`tunnel_span=[0.24,0.40]`、`tunnel_ratio_max=0.55`。

参考实现缺的顶板判据，本项目必须加：取列内（或 3×3 邻域）最低连续占据面为局部地面 $z_g$，列内最低的“悬空”占据为顶板 $z_c$，

$$
\text{TUNNEL\_FREE} \iff z_c - z_g \ge h_{\mathrm{robot}} + m_{\mathrm{top}}
\ \wedge\ \nexists\, z_{\mathrm{obs}} \in (z_g + h_{\mathrm{step}},\ z_g + h_{\mathrm{robot}} + m_{\mathrm{top}}).
$$

所有高度都相对 $z_g$，不用绝对 odom z。这样坡道、台阶和机器人自身的俯仰都不会把顶板误判成障碍或把低洞误判成可通行。只有空隙存在而不比较车高的规则（ZT_2027 `dog_map` 的“列内空隙 >0.15 m 即通行”）会产生假 free，不要用。

### A.2 动静态双层（第 0.2 节的实现规则）

每格状态：`first_hit`、`last_hit`、`hit_time_accum`、`cleared_once`、`layer∈{DYN, STATIC}`。

```text
on hit(cell, t):
    if cell 空: first_hit = t, layer = DYN
    hit_time_accum += min(t - last_hit, frame_dt_max); last_hit = t
    if layer == DYN and hit_time_accum >= T_s(3 s) and not cleared_since(first_hit):
        layer = STATIC
on ray_pass_through(cell, t):          # 视野内本应命中却被穿透
    清除该格（DYN 与 STATIC 同样处理），cleared_once = true
on tick(t):
    DYN 且不在视野内: if t - last_hit > T_hold(约 3 s): 置 UNKNOWN（不是 FREE）
    DYN 且在视野内: 不按时间清除，只靠射线穿透清除
save_map(): 只写 STATIC 且 cleared_once == false 且观测占比高于阈值的格
```

对照：navi_minco_bit 用纯时间衰减（最后一次命中后 `keep_time=0.5 s` 仍占据，`clear_time=1.2 s` 强制变 free），开销低，但被遮挡的墙会被清成 free，不满足本项目高速需求。

移动障碍：同一帧 DYN 格做欧氏聚类，簇质心用最近邻或匈牙利匹配关联上一帧，常速度 Kalman 估计速度；速度超过阈值的簇沿速度方向前向膨胀 $v\cdot t_{\mathrm{pred}}$（$t_{\mathrm{pred}}$ 取规划周期加 MPC 预测一半）。

### A.3 滚动重规划起点与局部目标（取自 sentry_nav_26，按 SUPER 时间语义收紧）

```text
t_now = 当前时间；t_ref = min(t_now - traj.start + plan_lead, traj.duration)
if 正在执行 and |traj.p(t_ref) - p_measured| < deviation_max:
    start = (traj.p, traj.v, traj.a, traj.yaw)(t_ref)；新轨迹 t0 = traj.start + t_ref
else:
    start = (p_measured, v_measured, a=0, yaw_measured)
已提交轨迹在 [t_now, t0] 区间保持不变，新轨迹从 t0 拼接
need_replan = 偏差 > deviation_max or 局部目标移动 > 0.3 m or 距上次规划 > refresh_period
```

参考值：`plan_lead=0.15 s`（需覆盖一次规划耗时 p99），`deviation_max=0.5 m`，`refresh_period=1.0 s`，10 Hz。局部目标取全局引导路径前方 2.5 m 弧长处，末速度 = 引导路径切向 × 巡航速度（参考 1.5 m/s，本项目取 MPC 可行域内的值），以消除每个前瞻点的人工刹停。sentry_nav_26 注释记录了改用续接前的实测问题：5.4 m 直线平均有效速度只有 0.27 m/s。

SUPER 的未知空间语义：轨迹分为“已提交段”和“探索段”。已提交段必须全部 known-free；探索段可穿过 unknown，但必须在已提交段内存在一个分叉点，从该点出发有一条完全落在 known-free 内、末速度为 0 的备份制动轨迹。备份轨迹求解失败时不提交新轨迹，继续执行旧轨迹或进入制动。

### A.5 安全阶梯（取自 sentry_nav_26 `safety_monitor`）

### A.7 连续 footprint 检查采样步长（Implicit-SVSDF 的简化替代）

定向矩形半对角线 $\rho=\tfrac12\sqrt{L^2+W^2}$。相邻采样间任一车体点的最大位移满足

$$
\delta \le |v|_{\max}\,\Delta t + |\omega|_{\max}\,\rho\,\Delta t .
$$

要求 $\delta \le m/2$（$m$ 为 footprint 余量）即可保证离散检查不漏角点，因此

$$
\Delta t \le \frac{m}{2\,(|v|_{\max} + |\omega|_{\max}\rho)} .
$$

例：$L=0.581$、$W=0.571$、$\rho\approx0.41$、$v=1.5$、$\omega=2$、$m=0.02$，得 $\Delta t \le 4.3\,\mathrm{ms}$。隧道段应按此加密，或改用解析的扫掠矩形 SDF；开阔段可按更大的余量放宽。

### A.8 隧道轴线估计

取预瞄窗口内左右两侧墙点（ESDF 等值线或 A.1 中隧道两侧的墙列），分别对左右两组点做主方向估计（PCA 第一主轴）。轴向 $\psi_{\mathrm{axis}}$ 取两主轴的平均，用 $\mathrm{atan2}$ 在 $[-\pi,\pi)$ 内求平均，并处理 $\pm\pi$ 等价；宽度取两组点到轴线距离之和的中位数。用滑动窗口，不从段起点累积。中线上左右墙的 ESDF 梯度相互抵消，所以不能用梯度方向估计轴线。

### A.9 全向 MPC：舵轮轮速线性约束与延迟补偿

车体系命令 $u=[v_x, v_y, \omega]$。第 $i$ 个舵轮安装位置 $(x_i, y_i)$，轮速矢量为

$$
\mathbf v_i = \begin{bmatrix} v_x - \omega y_i \\ v_y + \omega x_i \end{bmatrix},\qquad \|\mathbf v_i\| \le v_{w,\max}=1.669\ \mathrm{m/s}.
$$

圆约束用内接正 $K$ 边形线性化（$K=8$ 时保守度 $\cos\tfrac{\pi}{8}\approx0.924$）：

$$
\cos\theta_j\,(v_x - \omega y_i) + \sin\theta_j\,(v_y + \omega x_i) \le v_{w,\max}\cos\tfrac{\pi}{K},\quad \theta_j = \tfrac{2\pi j}{K},\ j=0..K-1 .
$$

每个轮 $K$ 行、4 轮共 $4K$ 行，对 $u$ 线性，可直接进入 QP。只对软约束行加精确罚 slack；求解失败时按各轴最大允许增量向零减速，不直接跳零（参考 holonomic_mpc_ekf 的做法；该项目为 GPL-3.0，只借鉴思路）。

延迟补偿（参考 navi_minco_bit）：

- 求解前把测量状态按控制延迟 $t_d$ 用上一拍已发布命令前推：$\hat x(t+t_d)$；
- 世界系到车体系旋转时，用 $\psi + \omega\,t_d/2$ 代替 $\psi$，补偿执行期间的转动。

更完整的做法是把执行器建模为一阶滞后 $\dot v = (u(t-t_d) - v)/\tau$，作为增广状态加入预测模型，命令历史用环形缓冲保存。

沿迹/横迹权重：位置误差投影到参考切向 $t$、法向 $n$，代价写为 $q_t (e\cdot t)^2 + q_n (e\cdot n)^2$。参考值 $q_t=3$、$q_n=12$，用于抑制高速抄弯。

### A.10 重定位接受门（取自 HWSentryNav26 `odom_localizer`）

GICP 1 Hz、单线程。以下条件全部满足才接受：

- 归一化误差 ≤ 0.3；
- 重叠率 ≥ 0.8；
- 信息矩阵（Hessian）最小特征值 ≥ 1e3；
- 条件数 ≤ 1e6。

后两条用于拒绝长走廊、隧道内沿轴向不可观测的退化匹配。接受后，与当前估计的跳变超过 0.2 m 或 0.1 rad 不直接采用，先连续确认；采用时用 EMA（系数 0.6）平滑。初始锁定参考 navi_minco_bit：粗配准（0.5 m 下采样）后做精配准（0.2 m），连续 3 个窗口结果的中位数一致才锁定。

第 4 版调整：整帧门只保留给“需要完整位姿”的场合（初始化、SUSPECT/LOST 恢复）；正常跟踪改用 A.13 的方向门，避免隧道里横向与 yaw 的有效约束被整帧拒掉。门限数值不能直接搬：HW 的归一化误差与本项目 `registration_error`（small_gicp 目标值 / 内点数，实车门 5.0）都是 GICP 目标值除以内点数，但协方差估计方式和体素不同，0.3 这个值要用本项目 bag 的分布重新定。最小特征值门同理，它与点数和体素尺度相关，换算前不要启用固定 1e3。

### A.11 定位降载（Batch-LIO 思路）

Point-LIO 对每个点做一次 EKF 更新。Batch-LIO 把 1 ms 时间窗内的点合并为一次 EKF 更新（`batch_dt=0` 时退化为原逐点更新，结果逐位一致）；批量化后残差计算可以多线程并行。其 README 自述单帧计算最多降低 4.7×（未复现）。移植时只改更新调度，不改状态定义和观测模型，并以 `batch_dt=0` 与现有 `point_lio` 输出逐位比对作为第一道回归。

### A.12 弧长速度剖面（取自 HWSentryNav26）

几何定型后，以 $w(s)=v(s)^2$ 为决策变量，约束为

$$
0 \le w(s) \le v_{\max}(s)^2,\qquad
\left|\frac{w_{k+1}-w_k}{2\Delta s}\right| \le a_{\max},\qquad
\kappa(s)\,w(s) \le a_{\mathrm{lat,max}} .
$$

这些约束都是线性的，可用 LP/QP 求解。$v_{\max}(s)$ 在隧道段取 COMMITTED 恒速，在窄道和大曲率处取更低值。求出 $w(s)$ 后由 $\Delta t_k = 2\Delta s/(\sqrt{w_k}+\sqrt{w_{k+1}})$ 反推时间分配，作为 MINCO 的初始时间。

### A.13 配准方向门与信息加权更新（取自 z-localization 后端，改写为 fusion 内实现）

目的：隧道、长走廊里只接受可观方向的修正，不可观方向沿用 LIO 相对运动。z-localization 在 GTSAM 图里做 6 自由度；本项目规划与 MPC 只用 SE2，LIO 已重力对齐，因此 fusion 只修正 $(x, y, \psi)$，$z$、roll、pitch 保持 LIO 值。

输入：GICP 最终 Hessian $H$（small_gicp 李代数顺序为 $[r; t]$，现有 `registrationCovariance` 已用置换表 `{3,4,5,0,1,2}` 转成 $[t; r]$，新代码沿用同一置换），残差尺度 $s = \mathrm{clip}\big(2\,\mathrm{error}/(3N_{\mathrm{in}}-6),\,10^{-6},\,10^{3}\big)$（与现有代码同式）。观测信息 $\Lambda_6 = H/s$。

1. 边缘化到平面三自由度，记 $a=\{x,y,\psi\}$，$b=\{z,\mathrm{roll},\mathrm{pitch}\}$：
   $$\Lambda = \Lambda_{aa} - \Lambda_{ab}\,\Lambda_{bb}^{+}\,\Lambda_{ba}.$$
2. 平移/旋转 Schur 补，记 $T=\{x,y\}$、$R=\{\psi\}$：
   $$S_T = \Lambda_{TT} - \Lambda_{TR}\Lambda_{RR}^{+}\Lambda_{RT},\qquad S_R = \Lambda_{RR} - \Lambda_{RT}\Lambda_{TT}^{+}\Lambda_{TR}.$$
   $S_T$ 是“消去 yaw 不确定性之后，平移还剩多少信息”。对 $S_T$ 做特征分解得 $\lambda_1 \le \lambda_2$ 与特征向量 $u_1, u_2$。
3. 弱方向判定（z-localization `analyzeBlock`）：块内相对强度 $\lambda_i/\lambda_{\max} < 1/\kappa$ 判弱，$\kappa=10$（参考值）。$S_R$ 是标量，与平移块的最大值比较判弱。特征值小于 $-8\epsilon\lVert\Lambda\rVert$ 视为实质不定，整条观测作废。数值计算前按块各向同性缩放，不要逐轴归一化（逐轴归一会把噪声主导轴放大成强轴）。
4. 去掉弱方向：令 $U_s$ 为强方向基（平移块强特征向量与 yaw 轴拼成，最多 3 列），
   $$\Lambda_{\mathrm{used}} = U_s\,(U_s^{\top}\Lambda U_s)\,U_s^{\top}.$$
   秩 $r = \mathrm{cols}(U_s)$。$r=0$ 视为“本拍无观测”，不计冲突。
5. NIS 门（只在强子空间内）：fusion 状态 $\hat x=(x,y,\psi)_{\mathrm{map\to odom}}$，协方差 $P$；观测 $z$ 为现有逻辑算出的候选 map->odom，新息 $\nu = z \ominus \hat x$（yaw 取 $[-\pi,\pi)$ 包角）。
   $$S = U_s^{\top} P U_s + (U_s^{\top}\Lambda U_s)^{-1},\qquad d^2 = (U_s^{\top}\nu)^{\top} S^{-1} (U_s^{\top}\nu).$$
   上尾概率 $1-F_{\chi^2_r}(d^2) < 10^{-3}$ 判冲突，即 $d^2$ 超过 10.83（$r=1$）、13.82（$r=2$）、16.27（$r=3$）。
6. 信息形式更新（$\Lambda_{\mathrm{used}}$ 奇异也成立，弱方向增益自动为 0）：
   $$P^{+} = \big(P^{-1} + \Lambda_{\mathrm{used}}\big)^{-1},\qquad \hat x^{+} = \hat x \oplus P^{+}\Lambda_{\mathrm{used}}\,\nu .$$
7. 预测：两次观测之间 $P \leftarrow P + Q$，$Q$ 按时间和里程累加。参考值（z-localization `graph.odom_noise`）：平移 $5\times10^{-4}\,\mathrm{m^2/s} + 2\times10^{-4}\,\mathrm{m^2/m}$，旋转 $10^{-6}\,\mathrm{rad^2/s} + 3\times10^{-7}\,\mathrm{rad^2/rad}$。

保留现有外层硬门：`max_correction_translation 2.0`、`max_correction_yaw 1.0`、LOST 放宽值和 epoch 推进阈值。初始化与恢复仍要求 $r=3$ 且通过 A.10 的完整位姿门。

标定：small_gicp Hessian 的尺度未做实车统计。用 bag 统计接受观测的 $d^2$，均值应接近 $r$；明显偏离时整体缩放 $\Lambda \leftarrow \Lambda / c$，再定门限。

消息变更：`RelocalizationObservation` 增加 `float64[9] information_xy_yaw`（已除以 $s$，行主序 $x,y,\psi$）、`uint8 observable_rank`、`uint8 weak_mask`（bit0 x、bit1 y、bit2 yaw，按强方向基投影后标注最接近的轴，仅用于诊断）。

### A.15 跟踪期调度与局部子图（z-localization `tracking` + HWSentryNav26 `odom_localizer`）

### A.16 Scan Context 全局恢复（z-localization `descriptor` 与 `build_pcd_map_bundle`）

描述子：

- 用 LIO 的 roll/pitch 把点云调平（不调平时雷达倾斜会改变高度分布，同一位置描述子差异很大）；体素 0.6 m 降采样。
- 以雷达为中心划分 $N_r=30$ 环 × $N_s=90$ 扇区，最大半径 $R$（z-loc 80 m；RMUC 场地约 28×15 m，取 20–30 m 即可），每格取最高点相对雷达安装高度的高度；格内点数 ≥1 才有效。
- 距离：对列平移 $k$ 取
  $$d(A,B) = \min_k \frac{1}{N_s}\sum_{j}\Big(1 - \frac{a_j\cdot b_{j+k}}{\lVert a_j\rVert\,\lVert b_{j+k}\rVert}\Big),$$
  最优 $k$ 给出 yaw 初值 $\psi_0 = 2\pi k/N_s$。全场约 200 个描述子，直接遍历，不需要 KD 树。

地图描述子包（离线）：在场地范围内按 1.5 m 网格，从先验 PCD 模拟雷达在安装高度处的局部扫描（扫描体素 0.4 m）生成描述子；每个网格点再做横向 ±2 m 平移增强（共 3 个）。作者经验是精修后的地图按网格重新生成，比建图时直接保存的描述子质量好。

恢复流程：

1. 候选范围：RELOCALIZING 取最后可信位置 30 m 内，LOST 取全场；
2. 取描述子距离 <0.8 的前 15 个候选；没有可信 yaw 时每个候选再加 6 个均匀 yaw 假设；
3. 候选并行做局部子图 GICP（A.15 的子图），只接受 $r=3$ 且通过 A.10 完整位姿门、水平覆盖扇区 ≥6 的结果；
4. 最优与次优组合评分差小于阈值时判歧义、保持当前状态（沿用现有 `ambiguity.*` 参数）；
5. 连续 2 次一致（沿用 `confirmation_count 2`）才写入 fusion 作为新锚点。

开局初值（HW）：读裁判系统己方颜色，按红/蓝方出发区给初始 map->odom，作为第一次配准初值。RMUC 场地中心对称，描述子可能混淆镜像位置，颜色先验和最后可信区域是主要的消歧手段。

### A.17 空间自适应采样与时间窗口（ZLIO `sampling.cpp:268-289`、`design.md` 2.6）

空间自适应（用于 Point-LIO 预处理，替代固定 `point_filter_num 8` + `filter_size_surf 0.05`）：

$$
\rho = \min\!\Big(\frac{\bar r}{r_0},\,1\Big),\qquad
N^{*} = N_{\min} + (N_{\max}-N_{\min})\big(1-(1-\rho)^{2}\big),
$$

其中 $\bar r$ 为最近 5 次观测代表点距中位数的平滑值，$r_0=30$ m，$N_{\min}=1000$，$N_{\max}=4000$。采样体素 $\ell$ 用 PD 控制：

$$
e_k = N^{*}-N_k,\qquad
\ell_{k+1} = \mathrm{clip}\!\Big(\ell_k - K_{p}\,e_k - K_{d}\,\frac{e_k-e_{k-1}}{\Delta t_k},\ 0.02,\ 1.0\Big),
$$

$K_p \in [10^{-6}, 10^{-4}]$、$K_d \in [10^{-9}, 10^{-7}]$，在区间内按 $\sqrt{\rho\cdot\min(|e|/(0.1N^{*}),1)}$（微分项用 $|\dot e|\Delta t/(0.2N^{*})$）插值。Point-LIO 每点一次更新，$N_k$ 基本直接决定 CPU；洞内 $\bar r$ 小，$N^*$ 趋近 1000，体素自动缩小保住点数。`point_filter_num` 降到 1–2 只做原始抽稀。

时间自适应（可选，用于方案 A 的批量窗口或方案 B 自带）：记机体系线加速度与角加速度为 $\kappa$，按匹配点数平均的点面信息矩阵为 $\bar\Lambda$，

$$
e^2(\Delta t) \simeq \frac{\Delta t^4}{4}\,\kappa^{\top}\bar\Lambda\kappa,\qquad
\Delta t_{\mathrm{next}} = \mathrm{clip}\!\Big(\Big(\frac{4\varepsilon^2}{\kappa^{\top}\bar\Lambda\kappa}\Big)^{1/4},\ \Delta t_{\min},\ \Delta t_{\max}\Big).
$$

ZLIO 取 $\varepsilon=2$、$[\Delta t_{\min},\Delta t_{\max}]=[0.03, 0.12]$ s；本轮更新无效或分母为零时取上限。Batch-LIO 的批量窗口是 1 ms 量级，数量级不同，若引入需单独标定上下限，先在固定批量版本稳定后再做。

### A.18 odom epoch 与前端重置（z-localization `localization_interfaces`）

- 前端维护 `instance_id`（进程启动时随机）与 `epoch`（重置计数），`/localization/status` 增加 `odom_epoch`，所有 odom 系消费者都读它。
- epoch +1 的时机：前端重启、重新初始化、冷重置。暖重置（保留速度、倾角、零偏，位置与航向归零）返回 `old_from_new`，即新 odom 坐标到旧 odom 坐标的刚体变换。
- 下游规则：
  - ROGMap 与 odom 系 2D 静态/动态层（O1）：有 `old_from_new` 时按 2D 刚体变换搬移静态层；没有时清空为 unknown。规划器作废已提交轨迹，MPC 输出零速直到新地图就绪。
  - fusion：有 `old_from_new` 时 $T_{\mathrm{map\to odom'}} = T_{\mathrm{map\to odom}}\,T_{\mathrm{old\_from\_new}}$，保持可信；没有时进入 LOST 走 A.16 恢复。
- 重置只在 LOST 时由 fusion 发起，两次之间至少 10 s（z-loc `reset.min_gap`）；请求带请求者 id 与事务号，前端对同一事务去重，重试不重复执行。
- 发散判据（触发 LOST）：LIO 速度超过 2 倍硬件上限、状态出现 NaN、相邻 IMU 间隔 >0.1 s 或时间回退、有效点面匹配数持续低于下限。

### A.19 撞击暂停（HWSentryNav26 `small_glim`）

- IMU 任一轴接近饱和（$|a| > 0.95\,a_{\mathrm{satu}}$ 或 $|\omega| > 0.95\,\omega_{\mathrm{satu}}$，现有 `satu_acc 6.0`、`satu_gyro 35.0`）的帧，状态仍按 Point-LIO 原有饱和处理更新，但不插入 iVox 局部地图，之后 0.5 s 内暂停插图。
- HW 还有“新帧延迟 0.5 s 再插图，用优化后的位姿”。它依赖固定滞后平滑器会回头修正位姿；Point-LIO 是滤波器，延迟插图拿不到更好的位姿，不采纳。
- 适用场景：钻洞剐蹭、被弹丸或车辆撞击。参数默认关闭，用撞击 bag 验证局部地图不出现重影后再打开。

### A.20 Point-LIO 精简的回归方法

Point-LIO 主循环单线程、无随机数，同一输入在同一二进制上输出确定，可以用“逐位一致”做删除类改动的回归。

1. 输入 bag：当前用 MuJoCo `lio` 模式（附录 A.21）录 `/clock`、`/livox/lidar`、`/livox/imu`、`/simulation/ground_truth/odometry`，场景覆盖静止启动、开阔区高速、钻洞、原地自旋、急加减速；有实车条件后再补实车 bag。现有 `~/ats_stageA/*` 是 truth 模式 MuJoCo bag，不含这些话题，不能用。
2. 回放方式：`ros2 bag play --rate 0.5` 并开 `use_sim_time`，降低回放速率，避免因 CPU 抖动丢帧导致非确定。旧、新二进制各跑一遍，录 `/aft_mapped_to_init` 与 `/cloud_registered`。
3. 判据：
   - P2 死代码删除、P1 内存项、P0 第 1 项（改为帧末发布）：帧末位姿逐位一致（第 1 项比较的是帧末那一条）。
   - P0 第 2 项（平面拟合改法方程）：位置差 <1e-4 m、姿态差 <1e-4 rad，累计轨迹终点差 <1 cm。
   - P0 第 3 项（体素与排序）、第 5 项（状态降维）：输入点集或滤波器结构改变，不要求一致；比较起终点闭合误差、与改动前轨迹的 RMS 偏差、洞内是否发散，并记录每帧处理耗时分布（节点内计时，p50/p99）。
4. CPU 记录：每一步都用同一 bag、同一回放速率记录 `pidstat -u -r -p <pid> 1` 的均值与峰值，写进报告第 6 节基线表，按“改动 -> 增量”列出。
5. 提交粒度：死代码删除、参数改动、每个 P0 优化各自单独提交，便于二分定位回归。

### A.21 MuJoCo LIO 模式（仿真跑真实定位链）

现状（`已验证`，读源码）：

- `_lidar_process_main`（`sim_node.py:406-570`）每帧取一次仿真状态，一次性追踪全部射线，发布 `/local_pointcloud`（雷达系）和 `/registered_scan`（world/odom 系），没有逐点时间；时间戳取节点时钟 `now()`，不是仿真时刻。
- `_publish_truth`（`sim_node.py:2502-2605`）以 `truth_rate_hz`（默认 10 Hz）发布真值 `/odometry` 与 `odom->gimbal_yaw_odom` TF。
- 模型有 `imu_gyro`、`imu_accel`（`imu_site` 挂在 `base_link`，`rmuc_2027_swerve.xml:183, 227-228`），但节点不发布 IMU。
- 默认 `lidar_downsample 24`、`lidar_rate_hz 10`：每帧约 1000 条射线，是实车 Mid360（约 20 万点/s）的 1/20。
- MuJoCo 不发布 `/clock`；仿真循环按墙钟节拍 `sleep`（`sim_node.py:2184-2210`）。
- 雷达挂在 `base_link` 下（无云台关节），与 2.1.8 的新硬件结构一致；但安装位姿仍是旧云台值（相对 `base_link` 的 $(-0.100, 0.245, 0.325)$，rpy $(75°, 0, -161°)$，`rmuc_2027_swerve.xml:104-112`、`sim_node.py:108-115`），光心离地约 0.5 m，超出 0.242 m 包络，S0 要按 2.1.8 改并参数化。

设计：

| 项 | 做法 | 要点 |
| --- | --- | --- |
| 模式开关 | launch 参数 `localization_source:=truth\|lio`；`truth` 行为与现在逐位一致 | `lio` 模式关闭仿真的 `/registered_scan`、`/odometry`、`odom->gimbal_yaw_odom` TF（`publish_robot_base_tf:=false`），改由 point_lio -> loam_interface -> sensor_scan_generation 提供；`gimbal_yaw_odom->front_mid360` 静态 TF 全栈只允许一个发布者 |

### A.22 omni_minco 可借鉴的算法要点（取自用户的 `参考/minco_sandbox/omni_minco`，2026-10-29）

出处：`omni_minco/src/minco_problem.cpp`、`validator.cpp`、`planner.cpp`、`sampler.cpp`、`include/omni_minco/time_mapping.hpp`、`types.hpp`，以及 `参考/minco_sandbox/docs/MINCO_Backend_Design_Omnidirectional (1).md` 的 §5.5、§6、§7、§10.4、§11、§12 和附录 C。只读源码，未编译、未运行。下列阈值是 omni_minco 在“圆盘 + 解析场景 + 速度上限 2 m/s”下的默认值，移植到 minco_planner 时只当起点，必须在本项目快照上重新整定。

**A.22.1 代价形态、时间映射与权重**

变量为内部路径点 $q_i$ 和 $\tau_i$，分段时长 $T_i=t_{\min}+e^{\tau_i}$，并限制 $\tau_i\ge\ln(0.5\,t_{\min})$，即 $T_i\ge1.5\,t_{\min}$。原因（附录 C.2 第 4 项）：$dT/d\tau=e^{\tau}$ 在 $\tau\to-\infty$ 时趋于 0，塌缩的分段梯度为零，L-BFGS 会在不可行点“收敛”。线搜索另设步长上界使 $\tau\le\ln(t_{\max}-t_{\min})$，保证 $e^{\tau}$ 有限。

平滑 L1（$C^1$，超过 $\mu$ 后线性）：

$$
\ell_\mu(x)=\begin{cases}0,& x<0\\[2pt] \left(\mu-\tfrac12 x\right)\left(x/\mu\right)^3,&0\le x\le\mu\\[2pt] x-\tfrac12\mu,& x>\mu\end{cases}
$$

无量纲违规量，其中 $v_m=0.97\,v_{\max}$，$a_m=0.97\,a_{\max}$，$d_{req}$ 为机器人半径 + 净空 + 0.02 m，$d_*=0.1$ m，$\mu=0.01$：

$$
g_v=\frac{\lvert v\rvert^2}{v_m^2}-1,\qquad g_a=\frac{\lvert a\rvert^2}{a_m^2}-1,\qquad g_o=\frac{d_{req}-D}{d_*}
$$

沿第 $i$ 段取 $K+1$ 个等分点 $s_j=u_jT_i$，$u_j=j/K$，梯形权重 $c_j$（端点 1/2，其余 1），总代价

$$
J=\frac{w_T}{T_*}\sum_i T_i+\frac{w_J\,T_*^5}{L_*^2}E_{\mathrm{jerk}}+\frac{1}{T_*}\sum_i\frac{T_i}{K}\sum_j c_j\Big[w_v\,\ell_\mu(g_v)+w_a\,\ell_\mu(g_a)+w_o\,\ell_\mu(g_o)\Big]
$$

$T_*$、$L_*$ 是种子轨迹的总时长和总长度。默认 $w_T=1$、$w_J=5\times10^{-5}$、$w_v=w_a=10^3$、$w_o=10^4$、$K=30$、段数 5–40。每次重试把三个惩罚权重统一乘 $10^k$。

时间梯度的直接部分必须同时含积分长度项和采样时刻随 $T_i$ 平移的项（$\ell_p,\ell_v,\ell_a$ 为被积项对 $p,v,a$ 的偏导）：

$$
\frac{\partial}{\partial T_i}\!\left[\frac{T_i}{K}\sum_j c_j\ell_j\right]=\frac1K\sum_j c_j\Big[\ell_j+u_jT_i\big(\ell_p\!\cdot\! v+\ell_v\!\cdot\! a+\ell_a\!\cdot\! \mathrm{jerk}\big)\Big]
$$

另有经 MINCO 系数传播的部分。这一项在 `minco_joint_optimizer.cpp` 中已有同构实现，移植时的检查点是中心差分测试。

权重定标（附录 C.2 第 7 项）：静止到静止的最小 jerk 曲线有 $E=720L^2/T^5$，时间项与 jerk 项的平衡点满足

$$
\left(\frac{T}{T_*}\right)^6=\frac{3600\,w_J}{w_T}
$$

$w_J=5\times10^{-5}$ 时右边为 0.18，时间项占主导，速度与加速度约束起作用，峰值落在限制的 0.94 倍附近（omni 自述）；$w_J=5\times10^{-3}$ 时平衡点是 $1.6T_*$，沿路径只跑到约 0.55 $v_{\max}$。minco_planner 当前的能量权重 1、时间权重 20 在源码里未见这样的定标推导 [推断，Confidence: Medium]，换成无量纲形式后需要重新整定。

**A.22.2 速度/加速度的精确峰值**

每段 $p(s)=\sum_{k=0}^{5}c_ks^k$，$s\in[0,T_i]$。$v=p'$ 是 4 次，$a=p''$ 是 3 次，所以

$$
\frac{d}{ds}\lvert v\rvert^2=2\,v\cdot a\ \ (7\text{ 次}),\qquad \frac{d}{ds}\lvert a\rvert^2=2\,a\cdot\mathrm{jerk}\ \ (5\text{ 次})
$$

用 companion 矩阵特征值求根，保留落在 $[0,T_i]$ 内的实根（虚部小于容差），连同两个端点逐点取 $\lvert v\rvert$、$\lvert a\rvert$ 的最大值。另在每段 200 个均匀点上取采样峰值做交叉检查：求根得到的峰值不应低于采样峰值，否则判为求根错误。判据 $\text{peak}\le\text{limit}\,(1+10^{-6})$，limit 取请求里的真实限制，不是优化器内部收紧后的值。

**A.22.3 碰撞的 Lipschitz 二分证书**

记 $c(t)$ 为 $t$ 时刻的净空（距离场值减去机器人所需距离）。若 $\lvert \dot c\rvert\le V$，区间 $[t_l,t_r]$ 内

$$
\min_{t\in[t_l,t_r]}c(t)\ \ge\ \min\big(c(t_l),c(t_r)\big)-\frac{V\,(t_r-t_l)}{2}
$$

算法：栈初值为 $[0,T_i]$。取出区间，若下界 $\ge-\text{tol}$（$\text{tol}=10^{-6}$ m）则该区间通过；若某端点净空 $<-\text{tol}$ 则判碰撞；否则在 $t_r-t_l>\Delta t_{\min}=10^{-3}$ s 时二分入栈，区间已小于 $\Delta t_{\min}$ 仍无法认证则“认证失败”，`require_certificate=true` 时按失败处理。因此最小可认证净空约为 $V\Delta t_{\min}/2$（$V=1.5$ m/s 时 0.75 mm）。结点总数上限 $2\times10^{6}$。报告 `clearance_lower_bound`（所有区间下界的最小值），它比“已评估点上的最小净空”更保守，`min_clearance` 只用于展示（附录 C.2 第 12 项）。

适配本项目（omni 未实现，推断，Confidence: Medium）：定向矩形上取角点与边中点各自的速度界 $V_k=\max\lvert v\rvert+\max\lvert\omega\rvert\,r_k$，$r_k$ 为该点到车体参考点的距离，对每个点分别做上述二分，取最小下界。这与 A.7 是同一个不等式，区别是 A.7 用固定步长，这里按净空自适应：开阔段一次通过，隧道段（净空约等于余量 $m$）自动细化到约 $m/(V_k)$ 量级。ESDF 是栅格双线性插值，梯度范数不严格等于 1，$V_k$ 要留插值误差余量 [Confidence: Low]，具体系数需在快照上实测。

**A.22.4 其他验收项（阈值为 omni 默认值）**

- 边界：起终点位置、速度、加速度与请求之差分别 $\le10^{-6}$ m、m/s、m/s²。
- 连续：相邻段位置、速度、加速度连续，容差 $10^{-6}(1+\lvert\text{value}\rvert)$。
- 结构：每段 $T_i\ge0.05$ s，段数 $\le4096$，总时长 $\le10^{5}$ s，所有系数有限。
- 请求入口先检查边界状态本身可行（起终点速度 $\le v_{\max}$、加速度 $\le a_{\max}$、起终点净空 $\ge d_{req}$），不可行就直接拒绝，不静默修改输入（设计文档 9.4）。
- 起终点位置重合：速度加速度全为零则输出 1 s 停留轨迹并走同一验收；否则拒绝，要求先给制动或返回计划，不把“停住”伪装成可执行轨迹。

**A.22.5 重试阶梯与状态分离**

1. 优化器内部用收紧的限制：速度、加速度 $\times0.97$（`limit_margin`），净空 $+0.02$ m（`obstacle_pad`）；验收始终用请求里的真实限制。原因：罚函数在边界附近允许很小的越界，留余量让这种越界不触发验收失败。
2. 第 $k=0,1,2,3$ 次尝试：惩罚权重 $\times10^{k}$，每段求积点 $K+10k$，从上一次的解热启动；求解数值失败（`NUMERICAL_FAILURE`）时从种子重来，初始时长乘 $(1.5+k)$。
3. 每次尝试先按下游实际收到的形式导出（序列化再反序列化），再对导出结果做 A.22.2–A.22.4 的验收。`success = 验收通过 ∧ 求解状态可接受`；默认只接受 `CONVERGED`，放宽后通过验收的 `MAX_ITERATIONS`/`LINE_SEARCH_FAILED` 标 `quality=feasible_unconverged`。
4. 求解状态（`CONVERGED`、`MAX_ITERATIONS`、`LINE_SEARCH_FAILED`、`TIMEOUT`、`CANCELLED`、`NUMERICAL_FAILURE`）和可行性状态（通过、速度超限、加速度超限、碰撞、边界不符、格式错误等）分开输出；`attempts[]` 记录每次的权重倍率、求积点数、迭代数、峰值速度/加速度、最小净空。`success=false` 时轨迹只用于诊断。
5. 每次尝试前检查剩余预算（调用方给定的截止时间减去已用时间，steady_clock）与取消标志；剩余预算同时传给 L-BFGS 的进度回调，回调里轮询取消和截止。目标函数抛异常时回调返回 $10^{30}$ 与零梯度，让线搜索回退，不让异常穿出求解器。
6. 整条均匀时间放慢 $c_k\leftarrow c_k/\lambda^{k}$ 只在起终点 $v=a=0$、场景静态、且失败类别只有速度/加速度峰值时作为最后一步：$\lambda=1.002\max\{1,\ v_{peak}/v_{\max},\ \sqrt{a_{peak}/a_{\max}}\}$，放慢后整条重新验收。非零边界速度或场景会变时不适用（设计文档 §12），滚动重规划不能用它。
7. 结果记录场景指纹，`validFor(scene)` 要求当前指纹一致，对应本项目的快照 generation 校验。

本项目适配（推断）：omni 的 4 次尝试、最多 1500 次迭代、中位数 83–411 ms 是离线设置，O2 要求 p95 <30 ms，所以第一次尝试热启动自上一条已提交轨迹（A.3），只允许再多一次加权重的重试，仍失败就保留已提交轨迹并走 A.5 的安全阶梯。重试阶梯取代现有叠加的 5–8 次 `optimize`，不在其上再加一层。

**A.22.6 参考采样与轨迹消息**

- 按物理时间 $t$ 找到所在段后直接求 $p,v,a$，MPC 预测时刻逐点调用；$t$ 早于起点、晚于 $t_0+\sum T_i$ 或晚于 `valid_until` 都返回失败，不外推五次多项式。仅当 `terminal_stop` 为真（末端 $v=a=0$）时在末点保持，且不越过 `valid_until`。
- 世界系参考转车体系：$v_B=R(\psi)^\top v$，$\dot v_B=R(\psi)^\top a-\omega\,J\,R(\psi)^\top v$，$J=\begin{bmatrix}0&-1\\1&0\end{bmatrix}$（标准推导）。2.4 中“前馈来自位姿差分”的问题用解析 $v,a$ 加这一式修正。
- 消息字段（设计文档 §10.4 的建议，非现成 ROS 标准）：`header`、`schema_version`、`session_id`、`trajectory_id`、`request_id`、`goal_version`、`execution_epoch`、`map_snapshot_id`、`constraint_version`、`start_time`、`valid_until`、`polynomial_order`（5）、`terminal_stop`、`durations[N]`、`coefficients_x/y/yaw[6N]`。每段系数按 $c_5,\dots,c_0$ 降幂排列，时间基是每段局部秒数，不能把 Unix 时间代入多项式。本项目取其子集：`trajectory_id`、`map_snapshot_id`（对应 MINCO local snapshot generation）、`start_time`、`valid_until`、`execution_epoch`、`terminal_stop`、`durations`、系数。`minco_s3.hpp` 内部系数排布与此是否一致未核对，转换时显式处理。
- 切换规则（§11，omni 只有设计、未实现）：切换时刻 $t_s=t_r+\Delta_{lead}$，新轨迹起点继承旧参考在 $t_s$ 的 PVA，不混用旧位置、实测速度和零加速度；active/pending 两条轨迹各自不可变，截止时间用 steady_clock。与 A.3 一致，不重复展开。
