# P2/P3 运行期故障注入与恢复闭环验证记录

## 范围与结论

本记录只覆盖 `planning_grid_owner:=rog_map` 的 P2/P3 运行期安全故障注入。
每个用例使用新的 `ROS_DOMAIN_ID` 和新的无 viewer MuJoCo launch；没有在一次
launch 中串行注入多个故障。

**已验证**：P2 的 adapter lease、projection service timeout、Point-LIO-compatible
input stale、all unknown、free-but-unreachable 共 5 例，均到达预期健康状态后触发
`/planner/emergency_stop=true`，并在 `/cmd_vel_mpc` 与 `/motion_control` 观测到全零
输出。三个可恢复的输入/服务/adapter 用例恢复后，`/rog_map_adapter/generation`
继续递增，未提交新目标时两路输出保持为零。

**已验证**：P3 cancel、preempt、timeout、TF failure 共 4 例均返回预期 action 结果，
然后进入急停和双零输出。`capture_zero_outputs` 在急停后先等待 `0.5 s`，再持续采样
每个输出 topic 最多 `3 s`；其覆盖 MPC `execution_command_timeout=0.5 s` 和 MuJoCo
`command_timeout=0.5 s` 的一个 watchdog 周期以上。没有在采样窗内观察到旧 command
自行恢复。

**未声明**：这不是 P2 总体验收、红框验收或 P3/Nav2-free 最终验收。仅运行了
`TEST_PROFILE=default`；未运行红框，也未验证扩大矩形。虽在本次 P3 launch 中运行时
确认了 ATS action 存在、Nav2 节点和 `/plan` 不存在，但该单项不能替代 P3 的全部门禁。

## 基础链与所有权证据

domain `213` 的 default 名义路线到终点误差为 `0.011433 m`，
`footprint_collisions=0`，telemetry 的 `contact_violation_count=0`。
此处没有独立 physical contact evaluator；因此只报告该 telemetry 字段，**不**推导
MuJoCo 物理碰撞为零。

每个 fault launch 在注入前均确认：

- `/rog_map/occ`、`/rog_map/inf_occ`、`/rog_map/unk`、`/rog_map/esdf` 非空；
- ROGMap 输入新鲜，adapter 使用 `/rog_map/get_ground_projection` 数值服务，未订阅
  `/rog_map/esdf`；
- `/rc_esdf/planning_grid` 仅由 `ats_rog_map_adapter` 发布，`rc_esdf_map` 未启动；
- `/cmd_vel_mpc` 与 `/motion_control` 的运行期命令流由脚本持续采样；
- P3 launch 中 `/ats_goal_manager` 和 `/ats_navigate_to_pose` 存在，同时无
  `bt_navigator`、`planner_server`、`controller_server`、`behavior_server` 与 `/plan`。

## 残余风险与下一门禁

- [Confidence: High] 本记录的 fault-to-stop 结论由脚本状态断言与运行期 action/命令流
  两类证据共同支持；其范围仅限当前 revision、default 路线和 MuJoCo。
- [Confidence: Medium] `manager_incarnation` 的 Goal Manager 到 MPC 传播在运行链存在，
  但本轮未重新审查 serial 的 producer/consumer，因此不将其升级为端到端 serial 契约。
- 未运行红框、扩大矩形和真实硬件；不得从本记录得出实车性能、物理零碰撞或 P3 总体验收。
- 后续应在新的 domain 中执行红框，并保留结构化跨 topic 原子安全契约作为后续加固项。
