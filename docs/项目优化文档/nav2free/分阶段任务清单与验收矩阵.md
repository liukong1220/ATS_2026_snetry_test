# 分阶段任务清单与验收矩阵

## 1. 使用方法

本清单是后续实施的唯一任务入口。每一阶段必须按以下顺序执行：

```text
检查分仓状态和基线
-> 读取目标 owner 完整作用域
-> 最窄修改
-> 包级构建/单测
-> launch/graph 检查
-> 独立 domain MuJoCo 故障注入
-> 更新证据文档
-> 分仓 staged diff 检查
-> 中文分内容提交与普通 push
```

状态含义：

- `[ ]` 未开始；
- `[~]` 已实现但验证未闭合；
- `[x]` 已完成且有本清单要求的证据。

截至 2026-07-31，本轮只完成静态审查与计划文档生成，所有源码阶段保持未开始。

## 2. 总体门禁

| 门禁 | 进入实车前要求 |
| --- | --- |
| 唯一 owner | planning grid、TF、execution、`/cmd_vel`、`/motion_control` 均唯一 |
| stale fail-stop | map、localization、gimbal、execution 任一 lease 失效均确定性零速度 |
| identity | goal、candidate、execution、serial gate 可区分进程重启 incarnation |
| map atomicity | geometry、occupancy、ESDF、gradient、source generation、publication 同一消息 |
| planning atomicity | candidate reference、failure/yaw/status、snapshot generation 同一消息 |
| execution atomicity | reference、authorization、identity、generation 同一 `ExecutionCommand` |
| Nav2 removal | graph、manifest、launch、YAML、RViz、测试无活动 Nav2 依赖 |
| config authority | 正式实机只加载 `node_params.yaml` |
| velocity frame | fake/chassis compatibility 与 Nav2 解耦并默认启用；固定雷达 profile 才关闭 |
| closed loop | default + red_box + fault cases 使用 ATS action 分别启动新 MuJoCo |
| real calibration | 外参、轮径、减速比、舵零位、执行器/延迟/误差预算实测闭合 |

## 11. 阶段 P8：仿真闭环与故障注入

每个 case 使用新 `ROS_DOMAIN_ID` 和新 MuJoCo launch，不在一次仿真串行污染机器人状态。

### 名义路线

- [ ] default ATS action 到达。
- [ ] red_box ATS action 到达。
- [ ] 记录终点坐标、位置/yaw 误差、terminal velocity/dwell。
- [ ] 记录 raw path 点数、reference 点数、MINCO footprint collision samples。
- [ ] 记录 MPC solve p99、saturation、`/cmd_vel`、`/motion_control` ownership。
- [ ] 记录 contact evaluator；无独立 evaluator 时写“物理接触未验证”。

### 独立故障

- [ ] adapter ready heartbeat 中断。
- [ ] projection service `SIGSTOP` 无响应和迟到恢复。
- [ ] Point-LIO `/registered_scan` stale。
- [ ] localization stale、DEGRADED/LOST、epoch change、single-frame jump。
- [ ] gimbal joint/TF stale、request/ack mismatch。
- [ ] planning grid 全 unknown、真实 unknown cell、unreachable goal。
- [ ] unsafe trajectory 专用注入。
- [ ] Goal Manager restart、MPC restart、serial bridge restart。
- [ ] execution command reorder、旧 transient-local sample、旧 reference resurrection。

每项必须观察：

```text
health/ready false
-> ExecutionCommand STOP
-> cmd_vel = 0
-> motion_control = 0
-> four-wheel 0 rpm
```

恢复后没有新 goal 时不得自动恢复运动。

## 15. 全局停止条件

出现任一情况立即停止进入下一阶段：

- 同一接口有两个活动 owner；
- 新旧 YAML 同时生效；
- graph 仍有 Nav2 但文档已标 Nav2-free；
- stale/unsafe/failure 后任一底盘级仍非零；
- 修改后的源码尚未重跑对应闭环，却沿用修改前 MuJoCo 结果；
- RViz/debug 成为 planner 数值输入；
- 实车数据未测量却引用参考项目性能；
- 用户修改与目标文件重叠且无法安全合并；
- 任一分仓不在 `develop` 或 push 需要 force。
