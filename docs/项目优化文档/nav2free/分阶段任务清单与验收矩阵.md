# 自研导航分阶段任务清单与验收矩阵

更新时间：2026-08-02。

## 1. 使用方法

每个源码阶段必须闭环执行：

```text
三/多仓 status + HEAD
-> rg 定位 owner/symbol/topic
-> 读取完整 producer/consumer/launch/test
-> 最窄修改
-> 构建/单测
-> launch/graph/effective param
-> 独立 domain MuJoCo
-> 文档
-> 显式 staged diff
-> 中文提交与普通 push
```

状态：`[x]` 表示源码或文档能力已完成并有对应静态/测试证据；`[~]` 表示部分接通
但门禁未闭合；`[ ]` 表示未开始。本目录不采用其它历史目录中的状态或结果。

## 3. 总体门禁

| 门禁 | 最终要求 |
| --- | --- |
| 目标入口 | 只存在 `/ats_navigate_to_pose` 或 Goal Manager 管理的 `/goal_pose` |
| Nav2 removal | graph、manifest、launch、YAML、RViz、behavior、测试无活动 Nav2 依赖 |
| config authority | 正式 profile 只加载 `node_params.yaml` |
| map owner | `/rc_esdf/planning_grid` 固定由 adapter 唯一发布 |
| map atomicity | geometry、occupancy、SDF、gradient、source/publication identity 同一 snapshot |
| planning atomicity | candidate reference、status、failure、yaw、snapshot identity 同一消息 |
| execution atomicity | authorization、reference、identity、incarnation、lease 同一 command |
| frame | 世界系 state `[x,y,yaw]`，车体系 command `[vx,vy,wz]`，保留 `vy` |
| velocity chain | fake/chassis 与 Nav2 无关；实机默认启用，固定雷达 profile 才关闭 |
| fail-stop | map/localization/gimbal/reference/command stale 或 failure -> 双零/四轮零 |
| closed loop | rectangle + red_box + 独立 fault cases 使用 ATS action 和新 MuJoCo |
| real robot | 外参、轮径、减速比、舵零位、执行器、延迟、制动和接触实测闭合 |

本阶段只运行并在失败时修复现有故障注入门禁，不进行 Nav2 清理或总 YAML 重构。

1. P2 按新的 domain 与新 launch 依次运行 `adapter_lease`、`service_timeout`、
   `input_stale`、`unknown`、`unreachable`。
2. P3 按新的 domain 与新 launch 依次运行 `cancel`、`preempt`、`timeout`、
   `tf_failure`。
3. 每例必须在配置 deadline/lease 内证明 `emergency_stop=true`、`/cmd_vel_mpc=0`、
   `/motion_control=0`；恢复后必须证明 generation 前进且旧 reference/command 不复活。
4. 任一用例失败时，仅修改其实际 owner 并补最窄回归；不以 topic 存在、启动成功或
   单次局部运动替代闭环。
5. 全部通过后，才新增 Goal Manager/MPC/serial 的真实进程重启注入；该项仍须确认
   serial gate 是否已消费 `ExecutionCommand` 再决定 schema 范围。
