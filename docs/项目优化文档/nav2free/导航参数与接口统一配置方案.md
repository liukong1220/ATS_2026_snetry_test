# 导航参数与接口统一配置方案

## 1. 决策

正式实机 profile 继续使用现有文件：

```text
src/ats_sentry_bringup/params/node_params.yaml
```

不新增 `ats_nav2_free.yaml` 作为第二权威。用户以后仍在原参数文件中直接修改、添加和删除节点参数。

统一后的 `node_params.yaml` 覆盖：

- 串口、雷达、Point-LIO、定位融合、TF 和地形分析；
- ROGMap 核心地图参数和 ROS wrapper 参数；
- ROGMap ground adapter、RC-ESDF 规划接口；
- Goal Manager、JPS/MINCO、footprint/repair、SE2 MPC；
- fake-yaw 与 chassis velocity compatibility 的 frame/topic 参数；
- behavior、telemetry、RViz/debug 开关；
- topic、frame、timeout、QoS 和唯一所有权选择。

`.msg/.srv/.action` 继续是字段、常量和类型 schema 的唯一权威。YAML 不复制接口字段定义，只保存节点如何连接这些接口。

## 2. 单一权威规则

1. 正式实机 launch 只向所有节点传递同一个 `node_params.yaml`。
2. package 私有 YAML 可在迁移期间作为输入清单，迁移完成后不得再被正式入口加载。
3. launch 只允许覆盖两类运行上下文：`use_sim_time` 和地图/PCD/设备文件路径；几何、动力学、阈值、topic、frame、timeout 不在 launch 覆盖。
4. MuJoCo 若必须使用不同物理参数，应有单独仿真总配置并明确不是实机权威；不得由多个 package 私有 YAML 拼装。
5. `planning_grid_owner` 不允许运行时热切换。彻底移除 Nav2 后正式值固定为 `rog_map`，可删除该选择参数。
6. 同一 topic 在 producer 和 consumer 节点段中可能重复出现，因为 ROS 2 参数不能跨节点引用；CI 必须校验重复值一致。
7. 禁止依赖 YAML anchor/alias 作为运行契约，避免 `rcl_yaml_param_parser` 与自定义 yaml-cpp loader 行为差异。

## 3. 当前配置来源与迁移目标

| 当前文件 | 内容 | 目标动作 |
| --- | --- | --- |
| `ats_sentry_bringup/params/node_params.yaml` | 实机总参数 + 大量 Nav2 段 | 保留路径，删除 Nav2，作为唯一总文件 |
| `ats_nav_bringup/config/reality/nav2_params.yaml` | 定位/地形/Nav2/RC-ESDF 重复参数 | 非 Nav2 段迁入后删除 |
| `ats_nav_bringup/config/simulation/nav2_params.yaml` | 仿真混合参数 | 自研仿真总配置迁移完成后删除 |
| `ats_rog_map/config/rog_map_ground_planning_mujoco.yaml` | ROGMap 自定义 YAML | 参数源改为 ROS 参数后删除正式加载 |
| `ats_rog_map_adapter/config/rog_map_ground_planning.yaml` | adapter 参数 | 合入 `ats_rog_map_adapter` 段 |
| `minco_planner/config/minco_planner_reality.yaml` | 实机 JPS/MINCO 参数 | 合入 `minco_planner` 段 |

迁移必须采用“镜像、对比、切换、删除”四步，不能一边加载旧文件一边修改新文件后直接宣称单一权威。

## 4. ROGMap 特殊迁移

ROGMap 当前由 `AtsRogMapNode` 读取 `map_config_file`，再由自定义 loader 解析根键 `rog_map`。这阻碍真正的单 YAML。

目标改造：

1. 在 `AtsRogMapNode` 中声明完整的 `rog_map.*` ROS 参数；
2. 为 `rog_map::Config` 增加从显式参数结构构造的入口，不通过临时文件；
3. `map_config_file` 仅保留一个版本作为迁移 fallback，正式 profile 设为空并在启动时拒绝“双来源同时启用”；
4. 单测比较旧 YAML 和新 ROS 参数构造出的 Config，要求每个字段完全一致；
5. 切换后删除正式 launch 对 `rog_map_ground_planning_mujoco.yaml` 的引用。

建议参数名保持原层级语义：

```yaml
ats_rog_map:

    map_frame: odom
    base_frame: gimbal_yaw_odom
    sensor_frame: front_mid360
    odom_topic: /localization
    cloud_topic: /registered_scan
    cloud_timeout_sec: 0.5
    odom_timeout_sec: 0.5
    tf_timeout_sec: 0.1
    debug_rate_hz: 2.0
    esdf_visualization_height: 0.15
    self_filter_radius: 0.45
    input_qos_reliable: false
    debug_qos_reliable: false
    rog_map.esdf.enable: true
    rog_map.esdf.resolution: 0.10
    rog_map.esdf.local_update_box: [8.0, 8.0, 1.0]
    rog_map.esdf.update_interval_updates: 1
    rog_map.map_sliding.enable: true
    rog_map.map_sliding.threshold: 1.0
    rog_map.fix_map_origin: [0.0, 0.0, 0.5]
    rog_map.resolution: 0.10
    rog_map.inflation_resolution: 0.10
    rog_map.inflation_step: 2
    rog_map.unk_inflation_en: false
    rog_map.map_size: [10.0, 10.0, 1.0]
```

## 6. 接口账本

### 6.1 核心 topic/action/service

| 接口 | 类型 | producer | consumer | QoS/语义 | stale/fallback |
| --- | --- | --- | --- | --- | --- |
| `/localization` | `nav_msgs/Odometry` | localization fusion/Point-LIO profile owner | ROGMap、Goal Manager、MINCO 首端状态、MPC | sensor data；stamp 为观测时间 | 超时/跳变 -> revoke execution、零速度 |
| `/localization/status` | `LocalizationStatus` | localization fusion | adapter、Goal Manager、MPC | reliable；带 epoch | 非 TRACKING/lease 超时 -> stop |
| `/registered_scan` | `PointCloud2` | Point-LIO | ROGMap | best effort sensor stream | stale -> ROGMap stale -> adapter false |
| `/rog_map/get_ground_projection` | `GetRogMapProjection` | ROGMap | adapter | service；steady deadline；迟到 response 按 epoch 丢弃 | timeout 清 pending，允许重试 |
| `/planning/map_snapshot` | 目标 `PlanningMapSnapshot` | adapter | MINCO、Goal Manager health | reliable，建议 transient local depth 1 | ready=false 或 lease 超时 -> stop |
| `/ats_navigate_to_pose` | ATS action | Goal Manager | behavior/RViz/test | feedback/result/cancel/preempt/timeout | reject/failure -> STOP |
| `/ats_goal_manager/planner_goal` | `PlannerGoal` | Goal Manager | MINCO | reliable depth 10；含 identity/incarnation | stale identity 丢弃 |
| `/minco/planner_candidate` | 目标 `PlannerCandidate` | MINCO | Goal Manager | reliable depth 1；reference 与 status 原子 | mismatch/unsafe -> STOP |
| `/planner/execution_command` | `ExecutionCommand` | Goal Manager | MPC、serial gate | reliable + transient local depth 1；授权与 reference 原子 | lease/sequence/incarnation 失败 -> STOP |
| MPC 中间速度 topic | 显式记录的 command frame | MPC | fake-yaw compatibility | topic 去 Nav2 命名；实机默认启用 | stale -> 0 |
| fake-yaw 中间 topic | `gimbal_yaw_odom` 兼容语义 | fake-yaw transform | chassis transform | 唯一 producer/consumer | 缺 TF -> 0，不得丢帧保持旧速度 |
| `/cmd_vel` 或目标授权速度包 | body `[vx,vy,wz]` | chassis transform | serial/MuJoCo 唯一桥 | 当前 Twist；目标与授权同样本 | watchdog -> 0 + stop=true |
| `/motion_control` | `MotionCtrl` | MuJoCo bridge | MuJoCo chassis | reliable depth 10 | bridge stale -> 0 |

### 6.2 frame 契约

| 数据 | frame | 规则 |
| --- | --- | --- |
| 全局目标 | `map` | Goal Manager 变换到 `odom` planning frame |
| planning grid/snapshot | `odom` | origin 包含 yaw；所有数组同一 geometry |
| ROGMap sensor | `front_mid360` | TF 必须在观测时间可用且新鲜 |
| 机器人规划 footprint | `gimbal_yaw_odom` | 0.70 m x 0.55 m + margin，带 yaw |
| MPC state/reference | 世界系 `odom` | `[x,y,yaw]` |
| MPC/底盘 command | 车体系 | `[vx,vy,wz]`，保留 `vy` |

实机主入口默认 `launch_fake_vel_transform=true`、`launch_chassis_vel_transform=true`。两者必须与 Nav2 开关解耦；fake-yaw 关闭时保留 `gimbal_yaw_odom -> gimbal_yaw_fake` 零旋转 TF。固定雷达迁移只能由显式 profile 关闭兼容层。

### 6.3 generation 契约

| 名称 | 产生者 | 当前载体 | 目标 |
| --- | --- | --- | --- |
| ROG source generation | ROGMap | projection service response | 与 occupancy/ESDF/gradient 同一 snapshot |
| adapter publication sequence | adapter | 独立 status topic | 与 planning grid 同一 `PlanningMapSnapshot` |
| MINCO local snapshot generation | MINCO | 本地计数 + PlannerStatus | 与 candidate reference 同一 `PlannerCandidate` |
| localization epoch | fusion | status/goal/command | 全链严格匹配 |
| authority incarnation | Goal Manager | 当前缺失 | goal/status/command/serial gate 全链携带 |

## 7. 参数约束必须机器校验

新增 `scripts/validate_navigation_config.py`，使用结构化 YAML parser 校验：

1. 必需节点段存在，Nav2 禁止段不存在；
2. producer/consumer topic、frame 和 timeout 成对一致；
3. `dt = 1 / control_rate_hz`；
4. `T_hold < T_cmd_watchdog <= T_execution_lease`；
5. MPC/adapter/MINCO footprint length、width、margin 一致；
6. ROG resolution、planning resolution 和 ESDF resolution 的组合合法；
7. `unknown_is_obstacle=true`，`publish_unsafe_trajectory=false`；
8. 实机 `use_sim_time=false`、`require_localization_status=true`、`require_gimbal_status=true`；
9. `/rc_esdf/planning_grid`、`/cmd_vel`、`/motion_control` 只有一个配置 owner；
10. 所有 topic 使用统一的绝对/相对命名规则。
11. 实机两个速度兼容层默认启用，且 `base_footprint -> base_link` 不会出现第二个 TF owner。

## 8. 配置迁移验收

### U0：生成参数清单

对每个活动节点运行 `ros2 param dump`，与旧 YAML、源码默认值形成三方表。数值不一致时以“正式 launch 实际加载值”为当前基线，不凭文件名猜测权威。

### U1：镜像到总 YAML

只添加段，不切 launch。运行 validator 并人工审核 diff。

### U2：单节点切换

顺序：adapter -> ROGMap -> MINCO -> Goal Manager -> MPC -> serial -> behavior。每切一个节点都运行包级单测和 param dump 对比。

### U3：正式入口只加载总 YAML

验证 launch 实际传参列表，禁止 package 私有 YAML 同时生效。

### U4：删除重复配置

`rg` 确认同名正式节点段只在 `node_params.yaml` 出现；包内可保留的独立示例必须改名为 `example` 并明确不被正式 launch 使用。

## 9. 停止条件

- ROGMap 新参数构造与旧配置字段不完全一致；
- launch 同时传入总 YAML 和 package 私有 YAML；
- validator 发现 topic/frame/footprint/timeout 冲突；
- 参数切换后 `ros2 param dump` 与目标总 YAML 不一致；
- 仿真通过依赖 launch 临时覆盖一个未记录的安全参数；
- 正式配置中 `require_*_status` 被受控 HIL 之外的 profile 关闭。
