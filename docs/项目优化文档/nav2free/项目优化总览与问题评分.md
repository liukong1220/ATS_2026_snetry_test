# 自研导航一体化问题总览与评分

更新时间：2026-08-01。

本评分只反映活动源码的当前状态。分数高表示阻塞自研主链或实车准入，不表示某个
问题已经在运行中复现；运行结论必须另有当前 revision 的测试或闭环证据。

## 1. 结论

ATS 自研链的主体已经存在：ATS `NavigateToPose`、Goal Manager、ROGMap 数值投影、
planning grid、JPS、MINCO S3、独立 yaw、footprint gate、Local Collision Repair、
`ExecutionCommand` 和全向 SE2 MPC 均有活动源码。专用实机入口和 action-only MuJoCo
脚本也已建立。

但活动仓库仍不是纯自研架构：通用 launch、MuJoCo/loopback、行为插件、manifest、
`node_params.yaml`、RViz 资产和 `trajectory_optimizer` 仍保留 Nav2 运行或构建依赖；
自研核心的参数和结构化 snapshot 仍未完全单一化。因此当前结论是：

> `自研链已形成，仓库级 Nav2 清理和参数/版本原子化未完成。`

## 2. 评分模型

$$
R = S_{30} + C_{25} + H_{20} + B_{15} + T_{10}
$$

- $S$：运动安全影响；$C$：接口/状态正确性；$H$：实车准入阻塞；
  $B$：影响范围；$T$：测试缺口。

| 等级 | 分数 | 处理规则 |
| --- | ---: | --- |
| S0 | 90-100 | 阻塞通电运动或任何实车声明 |
| S1 | 75-89 | 阻塞架构收敛或主链发布 |
| S2 | 55-74 | 阶段内必须修复 |
| S3 | 30-54 | 工程治理、诊断和文档整改 |
| 建议 | 0-29 | 按收益安排 |

### 3.1 已确认的源码锚点

- N01/N06：`ats_sentry_bringup/launch/bringup.launch.py`、
  `ats_nav_bringup/launch/navigation_launch.py`、MuJoCo launch 仍包含
  `nav2_common`、`launch_nav2` 和 Nav2 server 条件。
- N02：`node_params.yaml` 仍有 `bt_navigator`、costmap、planner/controller 等段；
  `behavior_params_file` 默认指向 `sentry_behavior.yaml`；ROGMap wrapper 仍有
  `map_config_file` 兼容路径。
- N03：`GetRogMapProjection.srv` 已将 grid/SDF/gradient/generation 放在同一 response，
  但 adapter publication、planning grid 和 status 仍分 topic；当前没有
  `PlanningMapSnapshot.msg`。
- N04/N09：`PlannerGoal.msg`、`ExecutionCommand.msg` 的注释和字段显示 sequence/goal
  仍是进程内或分域语义，未携带 authority incarnation/content digest。
- N05：`minco_planner` include/link `trajectory_optimizer` 的 RC-ESDF provider 和
  static map fusion；删除前必须迁移公共算法。
- N07：正式 `sentry_behavior.yaml` 使用 `/ats_navigate_to_pose`，但 `nav2_msgs` 和
  `send_nav2_goal`/`send_nav_through_poses` 仍在 build/source/test。
- N11：`ats_rog_map_node.cpp` 已有 `/rog_map/bounds` MarkerArray；RViz 仍保留部分旧
  costmap/MPPI 资产，四色 bounds 尚未实现。

## 4. 已解决或降级的问题

| 项目 | 当前结论 |
| --- | --- |
| 正式 action endpoint | 正式参数使用 `/ats_navigate_to_pose`，行为层不再在正式 YAML 提供 Nav2 endpoint |
| P3 回归入口 | 回归脚本固定 ATS action，并检查无 Nav2 process、无 `/plan` 和 owner 唯一 |
| 速度兼容开关 | fake-yaw/chassis transform 已从 `launch_nav2` 隐式绑定中解耦，实机专用入口默认 true |
| ROGMap RViz 基础层 | occ、inf_occ、unk、esdf 和 `/rog_map/bounds` 已有显示配置 |
| 服务端重启测试 | 行为侧新增旧 incarnation 不得污染新路径的聚焦测试 |

这些项目仍需在全仓清理后的新 revision 重新运行，不能用历史结果替代最终门禁。

## 5. 优先级

1. S0：N01/N02/N03/N04/N12/N13，先固定运行入口、参数权威、snapshot 和实车安全边界。
2. S1：N05-N10，先迁移 RC-ESDF 和行为/仿真依赖，再删除 Nav2 构建资源。
3. S3：N11/N14，在运行图和数值接口稳定后补齐可视化与目标机性能测量。

任何阶段出现 planning grid、TF、`/cmd_vel`、`/motion_control` 多 owner，或 stale 后
底盘非零，都必须停止扩展修改范围。
