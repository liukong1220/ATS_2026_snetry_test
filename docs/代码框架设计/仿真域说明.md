# 仿真域说明

## 活动入口与边界

当前导航验收使用`src/sim/ats_mujoco_sim`的RMUC 2027场景。场景、路线、起点和命令以[2027最终方案](../nav_acceptance/20261116_2027_final_test_plan.md)为准；RMUL 3V3、旧2025/2026、红框和Gazebo不替代本套件。

MuJoCo提供物理、传感器及独立真值；LIO验收由Point-LIO和地图匹配提供导航位姿。truth输入只用于隔离诊断，不替代LIO导航通过。Gazebo当前未启用，旧入口待同步，见[Gazebo兼容边界](Gazebo与当前导航接口.md)。

## 构建与运行

在工作区根目录，按资源预算选择并发；窄构建示例：

```bash
MAKEFLAGS=-j1 colcon build --base-paths src --packages-select ats_mujoco_sim \
  --symlink-install --parallel-workers 1 --cmake-args -DCMAKE_BUILD_TYPE=Release
```

运行前核验账本和宿主占用，选择新domain及新证据目录，加载工作区WLAN配置。按最终方案分别执行`rmuc_2027_tunnels`的`tunnel_b_roundtrip`、`ramp_south`、`six_tunnels`和`SCENE=rmuc_2027 TEST_PROFILE=single`对称点速度。兼容runner默认仍为2025，不能直接沿用默认起点或默认0.30 m终点门；当前速度用例明确0.08 m。

## 传感器与资源

| 项目 | 当前契约 |
| --- | --- |
| LiDAR | MID360，仿真时间10 Hz、最多200000射线/s即20000射线/帧；返回点数取决于命中 |
| IMU / 物理 | LIO模式200 Hz / 400 Hz；truth物理默认300 Hz |
| 扫描 | LIO每段≤5 ms，保留逐点offset_time；降密度覆盖完整0.1 s图案 |
| 线程 | `lidar_threads=0`按进程可用CPU的1/3，最少1、最多8；仅雷达子进程绑定该预算，BLAS/OMP限制1线程 |
| 点数 | `lidar_downsample=0`自动：1/2–3/≥4线程对应5000/10000/20000射线/帧；显式正整数覆盖 |
| 安装 | `lidar_mount_preset=chassis`；底盘转动带动雷达和原始扫描，配准后的世界系静态环境不随车旋转 |

10 Hz是仿真时间频率；墙钟频率和实时率另报。原20 Hz/12000射线实验不能作为当前性能。LiDAR子进程CPU预算不等于整个导航栈的进程重排已验证。

## 速度、显示和所有权

三套profile使用0.581×0.571 m车体、0.02 m余量、0.249 m车高门。暂定平移5 m/s、yaw 3 rad/s、角加速度2 rad/s²；MINCO起点保护随max_velocity，MuJoCo轮速控制范围为±117.6470588 rad/s（轮半径0.0425 m），不改变力矩范围。5 m/s叠加自旋仍受逐轮限速约束。

RViz默认显示车辆、定位箭头、当前帧`/registered_scan`（Points、Decay Time=0）、传感器轴和TF；ROG体素、局部规划窗口、距离场、路径及安全调试组关闭，可手动打开。配置检查未证明动态显示已现场观察。

```text
Point-LIO/独立定位 -> ROGMap进程内adapter -> PlanningMapSnapshot
 -> JPS/MINCO -> Goal Manager -> MPC /cmd_vel/autonomy_raw
 -> arbiter /cmd_vel/selected -> twist_to_motion_ctrl /motion_control -> MuJoCo
```

每一级唯一发布者、bridge消费者及急停后零输出须核验；不从`footprint_collisions=0`推导物理零接触。`/cmd_vel_mpc`只属于旧证据。
