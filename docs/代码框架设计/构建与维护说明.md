# 构建与维护说明

## 简介

本工作区是 ROS 2 多包工程。活动源码位于 `src`，参考目录不参与构建。

## 模块

根 bringup、导航、行为、MuJoCo、Gazebo、串口和视觉是独立仓库/包域，按改动范围选择包。

## 依赖

ROS 2 Humble、标准 ament 工具链和各包在 `package.xml` 声明的依赖。

## 构建

```bash
source /opt/ros/humble/setup.bash
MAKEFLAGS=-j1 colcon build --base-paths src --symlink-install --parallel-workers 1 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

视觉 ROS 2 条件编译：

```bash
colcon build --base-paths src --packages-select sp_vision25 --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

串口/仿真最窄构建：

```bash
colcon build --base-paths src --packages-select standard_robot_pp_ros2 ats_mujoco_sim --parallel-workers 1 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

最窄构建示例：

```bash
MAKEFLAGS=-j1 colcon build --base-paths src --symlink-install --parallel-workers 1 \
  --packages-select ats_rc_esdf ats_rog_map minco_planner \
  ats_nav_bringup ats_sentry_bringup ats_mujoco_sim --cmake-args -DCMAKE_BUILD_TYPE=Release
```

整仓构建直接使用根目录 `./build.sh`（自动按可用内存与 CPU 核数计算并发并传入 `-DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF`）。验证统一以配置校验（`python3 scripts/validate_navigation_config.py`）和正式 launch / `scripts/s3_mujoco_acceptance.py` 闭环运行为准。单独 CMake 仅用于诊断局部编译，不能替代 colcon 的依赖排序与 ament 安装。

## 启动

先 `source install/setup.bash`，再使用 `ros2 launch`。无界面仿真建议设独立
`ROS_DOMAIN_ID` 和可写 `ROS_LOG_DIR`。

## 接口

构建不改变 ROS 接口权威：`.msg/.srv/.action` 定义 schema，根 `node_params.yaml` 定义节点参数。

## 配置

活动源码仅以 `--base-paths src` 发现。遇到旧生成 symlink 时只清理精确的
`build/<package>` 与 `install/<package>` 产物，建议避免清理 `src` 或用户文件。

## 架构

`colcon` 在工作区层解析 package manifest、构建依赖、安装空间和测试；它是本工程正式构建入口。
