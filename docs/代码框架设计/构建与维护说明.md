# 构建与维护说明

## 简介

本工作区是 ROS 2 多包工程。活动源码位于 `src`，`参考/` 目录不参与构建。

## 构建入口

整仓 Release 构建直接使用根目录 `./build.sh`（自动按可用内存与 CPU 核数计算并发并传入 `--base-paths src -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF`）：

```bash
source /opt/ros/humble/setup.bash
./build.sh
source install/setup.bash
```

窄构建仅编改动包：

```bash
./build.sh --packages-select ats_rog_map minco_planner ats_goal_manager ats_swerve_mpc
```

视觉与串口窄构建示例：

```bash
./build.sh --packages-select standard_robot_pp_ros2 sp_vision25
```

## 验证规范

本项目已移除包内测试目录与 `scripts/test_*` 脚本，严禁新建、恢复或运行 `test/`、`gtest`、`pytest`、`colcon test` 或 `scripts/test_*`。标准验证链为：

1. `./build.sh --packages-select <targets>`（Release 构建）；
2. `python3 scripts/validate_navigation_config.py`（单源参数、唯一 `OSQP SQP-RTI` 与 `lidar_mount_mode` 契约校验）；
3. `python3 -m py_compile <changed_python_or_launch>` 与 `ros2 launch ... --show-args`；
4. 各改动仓库运行 `git diff --check`；
5. 隔离 `ROS_DOMAIN_ID` 下运行 `scripts/s3_mujoco_acceptance.py` 无窗口 2027 闭环与 `scripts/evaluate_lio_frontend_ab.py` 离线评测。

## 维护边界

- 遇到旧生成产物时仅清理精确的 `build/<package>` 与 `install/<package>`，不清理 `src`、第三方依赖或用户保留文件；
- 改动分别按仓库（根仓、`src/ats_sentry_nav`、`src/sim/ats_mujoco_sim`）显式 stage、中文提交并推送 `origin/develop`，不提交 `log/`。
- 当前验收结论与剩余优化项统一见 [主报告](../调研/无先验地图钻洞高速导航优化调研报告.md) 与 [2027 导航验证方案](../nav_acceptance/20261116_2027_final_test_plan.md)。
