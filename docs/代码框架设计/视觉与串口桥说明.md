# 视觉与串口桥说明

## 简介

视觉/裁判系统提供任务输入，串口与云台链提供下位机速度边界与云台状态；它们不替代定位、地图或导航 owner。**导航架构精简与优化阶段不修改 `sp_vision25`（自瞄）与 `standard_robot_pp_ros2`（串口）。**

## 模块与构建

- `standard_robot_pp_ros2`：底盘、云台和链路的唯一串口 owner；
- `sp_vision25`：ROS 2 模式下通过 `io::GimbalTopicBridge` 访问云台话题，不直接打开 `/dev/tty*`。

```bash
./build.sh --packages-select standard_robot_pp_ros2 sp_vision25
```

## 接口与方案 A 速度链

- 视觉/串口桥接口：`/serial/gimbal_state`（11 元，四元数 `wxyz`）、`/serial/gimbal_cmd`（7 元，rad，100 ms 超时停发）、`/serial/link_up`（50 ms 心跳）、`serial/gimbal_joint_state`。
- MCU 采用方案 A（直接消费底盘系 `[vx, vy, wz]`）：
  - `real_robot_navigation.launch.py` 默认 `lidar_mount_mode:="gimbal"`、`gimbal_use_base_footprint_odom:="True"`、`launch_fake_vel_transform:="False"`、`launch_chassis_vel_transform` 自动联动（`gimbal` 为 `True`、`chassis` 为 `False`）；`base_footprint` 解耦下 `transform_linear_with_big_yaw:=False`，保留 `gimbal_yaw_odom -> gimbal_yaw_fake` 零旋转兼容 TF；
  - 显式设 `gimbal_use_base_footprint_odom:=False` 回退至 `gimbal_yaw_odom` + 大 yaw 前馈延迟补偿；需要旧 `fake_vel_transform` 时显式开启 `launch_fake_vel_transform:=True`。

```text
sp_vision25 (GimbalTopicBridge) <-> /serial/gimbal_state, /serial/gimbal_cmd
standard_robot_pp_ros2 (唯一串口 owner) -> /serial/link_up, serial/gimbal_joint_state
behavior -> Goal Manager -> OSQP MPC (/cmd_vel/autonomy_raw)
 -> [可选 sentry_chassis_vel_transform -> /cmd_vel/autonomy]
 -> cmd_vel_arbiter -> /cmd_vel/selected -> standard_robot_pp_ros2
```

## 验证与限制

`sentry_chassis_vel_transform` 6 工况独立运行时验证（含旋转系自旋加减速搬运 $R(-\omega_z \Delta t)$ 与 `hold_last` 过期保持）已通过；串口 PTY 回环属于历史单测记录。**实车电控波特率/字节帧、双 yaw 云台外参标定、真机急停断连与自瞄-导航联合实车联调均未执行**（纳入主报告 Wave 7 实车首阶段）。
