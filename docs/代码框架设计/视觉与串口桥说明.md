# 视觉与串口桥说明

## 简介

视觉/裁判系统提供任务输入，串口与云台链提供下位机速度边界和云台状态；它们不替代定位、地图或导航 owner。

## 模块

`standard_robot_pp_ros2` 是底盘、云台和链路的唯一串口 owner；`sp_vision25` 在 ROS 2 条件编译模式下使用 `io::GimbalTopicBridge`，通过话题访问云台，不直接打开 `/dev/tty*`。

## 依赖

ROS 2、业务消息接口、串口硬件依赖和底盘协议。

## 构建

```bash
colcon build --base-paths src --packages-select standard_robot_pp_ros2 --symlink-install --parallel-workers 1
colcon build --base-paths src --packages-select sp_vision25 --symlink-install --parallel-workers 1
```

## 启动

根 bringup 负责串口、云台状态、fake-yaw/chassis transform 兼容层与行为输入编排。

## 接口

视觉/串口桥接口为：`/serial/gimbal_state`（11 元状态，四元数 `wxyz`）、`/serial/gimbal_cmd`（7 元命令，角度 rad）和 `/serial/link_up`（50 ms 心跳）。视觉命令超过 100 ms 未更新时停发，mode=2 受串口宿主开火授权门约束。

MPC 输出车体系 `[vx, vy, wz]`。实机通路为
`/cmd_vel/autonomy_raw -> fake_vel_transform -> chassis_vel_transform -> /cmd_vel/autonomy`
`-> cmd_vel_arbiter -> /cmd_vel/selected`；手动 `/cmd_vel` 只作为 arbiter 的另一个输入。下位机负责
其后的 CAN/电机执行，导航不检查这些硬件状态。`serial/gimbal_joint_state` 是云台 yaw、速度坐标变换及
自瞄-导航协调输入，建议保留。

## 配置

串口/transform 参数在根总 YAML；实机默认保留 fake-yaw 与 chassis transform，关闭时建议保持
frame、TF 和速度契约。

## 架构

```text
sp_vision25(ROS 2 GimbalTopicBridge) <-> /serial/gimbal_state,/serial/gimbal_cmd
standard_robot_pp_ros2(唯一串口 owner) -> /serial/link_up,/serial/gimbal_joint_state
vision/referee -> behavior -> Goal Manager -> MPC -> /cmd_vel/autonomy_raw
-> fake/chassis transform -> /cmd_vel/autonomy -> arbiter -> /cmd_vel/selected
```

## 验证与限制

串口 PTY 双向回环已验证 `LINK_UP_TRUE=True`、状态话题、`GIMBAL_CMD_FRAMES=404`、CRC 全部有效以及断开后的 `LINK_UP_AFTER_DISCONNECT=False`；定向 GTest 为 `14/14`、`10/10`、`2/2`。视觉 ROS 2 构建和 CTest 为 `2/2`。实车键鼠到串口、真实电控字节/波特率、云台和固定雷达迁移仍未验证。串口保留 emergency stop、链路失效和 watchdog；自动授权已上移到 arbiter。
