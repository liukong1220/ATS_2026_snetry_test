# 代码范围与目录结构

## 简介

活动源码只在 `src`；根、导航和 MuJoCo 为独立 Git 仓库。

## 模块

- 根仓：`src/ats_sentry_bringup`、根脚本、地图资产和本文档。
- 导航仓：`src/ats_sentry_nav` 的 ROGMap、RC-ESDF、MINCO、Goal Manager、MPC、速度仲裁和 launch。
- MuJoCo 仓：`src/sim/ats_mujoco_sim` 的四舵轮物理、传感器、2027 隧道场景、bridge 和 RViz。
- Gazebo 仓：`src/sim/gazebo_simulator` 的 RMUC 2027 world/model、真值/雷达 bridge、底盘适配器和 RViz。
- 串口仓：`src/standard_robot_pp_ros2`，是底盘、云台和链路的唯一串口读写者。
- 视觉仓：`src/sp_vision25`，ROS 2 条件编译时通过 `GimbalTopicBridge` 使用串口话题，不直接打开云台串口。

## 依赖

依赖通过 ROS package manifest 和 `dependencies.repos` 解析；`参考/` 仅作算法/许可证溯源，不是活动构建输入。

## 构建

使用 `colcon build --base-paths src`，不扫描参考目录。

## 启动

入口由根 bringup、导航 bringup、`rmuc_2027_mujoco.launch.py`、
`rmuc_2027_gazebo.launch.py`、串口 launch 和视觉 ROS 2 可执行文件组成。旧 RMUC 2025/2026 launch 仍作为兼容入口，不能写成 2027 验收证据。

## 接口

跨域接口以 ROS `.msg/.srv/.action` 为准，YAML 仅承载参数。

## 配置

`node_params.yaml` 是正式导航总 YAML；资产、设备与 HIL 开关由 launch 受控覆盖。

## 架构

```text
视觉 ROS 2 topics <-> standard_robot_pp_ros2(唯一串口 owner)
       |                                      |
       +-> behavior/goal -> ROGMap/adapter -> JPS/MINCO/yaw -> SE2 MPC
                                               -> cmd_vel_arbiter
                      MuJoCo: /motion_control   Gazebo: /motion_control + chassis Twist
```

2027 隧道约束为车体 `0.571 x 0.581 m` 中的 `0.571 m` 面正对隧道；yaw 由 ESDF 估计隧道轴线，并在入口前完成对齐。

## 验证与限制

已验证视觉 ROS 2 构建、串口 PTY 双向回环、MuJoCo `tunnel_B` 和导航 yaw CTest；Gazebo 2027 world/SDF/RViz 通过静态/启动检查，但当前 GPU/EGL 环境没有 `/registered_scan`，完整 Gazebo 闭环待修复。物理接触 evaluator、实车/HIL、P3/P4 仍未完成。提交前逐仓检查状态，显式 stage 文件，建议避免 `git add .`/`git add -A`；未知文件属于用户。
