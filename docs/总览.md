## 目标架构

```text
传感器 + 独立状态估计
  -> ROGMap 概率占据 / 膨胀 / 3D ESDF
  -> 地面投影 + static/terrain/slope/unknown 融合
  -> RC-ESDF 数值规划接口
  -> ats_goal_manager
  -> JPS
  -> MINCO S3 + 独立 yaw
  -> footprint safety + Local Collision Repair
  -> 全向 SE2 MPC
  -> 四舵轮底盘
```

模块边界：

- Point-LIO 继续发布 `/localization` 与 `/registered_scan`，ROGMap 不是定位器。
- `ats_rog_map` 是活动 ROGMap 唯一实现；`参考/` 不参与构建。
- 规划消费数值 projection/signed distance，不反解析 `/rog_map/esdf` 可视化点云。
- 状态 `[x,y,yaw]` 在世界系，控制 `[vx,vy,wz]` 在车体系，保留全向 `vy`。
- Goal Manager 拥有目标生命周期、急停心跳和最终 `ExecutionCommand` 提交。
- MPC 与串口出口都拒绝旧授权；单独 `emergency_stop=false` 不恢复运动。

## 当前两条运行链

### 正式目标链/专用 Nav2-free 入口

```text
ats_sentry_behavior
  -> /ats_navigate_to_pose
  -> ats_goal_manager
  -> /ats_goal_manager/planner_goal
  -> minco_planner
  -> /minco/reference_path_candidate + /minco/planning_status
  -> ats_goal_manager 复核 snapshot/heartbeat/gimbal 并统一重定时
  -> /planner/execution_command
  -> ats_swerve_mpc
  -> /cmd_vel
  -> standard_robot_pp_ros2
```

该链由 `real_robot_nav2_free.launch.py` 选择。当前源码限制为不通电检查和抬轮
HIL，不能把“入口存在”写成落地实车验收通过。

### Nav2 对照链

```text
NavigateToPose/NavigateThroughPoses
  -> Nav2 planner/smoother/controller
  -> trajectory speed governor / velocity smoother
  -> fake_vel_transform
  -> chassis_vel_transform
  -> /cmd_vel
```

普通实机、loopback 和 MuJoCo 默认值仍可进入这条链。它用于基线比较，后续按
运行期依赖、行为接口、公共算法、构建依赖和旧资源五阶段移除。

## 地图与 generation 边界

规划地图 owner 只能是：

- `rc_esdf`：启动 `rc_esdf_map`，抑制 ROGMap adapter 输出；
- `rog_map`：启动 adapter，抑制 `rc_esdf_map` 输出。

运行期热切换未实现。必须分别区分：

```text
ROGMap source generation
adapter publication sequence
MINCO local immutable snapshot generation
```

当前 `OccupancyGrid` 不携带 source generation。可证明的上限是单次规划内 JPS、
二维 RC-ESDF、MINCO clearance、footprint gate 和 repair 共用同一 MINCO snapshot；
不能宣称三者编号端到端一致。

## 参数现状与目标

当前实机参数分布：

- `src/ats_sentry_bringup/params/node_params.yaml`：感知、定位、串口、Nav2 对照与兼容链；
- `minco_planner/config/minco_planner_reality.yaml`：规划；
- `ats_goal_manager/config/ats_goal_manager_reality.yaml`：目标/安全提交；
- `ats_swerve_mpc/config/ats_swerve_mpc_reality.yaml`：控制。

目标是以 `node_params.yaml` 为唯一正式实机总 YAML，使原有参数键可直接修改和
移除。迁移顺序必须是“加入并让 launch 加载 -> 校验 effective params -> 删除旧段”，
不能先删分包 YAML。消息字段仍由 `.msg/.srv/.action` 定义，不能复制到 YAML。

## 仿真定位

- MuJoCo：完整动力学、传感器、地图、规划、控制和故障注入的主要环境。
- loopback：快速行为/Nav2 接线回归，不提供物理与 ROGMap 数值证据。
- Gazebo：已从当前主线清理，不再新增入口。

P2 红框脚本使用 `planning_grid_owner:=rog_map` 也只证明自研规划控制链；若仍用
Nav2 `NavigateToPose` 和 `/plan`，不能据此证明 P3。
