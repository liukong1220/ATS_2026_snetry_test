# ATS 2026 哨兵工作区总览

本文档根据当前 `src` 目录中的包、launch、参数、消息和源码整理，不引用旧文档内容。文档范围只覆盖 `src` 下可见代码，不推断未在代码中出现的硬件、网络或赛场配置。

## 当前代码分层

当前 `src` 采用高整合、高划分的功能域结构：

```text
src/
├── ats_robot_description/          # 机器人描述、xacro / SDF 资源、状态发布入口
├── ats_sentry_bringup/             # 根仓保留的总启动入口、实机参数、地图、RViz、调试脚本
├── ats_sentry_behavior/            # 行为树决策、行为树插件、裁判/视觉/导航黑板
├── ats_sentry_nav/                 # 导航、定位、点云、地形、轨迹优化、速度坐标转换
├── interfaces/                     # 自研消息、裁判系统消息、视觉消息、仿真控制消息
├── sim/                            # loopback、MuJoCo、Gazebo 仿真域
├── sp_vision25/                    # 视觉识别、自瞄、视觉到导航融合发布
├── standard_robot_pp_ros2/         # 串口桥、裁判系统解析、云台管理、下位机命令下发
└── tools/                          # PCD 转栅格、rosbag 录制、键盘云台控制等工具
```

核心主链由 `ats_sentry_bringup` 组织。实机主入口读取 `src/ats_sentry_bringup/launch/bringup.launch.py`，并组合串口桥、导航、行为树、RViz 和 rosbag 录制。仿真入口分为 loopback、Gazebo 和 MuJoCo 三类，分别服务不同调试粒度。

## 主链职责

`ats_sentry_bringup` 是部署入口，不是算法仓。它的代码范围包括：

- `launch/bringup.launch.py`：实机总启动。
- `launch/loopback_decision_sim.launch.py`：无物理引擎的决策闭环仿真。
- `launch/loopback_nav_only.launch.py`：纯导航链路观察。
- `launch/loopback_vision_test.launch.py`、`launch/decision_vision_test.launch.py`：视觉接管相关仿真入口。
- `launch/gazebo_bringup.launch.py`：Gazebo + 导航链联调。
- `params/node_params.yaml`：实机主参数，覆盖串口、Livox、Point-LIO、地形、Nav2、轨迹优化、速度链、rosbag。
- `map/*.yaml` 与 `map/*.pgm`：部署地图。
- `pcd/`：PCD 本地目录。`*.pcd` 被忽略，不提交、不上传。
- `scripts/fake_decision_sim_inputs.py`：loopback 中发布模拟裁判、初始位姿和视觉目标。
- `scripts/debug_path_recorder.py`：记录 odom / GT 路径用于 RViz 观察。

## 实机链路

当前实机链路由 launch 和参数共同表达：

```text
ats_sentry_bringup/bringup.launch.py
  -> standard_robot_pp_ros2.launch.py
  -> chassis_vel_transform_node
  -> ats_nav_bringup/rm_navigation_reality_launch.py
  -> ats_sentry_behavior_launch.py
  -> Nav2 / Point-LIO / small_gicp / terrain / trajectory_optimizer
  -> fake_vel_transform
  -> trajectory_speed_governor
  -> velocity_smoother
  -> /cmd_vel
  -> standard_robot_pp_ros2
  -> 下位机
```

主要话题链：

```text
Livox MID360
  -> livox/lidar, livox/imu
  -> point_lio
  -> cloud_registered, aft_mapped_to_init
  -> loam_interface
  -> registered_scan, odometry / lidar_odometry
  -> terrain_analysis
  -> terrain_map
  -> terrain_analysis_ext
  -> terrain_map_ext, traversability_grid, traversability_*_grid
  -> Nav2 costmap / B-spline smoother / trajectory_optimizer
```

速度链：

```text
Nav2 controller_server
  -> cmd_vel_controller
  -> trajectory_speed_governor
  -> cmd_vel_controller_governed
  -> velocity_smoother
  -> cmd_vel_nav2_result
  -> fake_vel_transform
  -> cmd_vel_gimbal_yaw_odom
  -> sentry_chassis_vel_transform
  -> /cmd_vel
  -> standard_robot_pp_ros2
```

行为链：

```text
standard_robot_pp_ros2 发布 referee/*
sp_vision25 发布 vision/target
ats_sentry_behavior_server 订阅 referee/*、vision/target、odom/odometry、global_costmap/costmap
行为树选择巡逻 / 回补 / 视觉跟随 / 姿态模式
行为树发送 /navigate_through_poses 或 /navigate_to_pose
行为树发布 cmd_spin、cmd_gimbal、decision/robot_mode、stop_flag
```

## 仿真链路

`src/sim` 下有三类仿真：

- `src/sim/loopback_sim`：轻量闭环仿真，不依赖物理引擎。`loopback_simulator` 订阅 `cmd_vel` 和 `initialpose`，发布 `odom`、`scan`、TF 和 `/clock`。
- `src/sim/ats_mujoco_sim`：MuJoCo 舵轮底盘仿真，发布里程计、TF、点云、ToF 和 `manda_can_control` 反馈，接收 `MotionCtrl` / `SpeedCtrl` / `SteerCtrl`。
- `src/sim/rmu_gazebo_simulator`：Gazebo 仿真封装，负责 Gazebo 世界、机器人生成、桥接和裁判系统仿真。

仿真域不改变 ROS 包名。路径变为 `src/sim/*` 后，包仍然分别叫 `nav2_loopback_sim`、`ats_mujoco_sim`、`rmu_gazebo_simulator`。
