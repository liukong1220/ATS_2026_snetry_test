# 哨兵项目现状总览

这份文档面向当前维护者，完整说明现在仓库里真实在运行的主线、参数入口、运行命令和代码落点。

## 1. 当前系统分层

当前项目可按五层理解：

1. 启动编排层  
   `src/pb2025_sentry_bringup`
2. 决策层  
   `src/pb2025_sentry_behavior`
3. 导航与定位层  
   `src/pb2025_sentry_nav`
4. 轻量仿真层  
   `src/loopback_sim`
5. 设备与接口层  
   `src/standard_robot_pp_ros2`

### 1.1 每层负责什么

| 包 | 当前职责 | 典型修改内容 |
| --- | --- | --- |
| `pb2025_sentry_bringup` | 实机 / loopback 总入口，串起导航、行为树、RViz、假输入 | 改 launch 参数、改地图入口、改仿真组合 |
| `pb2025_sentry_behavior` | 行为树、姿态切换、视觉接管、路径生成、资源状态机、受击自旋 | 改决策逻辑、改姿态规则、改视觉跟随算法 |
| `pb2025_sentry_nav` | Nav2、MPPI、定位、点云、fake_vel_transform | 改控制器参数、改 frame 链、改底盘速度合成 |
| `loopback_sim` | 无实车条件下的 `/cmd_vel -> /odom/TF/scan/clock` 闭环 | 改 loopback 仿真行为、改仿真 Nav2 参数 |
| `standard_robot_pp_ros2` | 串口、裁判系统、底盘速度与姿态模式下发 | 改上下位机协议、改串口参数、改模式话题 |

## 2. 当前真实主线

### 2.1 实机主线

```text
bringup.launch.py
  -> standard_robot_pp_ros2
  -> pb2025_nav_bringup
  -> pb2025_sentry_behavior
  -> /navigate_through_poses
  -> Nav2 Planner + MPPI
  -> cmd_vel_nav2_result
  -> fake_vel_transform
  -> /cmd_vel
  -> 串口下发到底盘
```

### 2.2 loopback 主线

```text
loopback_decision_sim.launch.py / loopback_vision_test.launch.py
  -> fake_decision_sim_inputs.py
  -> pb2025_sentry_behavior
  -> /navigate_through_poses
  -> Nav2 Planner + MPPI
  -> cmd_vel_nav2_result
  -> fake_vel_transform
  -> /cmd_vel
  -> loopback_simulator
  -> /odom + TF + /scan + /clock
```

## 6. 当前主线中的关键算法

### 6.1 路径执行算法

当前 `SendNavThroughPoses` 不只是简单发 action，还做了三层稳定化：

1. `same_path`
   完全相同的路径不重复重发。
2. `near_active_path`
   近似同路径时，在 `active_goal_hold_tolerance` 和 `active_goal_min_resend_interval_s` 内不抢占。
3. `goal_succeeded` 与当前位姿兜底
   已成功且当前位姿仍在终点附近时，不再反复重发同一路径。

核心参数：

- `decision.decision_config.path_goal_reached_tolerance`
- `decision.decision_config.active_goal_hold_tolerance`
- `decision.decision_config.active_goal_min_resend_interval_s`
- `decision.decision_config.vision_active_goal_hold_tolerance`
- `decision.decision_config.vision_active_goal_min_resend_interval_s`

### 6.2 视觉跟随算法

当前 `SelectVisionFollowPath` 的核心流程是：

1. 读取 `VisionTargetMsg.target_position_map`
2. 将目标点和当前车位统一变换到规划坐标系
3. 基于敌方目标构造攻击圆周
4. 根据当前车位先求圆周上的最近点
5. 结合 costmap 做候选点筛选：
   - 栅格可通行
   - 距离地图边界保留安全余量
   - 从当前车位到候选点的线段尽量可通行
6. 若当前最近点不可用，则回退到更大角域甚至全环候选点
7. 对选中点做角度限幅平滑
8. 若发生重定位或位姿跳变，则清缓存重选

核心参数：

- `decision.vision.attack_radius`
- `decision.vision.follow_occupied_threshold`
- `decision.vision.follow_sample_count`
- `decision.vision.follow_arc_half_angle_deg`
- `decision.vision.min_replan_interval_s`
- `decision.vision.min_goal_shift_m`
- `decision.vision.max_goal_angle_step_deg`
- `decision.vision.pose_jump_reset_distance_m`
- `decision.vision.pose_jump_reset_angle_deg`

### 6.3 视觉接管算法

当前 `IsVisionTargetValid` 的核心逻辑不是“看到就追”，而是带三层平滑：

1. `activation_hold_s`
   初次接管前要稳定一段时间。
2. `switch_target_hold_s`
   已锁定目标 A 时，新目标 B 也要稳定一段时间才能切换。
3. `override_hold_s`
   短时掉帧或遮挡时，继续保持旧目标，避免立刻掉回普通分支。

核心参数：

- `decision.vision.timeout_s`
- `decision.vision.activation_hold_s`
- `decision.vision.switch_target_hold_s`
- `decision.vision.override_hold_s`

### 6.4 资源模式算法

当前 `IsRobotResourceMode` 统一根据：

- `RobotStatus.current_hp`
- `RobotStatus.projectile_allowance_17mm`

带迟滞判断三种状态：

- `engage`
- `resupply`
- `defend`

核心参数：

- `decision.resource_policy.defend_enter_hp`
- `decision.resource_policy.defend_exit_hp`
- `decision.resource_policy.resupply_enter_hp`
- `decision.resource_policy.resupply_exit_hp`
- `decision.resource_policy.resupply_enter_ammo`
- `decision.resource_policy.resupply_exit_ammo`

## 7. 当前最常改的参数与修改目的

### 7.1 姿态与资源

- `decision.mode_limits.switch_cooldown_s`
  控制姿态切换冷却时间。
- `decision.mode_limits.max_cumulative_s`
  控制单局同一姿态允许累计存在的最大时长。
- `decision.resource_policy.defend_enter_hp`
  决定多低血量进入防御姿态。

### 7.2 受击自旋

- `decision.motion.hit_spin_speed`
  控制自旋角速度。
- `decision.motion.hit_spin_stop_after_no_hp_drop_s`
  控制多久没有新掉血就停转。

### 7.3 视觉跟随

- `decision.vision.attack_radius`
  决定跟随半径。
- `decision.vision.min_replan_interval_s`
  控制重规划时间节流。
- `decision.vision.min_goal_shift_m`
  控制目标位移死区。
- `decision.vision.max_goal_angle_step_deg`
  控制圆周点平滑角速度。
- `decision.vision.pose_jump_reset_distance_m`
  控制何时认为发生位姿大跳变。
- `decision.vision.pose_jump_reset_angle_deg`
  控制多大角度变化才真正清缓存。

### 7.4 Nav2 / MPPI

- `general_goal_checker.xy_goal_tolerance`
  控制到点判定。
- `controller_server.FollowPath.*`
  控制 MPPI 采样、critic、速度边界。
- `inflation_radius`
  控制离墙保守程度。

## 8. 当前维护建议

1. 改启动链路，优先看 `pb2025_sentry_bringup`
2. 改姿态切换、视觉接管、退防逻辑，优先看 `pb2025_sentry_behavior`
3. 改 MPPI、goal checker、costmap，优先看 Nav2 参数文件
4. 改下位机模式和速度下发，优先看 `standard_robot_pp_ros2`
5. loopback 与实车共用行为层核心算法，因此调试结论优先先在行为层对齐
