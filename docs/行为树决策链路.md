# 行为树决策链路

本文档根据 `src/ats_sentry_behavior` 代码整理。

## 代码范围

`ats_sentry_behavior` 负责把比赛状态、机器人状态、视觉目标、导航反馈和 costmap 变成导航/云台/底盘模式输出。

目录职责：

- `behavior_trees/`：行为树 XML。
- `params/`：行为树参数。
- `plugins/action/`：行为树动作节点。
- `plugins/condition/`：行为树条件节点。
- `plugins/control/`：控制流节点。
- `plugins/decorator/`：装饰节点。
- `src/ats_sentry_behavior/src/ats_sentry_behavior_server.cpp`：行为树服务端。
- `src/ats_sentry_behavior/src/ats_sentry_behavior_client.cpp`：行为树客户端。

## 启动方式

入口：

```bash
ros2 launch ats_sentry_behavior ats_sentry_behavior_launch.py
```

启动节点：

- `ats_sentry_behavior_server`
- `ats_sentry_behavior_client`

参数文件默认：

- `src/ats_sentry_behavior/params/sentry_behavior.yaml`

loopback 使用：

- `src/ats_sentry_behavior/params/sentry_behavior_loopback.yaml`

视觉专测使用：

- `src/ats_sentry_behavior/params/sentry_behavior_decision_vision_test.yaml`

## 正式执行接口 `SendAtsNavGoal`（P6 二）

正式 RMUC/RMUL 树的导航执行统一走 `SendAtsNavGoal`：

- 服务端：`ats_goal_manager`，action 名 `/ats_navigate_to_pose`，
  类型 `ats_navigation_interfaces/action/NavigateToPose`。
- goal：`geometry_msgs/PoseStamped goal_pose` + `builtin_interfaces/Duration timeout`
  （`timeout <= 0` 表示用服务端默认值）。
- result code 映射：`RESULT_SUCCEEDED=0` 映射 `BT::NodeStatus::SUCCESS`；
  `CANCELED=1`、`PREEMPTED=2`、`TIMEOUT=3`、`MAP_UNREADY=4`、`PLANNING_FAILED=5`、
  `TF_FAILED=6`、`INTERNAL_ERROR=7` 全部映射 `FAILURE`，并把 `message` 写入日志。
- feedback：`STATE_ACCEPTED=0` 到 `STATE_STOPPED=5`。
- halt/cancel：节点重写 `halt()`，在返回 IDLE 前主动 `cancelGoal()`；
  `cancelGoal()` 可能抛 `rclcpp_action::exceptions::UnknownGoalHandleError`，已捕获，
  否则异常会穿透 `haltTree()` 的第二遍递归 halt。
- 迟到 result：goal 句柄失效后到达的 result 被丢弃，不得改变已 halt 分支的状态。
- server 不可用/重启：按 `action_server_wait_timeout_s` 等待后返回 `FAILURE`，不做无界等待。

### 对照 profile 的 `SendNavThroughPoses` 改造（P6 二）

原实现有两个与「授权 STOP -> 串口零速度」直接冲突的缺陷，本轮已修：

1. 类型是 `BT::SyncActionNode`，而 `SyncActionNode::halt()` 是 `final`（只做
   `resetStatus()`），派生类无法插入 `async_cancel_goal()`；同时 `tick()` 在
   `async_send_goal()` 之后立刻返回 `SUCCESS`，节点从不停留在 RUNNING。
   两者叠加的后果是：主树 halt 掉导航分支后 Nav2 侧目标仍在执行，
   对照 profile 下这条停车链整条失效。现改为 `BT::StatefulActionNode`，
   目标飞行中返回 `RUNNING`，`onHalted()` 真正 cancel 并清空进度。
2. `tick()` 内调用 `wait_for_action_server(action_server_wait_timeout_s)`，
   是 sync tick 内的阻塞等待（最坏每拍阻塞 2 s，整棵树反应性一起被拖死）。
   现改为 `action_server_is_ready()` + 跨拍累计等待，超时才判 `FAILURE`。

顺带修掉两处判据错误：单点路径（`NavigateToPose`）的句柄存在
`current_goal_to_pose_handle_`，原实现只看 `current_goal_handle_`，
导致单点目标在飞行中被判成「没有活动目标」而反复重发；`ABORTED` 收尾时
原实现直接重发同一条路径，失败永远不会上报给树，现改为返回 `FAILURE`
由上层决定重试或换分支（主动 cancel 不置该标志）。

测试：`test/test_send_nav_through_poses_halt.cpp`，4 项全部通过
（单点 halt cancel、多点 halt cancel、空路径不下发、server 缺失按超时判失败且
首拍耗时 `< 200 ms`）。

### 正式 profile 禁止项

1. 禁止 `PublishTwist` / `PubTwist` 直发底盘速度；`decision.topics.cmd_vel` 直通通路已移除。
2. 禁止 `cmd_spin` 在 MPC 之后叠加车体 `wz`。
3. 禁止用 `IsPathGoalReached` 的位置容差替代 ATS action 的终端成功判据。
4. 禁止伪造云台 ack。

## 决策输入源

参数 `decision.input_source` 支持：

- `referee`
- `simulation`

- `patrol`
- `anchor`
- `retreat`
- `safe`

## 动作节点范围

`plugins/action` 中的主要节点：

- `LoadCsvWaypoints`：加载 CSV 点位。
- `SelectPatrolPath`：选择巡逻路径。
- `AdvancePatrolCursor`：推进巡逻游标。
- `SelectSupplyPoint`：选择补给点。
- `SelectNearestRetreatPath`：选择最近退防点。
- `SelectFixedPath`：选择固定路径。
- `SelectPathGoalPose`：从路径中提取目标点。
- `SelectVisionFollowPath`：根据视觉目标和 costmap 生成视觉跟随点。
- `PublishDecisionGoal`：发布决策目标。
- `SendAtsNavGoal`：**正式执行接口**，向 `/ats_navigate_to_pose` 发送
  `ats_navigation_interfaces/action/NavigateToPose`，可 halt/cancel，见下节。
- `PubNav2Goal`：发布 Nav2 goal（仅对照 profile）。
- `SendNav2Goal`：发送 `nav2_msgs` NavigateToPose（仅对照 profile）。
- `SendNavThroughPoses`：发送 NavigateThroughPoses（仅对照 profile，
  本轮已由 `SyncActionNode` 改为可 halt 的 `StatefulActionNode`，见下节）。
- `PubTwist`：发布 Twist（正式 profile 禁用，见下节）。
- `PubSpinSpeed`：发布自旋速度。
- `PubGimbalAbsolute` / `PubGimbalVelocity`：发布云台指令。
- `PubRobotMode`：发布姿态模式。
- `HoldStopFlag`：发布 stop flag。
- `ResetLowHpTarget`：重置低血量目标。

## 条件节点范围

`plugins/condition` 中的主要节点：

- `IsGameStatus`：判断比赛阶段。
- `IsGameTimeStage`：按剩余时间划分阶段。
- `IsHpBand`：按血量阈值划分状态。
- `IsRobotHpBelow`：判断血量是否低于阈值。
- `IsRobotResourceMode`：判断资源策略状态。
- `IsRobotResupplyRequired`：判断是否需要补给。
- `IsAttacked`：判断是否受击。
- `IsRfidDetected`：判断 RFID。
- `IsFriendlyOutpostDestroyed`：判断己方前哨站状态。
- `IsVisionTargetValid`：判断视觉目标是否可用。
- `IsPathGoalReached`：判断路径目标是否到达。
- `IsDecisionInputSource`：判断当前输入源。
- `IsDecisionMode`：判断仿真决策模式。
- `IsStatusOK`：判断机器人状态有效。

## 输出话题

行为树输出：

- `cmd_spin`：自旋速度，供 `fake_vel_transform` 叠加角速度。
- `cmd_vel`：直接 Twist 输出节点使用。
- `cmd_gimbal`：云台控制，供 `gimbal_manager` 转成 joint state。
- `decision/robot_mode`：姿态模式，供 `standard_robot_pp_ros2` 写入下位机速度模式字段。
- Nav2 action：
  - `/navigate_through_poses`
  - `/navigate_to_pose`

## 视觉跟随策略

视觉链路输入消息为 `sp_msgs/msg/VisionTargetMsg`。行为树服务端参数中 `decision.vision.*` 控制视觉接管：

- `timeout_s`：视觉消息新鲜度。
- `attack_radius`：目标周围跟随半径。
- `follow_occupied_threshold`：costmap 占用阈值。
- `follow_sample_count`：圆周采样数量。
- `follow_arc_half_angle_deg`：采样弧范围。
- `min_replan_interval_s`：最小重规划间隔。
- `min_goal_shift_m`：目标变化阈值。
- `activation_hold_s`：首次接管保持时间。
- `switch_target_hold_s`：切换目标保持时间。
- `override_hold_s`：短时丢帧接管保持。
- `visualization_topic`：视觉跟随 marker 话题。

`SelectVisionFollowPath` 会结合目标地图坐标、当前机器人位姿和 costmap，选择可通行跟随点，并发布可视化 marker。

## 资源策略

资源策略参数位于 `decision.resource_policy.*`：

- `defend_enter_hp`
- `defend_exit_hp`
- `resupply_enter_hp`
- `resupply_exit_hp`
- `resupply_enter_ammo`
- `resupply_exit_ammo`
- `assume_engage_when_status_missing`
- `require_valid_ammo_before_resupply`

策略输出用于决定是否允许继续巡逻/追击、是否回补给点、是否进入防守状态。
