# 视觉与串口桥说明

## 简介

视觉/裁判系统提供任务输入，串口与云台链提供下位机速度边界和云台状态；它们不替代定位、地图或导航 owner。

## 模块

视觉与裁判输入位于根业务包；`standard_robot_pp_ros2` 保留决策、自瞄和云台状态功能。

## 依赖

ROS 2、业务消息接口、串口硬件依赖和底盘协议。

## 构建

```bash
MAKEFLAGS=-j1 colcon build --base-paths src --parallel-workers 1
```

## 启动

根 bringup 负责串口、云台状态、fake-yaw/chassis transform 兼容层与行为输入编排。

## 接口

MPC 输出车体系 `[vx, vy, wz]`。实机通路为
`/cmd_vel/autonomy_raw -> fake_vel_transform -> chassis_vel_transform -> /cmd_vel/autonomy`
`-> cmd_vel_arbiter -> /cmd_vel/selected`；手动 `/cmd_vel` 只作为 arbiter 的另一个输入。下位机负责
其后的 CAN/电机执行，导航不检查这些硬件状态。`serial/gimbal_joint_state` 是云台 yaw、速度坐标变换及
自瞄-导航协调输入，必须保留。

## 配置

串口/transform 参数在根总 YAML；实机默认保留 fake-yaw 与 chassis transform，关闭时必须保持
frame、TF 和速度契约。

## 架构

```text
vision/referee -> behavior -> Goal Manager -> MPC -> /cmd_vel/autonomy_raw
-> fake/chassis transform -> /cmd_vel/autonomy -> arbiter -> /cmd_vel/selected
```

## 验证与限制

MuJoCo 的 current-revision 运行仍未验证；实机键鼠到串口、云台和固定雷达迁移也尚未验证。
串口保留 emergency stop、链路失效和 watchdog；自动授权已上移到 arbiter，因此串口不得再订阅
`/planner/execution_command` 的 `MODE_STOP` 以免阻断新鲜手动输入。
