# 视觉与串口桥说明

更新时间：2026-07-31。本文档根据 `src/sp_vision25`、串口桥源码、导航授权接口
和实际参数文件整理。本轮没有运行相机、串口或实车。

## 视觉域 `sp_vision25`

包路径：

- `src/sp_vision25`

- `assets/`：模型和布局文件。

## 哨兵视觉主程序

入口源码：

- `src/sp_vision25/src/sentry.cpp`

主流程：

```text
Camera 读取图像
Gimbal 提供姿态
YOLO 检测装甲板
Decider 过滤无敌目标并设置优先级
Tracker 跟踪目标
Planner 计算云台控制和开火建议
Gimbal 下发云台/开火控制
Decider 生成 VisionTargetState
ROS2 发布 vision/target
```

当前 `sentry.cpp` 中全向感知 fallback 初始化被关闭。tracker lost 时直接停止云台控制，不启动侧向 / 后向相机。

### 速度语义与单位（P6 一）

`speed_vector {vx, vy, wz}` 是**车体系全向语义**，不得改成差速或强制 `vy = 0`：

| 字段 | 含义 | 单位 | 正方向 |
| --- | --- | --- | --- |
| `vx` | 车体纵向速度 | $\mathrm{m/s}$ | 车头方向为正 |
| `vy` | 车体横向速度 | $\mathrm{m/s}$ | 车体左侧为正 |
| `wz` | 车体偏航角速度 | $\mathrm{rad/s}$ | 逆时针（俯视）为正 |

映射位置：`standard_robot_pp_ros2.cpp` 中
`linear.x -> vx`、`linear.y -> vy`、`angular.z -> wz`，本轮未修改。

四舵轮几何与执行器上限（用于与下位机固件口径核对，任何不一致都是停止条件）：

$$(\pm 0.270,\ \pm 0.270)\ \mathrm{m},\quad r_{\mathrm{wheel}} = 0.0425\ \mathrm{m}$$

$$v_{\max}^{\mathrm{wheel}} = \frac{450 \times 2\pi}{60} \times 0.0425 = 1.6689711\ \mathrm{m/s},\quad
\dot\delta_{\max} = \frac{120 \times 2\pi}{60} = 10.4719755\ \mathrm{rad/s}$$

MPC 可行域：`max_vx = max_vy = 1.5`、`max_ax = max_ay = 2.0`、`max_wz = 2.0`、`max_awz = 3.0`，
`dt = 0.05`、`horizon = 30`。`chassis_vel_transform` 的出口限幅在正式 profile 中已随该节点一起停用；
若在对照 profile 保留，其限幅不得宽于 MPC 上限。

### 零命令保持与归零判据（P6 一）

`enable_transient_zero_cmd_hold` 只允许吸收**通信抖动导致的瞬时零**，
不得抑制**授权归零**。授权 STOP、急停、定位 stale、串口断连四类路径必须立即绕过保持逻辑，
直接写零速度。必须按实机与仿真 profile 区分判据：

```text
实机：
ready=false -> ExecutionCommand STOP -> MPC /cmd_vel=0
  -> speed_vector.stop=true, [vx,vy,wz]=0 -> 四轮 0 rpm

MuJoCo：
ready=false -> ExecutionCommand STOP -> /cmd_vel_mpc=0
  -> /motion_control=0 -> simulated actuator/contact evaluator
```

时序要求 $T_{\mathrm{hold}} = 50\ \mathrm{ms} < T_{\mathrm{wd}} = 300\ \mathrm{ms} \le T_{\mathrm{lease}} = 500\ \mathrm{ms}$，
即底盘看门狗必须严于或等于授权租约上限。

**实测归零时延为 `未实测`**：需要抬轮 HIL（执行器断开）在实车上用示波器或下位机日志测量，
本轮实车未通电，不得用估计值代入 5.11.2 净空预算。

### 串口断连与重连（P6 一）

`serialPortProtect()` 检测到断连后：

1. 立即输出零速度，并保持零速度直到重连成功。
2. 重连期间不恢复执行授权。
3. 重连成功后必须通过**新的** `localization_epoch` / `map_generation` / `command_sequence`
   重新获得授权，不得自动恢复断连前的旧命令。

**实测重连行为为 `未实测`**，同样需要抬轮 HIL。

### 实车 `GimbalYawStatus`（P6 零.4）

`gimbal_yaw_status_bridge_node` 从 `serial/gimbal_joint_state` 派生 `GimbalYawStatus`：

- `locked` 与 `tf_healthy` 均为实测量，不得伪造。
- 反馈超过 $T_{\mathrm{joint}} = 100\ \mathrm{ms}$ 视为 stale，`yaw_authority` 降为
  `YAW_AUTHORITY_HOLD_SAFE_STOP`。
- 若在受控 HIL profile 下把 `require_gimbal_status` 置 `false`，
  则 `BODY_YAW_FOLLOW` 被禁止。

`sentry_chassis_vel_transform` 的 `pass_through_without_yaw` 在正式 profile 中不生效
（该节点不启动）。该目录是用户未跟踪文件且自带嵌套 `.git`，本轮未修改、未 stage。

### 出口授权门（P6 一）

`standard_robot_pp_ros2_node` 的出口新增 `CmdVelAuthorizationGate`
（`include/standard_robot_pp_ros2/cmd_vel_authorization.hpp`），区分两类零命令：

| 类别 | 触发源 | 处理 |
| --- | --- | --- |
| 通信抖动导致的瞬时零 | 上游连续几拍发出 $\lvert v\rvert < \varepsilon$ 的样本 | 在 $T_{\mathrm{hold}}$ 内保持旧速度 |
| 授权归零 | `ExecutionCommand STOP`、急停、授权 stale、串口断连、看门狗超时 | 立即绕过保持逻辑写零，并同时置 `speed_vector.stop` |

出口每拍打印原因码（`0` 转发、`1` 瞬时零保持、`2` 授权归零、`3` 未授权、
`4` 看门狗超时、`5` 串口断连），抬轮 HIL 时可直接对着日志判断归零来自哪一级。

节点启动时校验 $T_{\mathrm{hold}} < T_{\mathrm{wd}} \le T_{\mathrm{lease}}$，
不满足就收紧参数并打 ERROR。`require_execution_authorization` 在
`config/standard_robot_pp_ros2.yaml`（Nav2 对照 profile）为 `false`，
在实车 Nav2-free 官方入口的 `node_params.yaml` 为 `true`。单独启动包内 launch 时若
误用默认配置，会绕过正式授权门，因此测试报告必须记录 effective parameter source。

## `gimbal_manager_node`

源码：

- `src/standard_robot_pp_ros2/src/gimbal_manager.cpp`

职责：

- 订阅 `cmd_gimbal`。
- 支持绝对角控制和速度控制。
- 以 10ms 周期积分云台 pitch / yaw。
- 发布 `cmd_gimbal_joint`，供串口桥下发。

话题：

```text
ats_sentry_behavior 或其他上层
  -> cmd_gimbal
  -> gimbal_manager
  -> cmd_gimbal_joint
  -> standard_robot_pp_ros2_node
```

## 视觉、行为树、串口桥协作

```text
sp_vision25
  -> vision/target
  -> ats_sentry_behavior
  -> cmd_gimbal / decision/robot_mode / ATS action
  -> gimbal_manager / standard_robot_pp_ros2 / ats_goal_manager
```

```text
standard_robot_pp_ros2
  -> referee/*
  -> ats_sentry_behavior
  -> resource policy / posture mode / navigation goal
```

姿态模式由行为树发布到 `decision/robot_mode`，串口桥订阅后写入下位机速度模式字段。代码中的模式名映射为：

- `1`：attack
- `2`：defend
- `3`：move

Nav2 action 只属于显式 baseline profile；正式链使用 `/ats_navigate_to_pose`。视觉和
行为层都不得发布可绕过 Goal Manager/MPC 授权的底盘非零速度。

## 当前验证边界

- **已验证**：本文串口 topic、授权参数、速度字段映射和云台状态接口已静态核对。
- **已实现未运行**：`CmdVelAuthorizationGate` 与真实 `GimbalYawStatus` bridge 源码链。
- **未验证**：相机到导航时延、串口断连/重连、抬轮归零时延、四轮 0 rpm 和固件单位。
- **残余风险**：轮半径、齿比、最大 wheel/steer acceleration 仍需台架与固件同口径标定。
