# 实机视觉跟随现状说明

这份文档只描述当前仓库中真实在使用的实机视觉接管链路。

## 1. 当前实机链路

当前实机视觉跟随主线可以直接理解成：

```text
sp_vision25
  -> 发布 vision/target (VisionTargetMsg)
  -> 包含 target_position_map / tracking / nav_hold / yaw / pitch

pb2025_sentry_behavior
  -> IsVisionTargetValid
  -> IsRobotResourceMode(state=engage)
  -> PublishRobotMode(mode=attack)
  -> PublishGimbalAbsolute
  -> SelectVisionFollowPath
  -> SendNavThroughPoses

Nav2 + MPPI
  -> /cmd_vel

standard_robot_pp_ros2
  -> /cmd_vel -> speed_vector
  -> decision/robot_mode -> speed_vector.mode
```

## 3. 当前视觉接管的必要条件

当前视觉接管不是“只要有目标就接管”，而是必须同时满足：

1. `IsRobotResourceMode(state="engage")`
2. `IsVisionTargetValid(...)`
3. `tracking=true`
4. `nav_hold=true`
5. 消息未超时
6. `target_position_map` 有效

如果这些条件有任意一项不成立，系统就会回退到普通分支，而不是保持 `attack`。

## 4. 当前真正驱动导航的视觉字段

当前真正驱动视觉跟随路径的是：

- `target_position_map`
- `has_target_position_map`
- `target_position_map_frame`

当前并不是只靠：

- `target_position_gimbal`
- `yaw`
- `pitch`

其中：

- `yaw / pitch` 主要给云台姿态使用
- `target_position_map` 才是导航跟随点计算的基础

## 5. 当前攻击圆周跟随的实现

当前行为层实现位置：

- [../src/pb2025_sentry_behavior/plugins/action/select_vision_follow_path.cpp](../src/pb2025_sentry_behavior/plugins/action/select_vision_follow_path.cpp)

当前逻辑：

1. 根据当前车位和敌方地图点，先求攻击圆周上最近点
2. 结合 costmap、边界余量、局部可通行性筛选候选点
3. 对选中点做角度限幅平滑
4. 位姿重定位或跳变时可清缓存后重选

因此现在的目标不是“死跟一个固定点”，而是“持续跟随攻击半径上最合理的点”。

## 6. 当前实机与 loopback 的关系

共用部分：

- 视觉接管判定
- 姿态切换
- 资源模式状态机
- 视觉圆周点选择
- `SendNavThroughPoses` 目标重发节流

不同部分：

- 实机使用真实视觉输入和真实裁判系统
- loopback 使用 `fake_decision_sim_inputs.py`
- 实机 Nav2 参数和 loopback Nav2 参数分离维护

## 8. 当前实机链路检查建议

### 8.1 先确认视觉消息

优先检查：

- `vision/target`

重点看：

1. `tracking`
2. `nav_hold`
3. `target_position_map`
4. `has_target_position_map`
5. `target_position_map_frame`

### 8.2 再确认行为层日志

重点看：

- `Decision resource mode=...`
- `Robot posture switched: ...`
- `Vision follow target=(...) nearest_ring_goal=(...) selected_goal=(...)`

### 8.3 再确认下位机接口

重点看：

1. `/decision/robot_mode` 是否变化
2. `/cmd_vel.angular.z` 是否在受击时变化
3. `standard_robot_pp_ros2` 是否正常把两者写入串口结构体

## 9. 当前实车链路的关键结论

### 9.1 `attack` 姿态

当前只要视觉接管成立，就会发布 `attack=1` 到：

- `decision/robot_mode`

最终下位机可以按 `int32_t mode` 或等价枚举接收。

### 9.2 自旋速度

当前自旋速度最终通过：

- `/cmd_vel.angular.z`

进入串口层，并写入：

- `SendRobotCmdData.data.speed_vector.wz`

### 9.3 模式与速度是两条独立信号

也就是说当前下位机接收时应把：

1. `mode`
2. `vx / vy / wz`

当成两条独立但协同的控制信息处理。
