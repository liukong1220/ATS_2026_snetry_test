# S3 建图、保存与身份闩锁恢复

本文记录当前接口与恢复步骤。MuJoCo 验收结果见
[无先验地图钻洞高速导航优化调研报告](../调研/无先验地图钻洞高速导航优化调研报告.md)
的 0.5、0.7 节；本文不代替实车验证。所有检查命令必须使用本次部署的同一个
`ROS_DOMAIN_ID`、同一份参数文件，并先 `source install/setup.bash`。

## 模式与身份

通用 launch 的 `use_identified_odometry` 默认仍为 `false`。建图入口 `mapping.sh`
显式启用它，身份与里程计在同一条 `IdentifiedOdometry` 中传递：

```text
Point-LIO /aft_mapped_to_init_identified
  -> loam_interface /lidar_odometry_identified
  -> sensor_scan_generation /odometry_identified
  -> localization_fusion
```

fusion 还监视未经过下游筛选的 `/aft_mapped_to_init_identified`，以识别旧实例并存。
`instance_id` 是 Point-LIO 启动时同机、同次开机的 `steady_clock` 纳秒数，不能跨机器或重启比较。
0、早于当前实例的消息和超过 fusion 自身 steady clock 加 5 s 容差的实例均不接受；
较新实例先推进前端 epoch，使地图与执行授权失效。

建图使用 `slam:=true use_identified_odometry:=true`，不加载先验 PCD。adapter 显式使用
`allow_missing_static_map=true`；全局 odom 层参与规划后，建图入口才将
`use_static_map_obstacles` 设为 `false`。建图 ready 要求前端身份已知、输入新鲜、
前端 epoch 与数值投影一致。首次地图匹配接受前，目标管理器继续持有目标，不下发规划目标。

比赛使用 `slam:=false`，加载同一起点保存的 PCD 和静态层；缺图或定位不健康时保持急停。
`allow_missing_static_map` 默认 `false`、`use_static_map_obstacles` 默认 `true`，
不要把建图的缺图例外带入比赛参数。规划、ESDF、MINCO 和 MPC 使用 `odom`；目标权威值保存在
`map`，由最新 `map->odom` 转换。

全局层固定 40×30 m、0.1 m，默认原点 `[-20,-15]`，12×12 m 只用于计算。
显式场地 profile 可偏置数组原点，配准地图的 `mapping.origin` 也须覆盖同一范围；
2025 使用 `[-6,-15]`，2027 使用 `[-8,-15]`（均为初始 odom 坐标）。出界观测计数并输出位置，
不能通过扩大 unknown 可通行范围消除出界。`allow_unknown_goal` 默认关闭，已提交轨迹始终须 known-free。

## 显式保存与对账

在建图节点仍运行、前端健康且已接受地图变换时调用服务；节点析构不保存地图。
输出前缀应为本次新目录，避免覆盖已有地图：

```bash
ros2 service call /rog_map/save_map ats_rog_map_interfaces/srv/SaveOdomMap \
  "{output_prefix: '/tmp/opencode/s3_manual/map'}"
```

或使用会核对产物和计数的客户端：

```bash
python3 scripts/save_s3_map.py --prefix /tmp/opencode/s3_manual/map
```

保存对不可变 odom 层快照施加一次完整三维 `map<-odom` 变换。产物为 `.pgm`、`.yaml`、
三维 `.pcd` 和二维调试 `.cells.pcd`；YAML 记录 `map_from_odom` 与 `map_from_odom_rpy`。
下一场 GICP 必须加载三维 `.pcd`。原始 Point-LIO 分段保持 `camera_init`，不能冒充 map 系重定位地图。

| 响应计数 | 含义与对账 |
| --- | --- |
| `occupied_cells` | 当前占据格，含尚未满足保存持久性阈值的格 |
| `persistent_cells` | 满足保存阈值的二维格，等于 `.cells.pcd` 的 `POINTS` |
| `persistent_voxels` | 未被射线清除的持久三维体素，等于 `.pcd` 的 `POINTS` |
| `raster_occupied_cells` | map 系重投影后的 PGM 黑格数 |

旋转、倾斜和栅格取整会改变最终栅格占据数，不能要求四项相等。历史 942/306 的原始产物
当前不可得，不能据新计数口径反推当时原因。服务失败、文件缺失或计数不符均须保留日志并判为保存失败。

`mapping.sh` 在停止 launch 前调用服务，停止后按本次启动时间归档全部 `scans*.pcd` 分段，
包括退出时产生的尾段，并写 manifest；原始归档不覆盖已经变换到 map 的 `.pcd`。
手动运行归档时，`--since` 必须使用本次 Point-LIO 启动前记录的 Unix 时间：

```bash
python3 scripts/save_s3_map.py --archive-source src/ats_sentry_nav/point_lio/PCD \
  --archive-output /tmp/opencode/s3_manual/raw_segments --since 1793800000
```

上面的时间仅演示参数格式，实际操作必须换成本次记录值。

## 并存实例闩锁

当 `/localization/status` 显示 `odom_identity_latched=true`，或消息包含
`concurrent odometry instances; restart fusion required`，移除旧消息源不会自动解锁。
当前没有 reset service；不要反复发布 ready 或重放旧 reference 尝试恢复。

1. 保持急停，检查 `/planner/emergency_stop=true`，并确认
   `/cmd_vel/autonomy_raw`、`/cmd_vel/selected`、`/motion_control` 持续为零。
2. 核对本次域内 `/aft_mapped_to_init_identified` 的 publisher，定位本次启动所拥有的
   Point-LIO 进程或容器；只停止确定属于该部署的实例，避免影响其他域。
3. 停止并完整重启本次导航 bringup，使 fusion、地图、目标管理器与控制器共同重建状态，
   同时取得新的前端实例。仅重启 fusion 的完整恢复闭环本轮没有验证。
4. 确认只有一个权威前端，`odom_instance_id`、`odom_epoch` 均非零，闩锁已清除，
   新观测已被 fusion 接受；核对 adapter 的 epoch 与定位状态一致且 ready 持续续租。
5. 核对 `/rc_esdf/planning_grid` 只有 adapter 一个 publisher、frame 为 `odom`。
   ready 恢复不能复活急停前轨迹；车辆应继续停住，再由操作员提交新的目标。

```bash
ros2 topic info /aft_mapped_to_init_identified --verbose
ros2 topic echo /localization/status --once
ros2 topic echo /rog_map_adapter/status --once
ros2 topic info /rc_esdf/planning_grid --verbose
ros2 topic echo /planner/emergency_stop --once
ros2 topic echo /cmd_vel/autonomy_raw --once
ros2 topic echo /cmd_vel/selected --once
ros2 topic echo /motion_control --once
```

`--once` 仅便于检查字段；持续零速、heartbeat 续租和恢复后旧轨迹不复活需要时间窗口证据。
真实 Point-LIO 重启的故障注入与并存实例闩锁是两个实验，不能相互替代。
