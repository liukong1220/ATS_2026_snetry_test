# RMUL 2027 3V3 场地部署与 MuJoCo 仿真

来源：`2027_map/RMUL2027_3V3_V1.0.0.STL`（二进制 STL，单位 mm）。场地依据规则手册 V1.0.0 第 3.2 节：12 m x 8 m 战场，
中心对称，启动区兼补给区在对角，中央控制区在场地中心，两侧高地各有一条隧道。STL 外框含围墙为 12.6 x 8.6 m。

## 一键生成

```bash
python3 scripts/convert_rmul_2027_map.py            # 写出全部资产
python3 scripts/convert_rmul_2027_map.py --check    # 校验已提交文件与生成器一致
python3 scripts/convert_rmul_2027_map.py --orientation official   # 规则手册朝向（启动区在左上）
python3 scripts/convert_rmul_2027_map.py --roof-bottom 0.30       # 调整顶板下沿
```

生成物（地图系：原点在外框左下角，地面 z=0，x 向右、y 向上）：

| 文件 | 用途 |
| --- | --- |
| `src/ats_sentry_bringup/map/rmul_2027.{pgm,yaml}` | 规划静态图，0.05 m，252 x 172 |
| `src/ats_sentry_bringup/pcd/rmul_2027.pcd` | GICP 先验，3 cm 面采样，约 20.9 万点 |
| `src/sim/ats_mujoco_sim/models/meshes/rmul_2027.obj` | 激光雷达射线网格 |
| `src/sim/ats_mujoco_sim/models/rmul_2027_height.bin` | 物理地面 hfield，1 cm |
| `src/sim/ats_mujoco_sim/models/rmul_2027_roof_boxes.xml` | 隧道顶板碰撞盒 |
| `src/sim/ats_mujoco_sim/models/rmul_2027_swerve.xml` | MuJoCo 场景 |

地图判据复用 `scripts/generate_rmuc_2027_map.py`（可达地面、墙体、悬崖边、占据覆盖 50%），不另起一套。

## 朝向与启动点

默认 `mirror_y`：启动区在左下角，红蓝对角，工作台在启动区角落。出生点 `(1.60, 1.20)`，`start_z=0.20`，yaw 0。
高地（200 mm）超过 `step_max=0.04`，在规划图中整块占据；中央控制区与启动区地胶只有 10 到 20 mm，可通行。

## 隧道顶板

官方顶板下沿离地 0.250 m，车高 0.242 m（含雷达），净空 8 mm，实际过不去。生成器把两块顶板连同墩子整体抬高到
`--roof-bottom`（默认 0.32 m，净空 0.078 m），网格保持封闭。通道宽 0.80 m（高地与边缘条之间），位于 y 0.45..1.25 与
y 7.35..8.15，顶板投影 x 3.625..3.975 与 x 8.625..8.975。

## 运行

```bash
source /opt/ros/humble/setup.bash && source install/setup.bash
ROS_DOMAIN_ID=133 ros2 launch ats_mujoco_sim rmul_2027_mujoco.launch.py use_viewer:=true show_viewer:=true use_rviz:=true
ros2 topic pub -t 4 -r 2 /goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: map}, pose: {position: {x: 8.8, y: 7.75, z: 0.0}, orientation: {w: 1.0}}}"
```

`ROS_DOMAIN_ID` 不要超过 232（CycloneDDS 端口上限）。

## 本轮验证（2026-11-10，truth 定位，无 RViz、无 MuJoCo 窗口）

已验证：

- `pytest test/test_rmul_2027_scene.py`：8 项通过（地图与网格同框、围墙、出生无穿透、顶板净空、走廊自由、PCD 帧）。
- 恒等变换下实时扫描到先验 PCD 的最近点距离中位数 2 cm，90 分位 3.8 cm。
- 隧道 A、B 各四到五段强制目标，东西两端进入和穿出共 9 段全部 `goal reached`，终点距离 0.064 到 0.076 m；
  走廊内偏离轴线最大 0.049 m（A）、0.07 m（B）；车心在顶板正下方的采样 34 到 342 个。
- 启动区到隧道 A 东侧、返回启动区、到隧道 B 顶板下，均到达。
- 自由规划穿隧道（不用强制目标，只发一个目标点）：原先首选净空 0.436 m 大于通道半宽 0.40 m，
  图搜索在首选档绕远路也能成功，净空梯子不降档，车绕行约 13.7 m（直线 3.8 m）而不进隧道。
  现在 `minco_planner.clearance_detour_ratio: 1.5`（仅 RMUL profile 开启，默认 0 关闭）：首选路径超过直线 1.5 倍时，
  再用下限档 0.341 m 搜一次，明显更短才取代，日志为 `【绕行回退】`；足迹门禁与局部碰撞修复不变。
  实测隧道 A（5.4,0.85 到 1.6,1.2）与隧道 B（10.8,7.75 到 6.8,7.75）都走隧道并 `goal reached`，
  路径 13.68 m 换成 3.96 m、13.88 m 换成 4.13 m，隧道内 y 范围 0.84–0.87 与 7.70–7.73。

未验证或有限制：

- 物理接触：没有独立接触评估器，`footprint_collisions` 不等于物理零碰撞；静态扫过两条隧道的穿透检查为 0。
- GICP 在特征少的场地上不稳：`map->odom` x、y 在约 ±0.12 m 内，z 在 -0.27..+0.14 m 内跳变（会吸附到 0.2 m 高地面）。
  关闭 GICP 则定位永远到不了已接受状态，目标直接失败。未做 lio（Point-LIO）模式验证。
- 未做建图模式（`slam:=true`）、实车、故障注入和红框回归。
